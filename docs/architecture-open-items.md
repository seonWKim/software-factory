# Architecture: open items

Moved out of `ARCHITECTURE.md` (was section 7, "Review notes: where the architecture could improve") so work on the overview and work on these rows stop conflicting.

Open proposals and pressure points, for the reviewer to weigh. The RFCs are the owner's design proposals, kept outside this repository; the numbers and titles below are their references. Each "today" is checked against the code at the commit that last changed this file.

| Area | Today | Proposal |
|---|---|---|
| Maintenance | No regular GC, DRY or deprecation pass; done as manual sweeps | RFC 0001: Maintenance loop (garbage collection, DRY, deprecation) |
| Sandbox dependencies | `noop`: a host worktree that can resolve `node_modules` from the owner's main checkout | RFC 0002: Sandboxes get dependencies from the lockfile, not the main checkout |
| Coordination | An open PR waiting on a person still holds overlapping queued runs; `hold_policy` can time out a cost hold, but the default keeps it | RFC 0004: PRs waiting on a human don't hold other runs |
| Self-update | A schema step stops the supervisor until `npm run migrate`, unless `updater.auto_migrate` (default false) is set | RFC 0005: Additive migrations don't stall an unattended factory |
| Human waits | Some `blocked_reason` values list no command that moves the item | RFC 0007: Every human wait has a way forward |
| Triage scope | A missed caller or test file fails implement with `spec_conflict` and a second approval | RFC 0008: Triage scopes the blast radius |
| Merge safety | Local changes land through the merge queue on a checked merged result; a GitHub PR's `test` check can still be stale against a newer main | RFC 0009: Test the merged result before merging |
| Local first | Still on the core path: plugin defaults pick `github-issues`, the `github` broker and `token` (their descriptors' `default: true`); `GitHubCredentials` is a required kind; `update` fails an item with no `change_ref` (`no_pr`). Resolved since the RFC 0011 audit: the base push reaches origin (a `push_base` delivery), no behaviour keys on `github.push_branch` (gone), and "is this item local" is the item's route, so the review and resolve runs take a local item with no `change_ref` | RFC 0011: Local-first audit: is the forge plugin off the core path? |
| Dashboard | The app shows the facts but the owner can't act from it everywhere | RFC 0012: Dashboard enhancements for the overnight owner |
| Sandbox isolation | `noop`: a host worktree; writes limited by the runner's rules | Container sandboxes; toolchain caches read-only, modelled on frontier harnesses (#334) |
| One process, four components | The controller role wires inbound, the controller, outbound and the retry scheduler into one process (`controller-role.ts`); outbound cannot be scaled or restarted apart from the decisions | A process role per component (`runtime/roles/<role>/` in RFC 0015 §6.1), so each scales and restarts on its own |
| Runs off the bus | Workers claim from `worker_runs` through the store's `claimRun`; the worker has no outbox or inbox and publishes nothing; its intents wait for the controller's next outbox step to be announced; no topic is `competing`, so `requires` / `capabilities` are unused | A `runs.requests` competing topic with worker capabilities |
| Units not pure yet | `unit-purity` ratchet: 24 entries in 10 units (`alarms`, `closes`, `coordination`, `improve`, `intake`, `local-merge`, `model-probe`, `phases`, `pr-events`, `sync`) still reach the store, sources, forge, sandbox, LLM or network themselves. A decision's writes are applied in order but not in one transaction, and `legacy-controller` writes its inbox row after the effect, so no controller message is exactly-once | Split the rest into load/decide; a store call that commits a decision's writes with the inbox row (M5 follow-up) |
| Forge writes outside outbound | `forge-writes` ratchet: empty (sub-issue filing moved to outbound's `file_sub_issue`, 2026-11-09). No operator command writes to the forge today | Decide whether operator commands go through outbound |
| Legacy seams | `dependency-direction` ratchet: 298 `component-imports-legacy` entries (controller 118, worker 81, cli 72, inbound 11, outbound 9, runtime 7): components still import `src/core/` helpers and `src/interfaces/` types. The legacy `FactoryStore` still writes component tables for them (the worker's thread entries and intents through `recordItemMessage` / `recordRunIntent`; outbound claims and finishes its thread intents through `claimDelivery` / `finishDelivery`), and the `github-issues` source writes `inbound_commands` and `controller_item_thread` during its poll | Move each helper into its component as its milestone rewrites it (RFC 0015 M2 re-plan); the list only shrinks |
| Clock reads | `no-clock` ratchet: legacy files still read the clock or set timers, and five units read `clock.now()` (`run-results`, `coordination`, `model-probe`, `commands`, `improve`) | Time from ticks only |
| Golden cases | `rule-of-two` ratchet: the `triage`, `implement` and `resolve` roles have no golden case; auto mode does not call `ruleOfTwoRefusal` yet (owner decision) | Golden cases per role; wire the Rule of Two into auto mode |
| Gate list | `src/outbound/` (every forge write and its G5 scan) and `src/identity/` (passports) are not on `PROTECTED_PATHS` and not under a floor in `factory.config.json`, except their `settings/` folders | Owner decision: add them to the gate list or floors |
| Passport key and sessions | The passport key is a file in the state folder; `SF_PASSPORT_KEY` through the SecretStore is not wired; `factory session` stores its branch through a broker with no passport | Declare `SF_PASSPORT_KEY` and read it through the SecretStore; give sessions a passport |
| Identity leftovers | No `paths` caveat (no git proxy at the sandbox edge sees the files); the web app does not show `actor.name` and `merged_by_name`; components take their SQL driver from the legacy store (`storeSql`), not the runtime | A `paths` caveat once a proxy sees the files; show the names in the app; the runtime hands components their driver |
| Dead letters | A dead letter raises an alarm, but no CLI replays it (`SqlRetryScheduler.replay` exists) and the router does not mark the actor `blocked_on: dead_letter` | `factory dead-letters replay`; `blocked_on: dead_letter` in the router |
| Contract drops | 45 `legacy_*` tables and `outbound_base_pushes` stay until `npm run migrate -- --contract` (14 days after their migrations; not applied). One contract migration copies each legacy row missing from its current table, then drops every `legacy_*` table; `--contract --dry-run` prints what it would do | Owner runs `--contract --dry-run`, then `--contract` (waiting on the owner) |
| Update run steps | The update run is not split into steps; its push and PR comments are its only effects (M6 leftover) | Steps for update, with the worker half of M7 |
| Units: load and decide | `commands` and `run-results` interleave reads, other units' operations and writes; `merge-check`'s `MergeChecker` reads the store | Split them into load/decide and take `MergeChecker` off the store (M5 follow-up; the other units are in the "Units not pure yet" row) |
| Worker and outbound on the bus | The worker and outbound have no outbox and inbox migrations; the worker declares no `capabilities` | Their outbox and inbox migrations; capabilities when `runs.requests` lands (M3 leftover) |
| Hook points | `before_delivery` is not called: startup refuses an enabled one (`UNCALLED_HOOK_POINTS`) | Call it from outbound at delivery (M7), then drop it from `UNCALLED_HOOK_POINTS` |
| Store reads for tests | `listInboxAfter` and `listCliCommandsAfter` are read only by tests; the store's command-row mapping duplicates `commandOf` in `src/inbound/records.ts` | Remove them as `FactoryStore` shrinks (M4 follow-up, with M5/M11) |
| Merge queue leftovers | No `github-change` merge delivery, no batches with bisect or partitions, no `paused` state; a removed entry's queued check run is not cancelled | Build them (M8 leftovers) |
| Outbound follow-ups | Outbound's given-up deliveries have no `alarmCommand` hint (group `outbound`); a batch whose intents no process can send (a `push_base` after the forge was switched off) still waits at its destination's head | The hint, pointing at the bus's dead-letter table; drop or fail such a batch |
