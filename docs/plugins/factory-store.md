# FactoryStore

What it does: the factory's state (work items, runs, state changes, handoffs, leases). Every transition is a conditional update, so any number of controllers and workers can share it (architecture §4). The logic exists once in `SqlFactoryStore`; a backend is a `SqlDriver`.

**SQLite is the only store (decision changed 2026-11-11, issue #567; current).** The factory serves one owner ([08-enterprise.md](../design/08-enterprise.md), One owner, many workers), and its workers share one SQLite file on one machine. `sqlite` is the only FactoryStore plugin and the default. The SQL layer has one dialect, `sqlite` (`SqlDialect.name`, the migration `Dialect`), and a schema change ships no second-store step. A config that names any other store type fails at startup like any unknown store, with `unknown FactoryStore plugin "<type>" at store.type`. Nothing moves data between stores: `npm run migrate` has only its SQLite modes (its argument parser is `src/cli/handlers/migrate/migrate-args.ts`), reads no secret, and an unknown argument prints the unknown-argument message and exits 1. `src/compose.ts` has one `StoreConfig` and no reviewed-keys merge, and passes `sharedStore: false` to the pack loaders until a later phase removes that option.

Worker processes (2026-11-07, issue #209; design §5 Worker slots reported per process): `reportWorkerProcess(report)` writes one process's snapshot (`process_id` `<host>:<pid>`, `pid`, `host`, `slots`, `max_slots`, `busy`, `index_base`, `started_at`) with `reported_at` = the store clock's now; keyed by `process_id`, so a repeat write replaces the row (update, else insert; a concurrent first insert that loses updates). `listWorkerProcesses(max_age_ms)` returns the rows at most `max_age_ms` old, by host, pid, process_id (read-only). `removeWorkerProcess(process_id)` deletes one row on a clean stop. Table `worker_processes`: SQLite migration 19. The contract tests are in `tests/store-contract.test.ts`.

Schema changes of 2026-11-09 (issue #461), through timestamped migrations: index `worker_runs_ack` on `worker_runs (acknowledged_at, updated_at)` (`src/worker/migrations/20261109T1400-worker-runs-ack`, additive), so `listUnacknowledgedRuns` walks the unacknowledged runs instead of scanning every run; and the column `runtime_child_restarts.recorded_at` is dropped (`src/runtime/migrations/20261109T1401-runtime-drop-restart-recorded-at`, breaking: archived and verified first).

Plugins:

- `sqlite`: `SqlFactoryStore` over `SqliteDriver`, file at `<state_dir>/db/factory.db`. One machine. Selected by the checked-in config, and used when there is no `store` block.
  - Enable: `"store": { "type": "sqlite" }`. Secrets: none. Applies additive migrations when opened; `npm run migrate` applies the breaking ones and the data steps, and `npm run migrate -- --contract` the contract ones.

Switch back / disable: none. A store cannot be disabled: the factory has no state without one.

## History

- **Current text names SQLite only** (decision changed 2026-11-11, issue #567; replaces four current decisions, whose replaced decisions are the lines below). Before, the current text held: (1) **MySQL dialect removed from the code; the shared store is paused** (2026-11-13, issue #663, phase 1 of 2 of #659): the `mysql` dialect, `mysqlSnapshot`, the sql bus's MySQL column types, table options and duplicate-key handling, and the MySQL branches of the migration runner, table copy, retention, outbound intents and table catalog were deleted; `src/compose.ts` lost its MySQL `StoreConfig` variant and the reviewed-keys merge (an external config's `dials`, `floors`, `plugins`, `permissions`, `auth`, `toolchain`, `hooks` and `packs` were taken from the checked-in file only on a MySQL store). (2) **`mysql` plugin and `MysqlDriver` removed** (2026-11-12, issue #654, phase 3 of 3 of #599): `src/impl/store/mysql/` and the `mysql2` dependency were deleted, no descriptor declared `MYSQL_PASSWORD`, and no config path named a MySQL path; owner answer 1 of #599: no MySQL data was left to copy, because the live store moved to SQLite on 2026-11-11 (#618). (3) **No copy from MySQL** (2026-11-12, issue #653, phase 2 of 3 of #599): `--copy-from-mysql`, `--replace`, `--mysql-host`, `--mysql-port`, `--mysql-database` and `--mysql-user` became unknown arguments to `npm run migrate`, and `copy-to-sqlite.ts` and `migrate-command.ts` were deleted. (4) **`mysql` is deprecated; SQLite is the only store** (2026-11-11, owner decision), with a removal plan whose phases were issues #590, #654 and #663; follow-ups were to remove the MySQL test-database and setup paths, the `sharedStore` pack option and the docs that still described MySQL. The text after the Plugins list also said no `mysql` plugin existed (a `mysql` store failed with `unknown FactoryStore plugin "mysql" at store.type`), that setup, `npm run migrate` and teardown had no MySQL path, and that a `MYSQL_PASSWORD` left in an old secret file was neither read nor scanned. The `worker_processes` table was also described with MySQL step `migrations/mysql/0019-worker-processes.sql`, the 2026-11-09 schema changes as running on both backends (the column drop on MySQL by `npm run migrate` with writers drained).
- **`mysql` store refused by its own check; the MySQL dialect kept** (decision changed 2026-11-13, issue #663; replaced by MySQL dialect removed from the code). Before: `checkConfigKeys` refused a `mysql` store with one line naming `"store": { "type": "sqlite" }` (`store type "mysql" is no longer supported …`); `SqlDialect.name` and the migration `Dialect` allowed `"mysql"`, and `mysqlSnapshot`, the sql bus's MySQL DDL and duplicate-key handling, and MySQL branches in the migration runner, table copy, retention, outbound intents and the store catalog stayed; `src/compose.ts` had a MySQL `StoreConfig` variant, took the reviewed keys of an external config from the checked-in file on a MySQL store (`withReviewedKeys`), and set `sharedStore` from `store.type === "mysql"`.
- **`mysql` plugin kept, selected by nothing** (decision changed 2026-11-12, issue #654; replaced by `mysql` plugin and `MysqlDriver` removed). Before: `src/impl/store/mysql/` held the refused `mysql` plugin (declaring `MYSQL_PASSWORD`), `MysqlDriver` over `mysql2`, the MySQL schema and the step runner for `migrations/mysql/`, and `factory.config.json` and the coordination defaults named the MySQL schema and step paths.
- **Copy, then switch** (decision changed 2026-11-12, issue #653; replaced by No copy from MySQL). Before: `npm run migrate -- --copy-from-mysql` (`src/impl/store/mysql/copy-to-sqlite.ts`) read the MySQL store named by its `--mysql-host`/`--mysql-port`/`--mysql-database`/`--mysql-user` flags with SELECT only inside one consistent snapshot, wrote every table into `<state_dir>/db/factory.db` at the latest SQLite schema, checked each table by row count and primary-key checksum, refused while a factory process ran and over a `factory.db` holding data unless `--replace` (which backed the old file up to `db/backups`), and read `MYSQL_PASSWORD` from the secret file as the one named exception; `--dry-run` listed tables and row counts.
- **`mysql` selectable** (decision changed 2026-11-11, issue #590). Before: the deprecated `mysql` plugin was still selected by the checked-in config, setup created its database, user and `MYSQL_PASSWORD`, `MYSQL_*` settings in the secret file overrode the `store` block, and `npm run migrate` ran its step files.
- **Copy, then switch** (decision changed 2026-11-11). Before: nothing copied data from MySQL to SQLite; a SQLite store started from an empty file.
- **Copy reads the config's MySQL store** (decision changed 2026-11-11, issue #590). Before: `--copy-from-mysql` read the MySQL store named in the `store` block of `factory.config.json`; with `mysql` refused at startup, the connection now comes from the command's own flags.
- **`mysql` deprecated, SQLite the only store** (decision changed 2026-11-11, owner decision). Before: `mysql` and `sqlite` were both supported stores, `mysql` was selected by the checked-in config, and it was the store for a team or several hosts.
- **Worker processes** (store methods added 2026-11-07, issue #209). Before: the store kept no per-process record; the only worker data was the lease owner on each running run.
