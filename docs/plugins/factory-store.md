# FactoryStore

What it does: the factory's state (work items, runs, state changes, handoffs, leases). Every transition is a conditional update, so any number of controllers and workers can share it (architecture §4). The logic exists once in `SqlFactoryStore`; a backend is a `SqlDriver`.

**MySQL dialect removed from the code; the shared store is paused (decision changed 2026-11-13, issue #663, phase 1 of 2 of #659; current).** The decision that changed: a `mysql` store was refused at startup by its own check in `src/config-keys.ts`, with one line naming `"store": { "type": "sqlite" }`, and the SQL layer still knew a `mysql` dialect. Now the dialect is `sqlite` only (`SqlDialect.name`, the migration `Dialect`): `mysqlSnapshot`, the sql bus's MySQL column types, table options and duplicate-key handling, and the MySQL branches of the migration runner, table copy, retention, outbound intents and the store's table catalog are deleted. A config with `"store": { "type": "mysql", … }` fails at startup like any other unknown store, through the generic error `unknown FactoryStore plugin "mysql" at store.type`. The shared store (several hosts on one database) is paused: `src/compose.ts` has no MySQL `StoreConfig` variant and no reviewed-keys merge (an external config's `dials`, `floors`, `plugins`, `permissions`, `auth`, `toolchain`, `hooks` and `packs` were taken from the checked-in file only on a MySQL store), and it passes `sharedStore: false` to the pack loaders until phase 2 removes that option. The SQLite store is unchanged.

**`mysql` plugin and `MysqlDriver` removed (decision changed 2026-11-12, issue #654, phase 3 of 3 of #599; current).** The decision that changed: the `mysql` plugin and `MysqlDriver` stayed in code, selected by nothing, until a later phase removed them. Now `src/impl/store/mysql/` (the `mysql` plugin, `MysqlDriver`, the MySQL schema and its step runner) and the `mysql2` dependency are deleted, so no descriptor declares `MYSQL_PASSWORD`. `factory.config.json` (`hotspot_paths`, `mechanical_paths`, `path_companions`) and the coordination defaults (`DEFAULT_HOTSPOTS`, `DEFAULT_MECHANICAL`) name no MySQL path. The config refusal stayed until 2026-11-13 (MySQL dialect removed, above). Owner answer 1 of #599: no MySQL data is left to copy, because the live store moved to SQLite on 2026-11-11 (#618).

**`mysql` is deprecated; SQLite is the only store (decision changed 2026-11-11, owner decision; current).** The factory serves one owner ([08-enterprise.md](../design/08-enterprise.md), One owner, many workers), and its workers share one SQLite file on one machine, so a shared MySQL store for a team has no reason left. `sqlite` is the only store and the default. Replaced by: `sqlite` (nothing new). Removal plan: phase 1 (issue #590) is done: the checked-in config selects `sqlite` and `mysql` is refused at startup. Phase 3 of #599 (issue #654) is done: the `mysql` plugin, `MysqlDriver`, the MySQL schema and step runner and `mysql2` are deleted, so a schema change ships no MySQL step. Issue #663 (phase 1 of #659) removed the `mysql` dialect from the SQL layer and the MySQL store type from `src/compose.ts`. Follow-up issues remove the MySQL test-database and setup paths, the `sharedStore` pack option, and the docs that still describe MySQL.

**No copy from MySQL (decision changed 2026-11-12, issue #653, phase 2 of 3 of #599; current).** The decision that changed: **Copy, then switch** (2026-11-11), under which `npm run migrate -- --copy-from-mysql` copied a MySQL store's data into `<state_dir>/db/factory.db`. The copy is removed: `src/impl/store/mysql/copy-to-sqlite.ts` and `src/impl/store/mysql/migrate-command.ts` are deleted, and `--copy-from-mysql`, `--replace`, `--mysql-host`, `--mysql-port`, `--mysql-database` and `--mysql-user` are unknown arguments to `npm run migrate` (it prints the unknown-argument message and exits 1). The migrate command reads no secret. The factory can no longer move a MySQL store's data into SQLite; whether data moves by another route is the owner's decision (decision 1 of #599). The SQLite modes of `npm run migrate` are unchanged; their argument parser lives in `src/cli/handlers/migrate/migrate-args.ts`.

Worker processes (2026-11-07, issue #209; design §5 Worker slots reported per process): `reportWorkerProcess(report)` writes one process's snapshot (`process_id` `<host>:<pid>`, `pid`, `host`, `slots`, `max_slots`, `busy`, `index_base`, `started_at`) with `reported_at` = the store clock's now; keyed by `process_id`, so a repeat write replaces the row (update, else insert; a concurrent first insert that loses updates). `listWorkerProcesses(max_age_ms)` returns the rows at most `max_age_ms` old, by host, pid, process_id (read-only). `removeWorkerProcess(process_id)` deletes one row on a clean stop. Table `worker_processes`: SQLite migration 19; MySQL step `migrations/mysql/0019-worker-processes.sql`, run by `npm run migrate`. Both backends share the contract tests in `tests/store-contract.test.ts`; on MySQL an upgrade test from state 18 runs the step through `MysqlMigrations`.

Schema changes of 2026-11-09 (issue #461), on both backends through timestamped migrations: index `worker_runs_ack` on `worker_runs (acknowledged_at, updated_at)` (`src/worker/migrations/20261109T1400-worker-runs-ack`, additive), so `listUnacknowledgedRuns` walks the unacknowledged runs instead of scanning every run; and the column `runtime_child_restarts.recorded_at` is dropped (`src/runtime/migrations/20261109T1401-runtime-drop-restart-recorded-at`, breaking: archived and verified first; on MySQL run by `npm run migrate` with the writers drained).

Plugins:

- `sqlite`: `SqlFactoryStore` over `SqliteDriver`, file at `<state_dir>/db/factory.db`. One machine. Selected by the checked-in config, and used when there is no `store` block.
  - Enable: `"store": { "type": "sqlite" }`. Secrets: none. Applies additive migrations when opened; `npm run migrate` applies the breaking ones and the data steps, and `npm run migrate -- --contract` the contract ones.

No `mysql` plugin (removed 2026-11-12, issue #654). A config with `"store": { "type": "mysql", … }` fails at startup with `unknown FactoryStore plugin "mysql" at store.type`. Setup, `npm run migrate` and teardown have no MySQL path. No plugin declares `MYSQL_PASSWORD`, so a value left in an old secret file is neither read nor scanned. No command copies a MySQL store's data into SQLite (No copy from MySQL, above).

Switch back / disable: none. A store cannot be disabled: the factory has no state without one.

## History

- **`mysql` store refused by its own check; the MySQL dialect kept** (decision changed 2026-11-13, issue #663; replaced by MySQL dialect removed from the code). Before: `checkConfigKeys` refused a `mysql` store with one line naming `"store": { "type": "sqlite" }` (`store type "mysql" is no longer supported …`); `SqlDialect.name` and the migration `Dialect` allowed `"mysql"`, and `mysqlSnapshot`, the sql bus's MySQL DDL and duplicate-key handling, and MySQL branches in the migration runner, table copy, retention, outbound intents and the store catalog stayed; `src/compose.ts` had a MySQL `StoreConfig` variant, took the reviewed keys of an external config from the checked-in file on a MySQL store (`withReviewedKeys`), and set `sharedStore` from `store.type === "mysql"`.
- **`mysql` plugin kept, selected by nothing** (decision changed 2026-11-12, issue #654; replaced by `mysql` plugin and `MysqlDriver` removed). Before: `src/impl/store/mysql/` held the refused `mysql` plugin (declaring `MYSQL_PASSWORD`), `MysqlDriver` over `mysql2`, the MySQL schema and the step runner for `migrations/mysql/`, and `factory.config.json` and the coordination defaults named the MySQL schema and step paths.
- **Copy, then switch** (decision changed 2026-11-12, issue #653; replaced by No copy from MySQL). Before: `npm run migrate -- --copy-from-mysql` (`src/impl/store/mysql/copy-to-sqlite.ts`) read the MySQL store named by its `--mysql-host`/`--mysql-port`/`--mysql-database`/`--mysql-user` flags with SELECT only inside one consistent snapshot, wrote every table into `<state_dir>/db/factory.db` at the latest SQLite schema, checked each table by row count and primary-key checksum, refused while a factory process ran and over a `factory.db` holding data unless `--replace` (which backed the old file up to `db/backups`), and read `MYSQL_PASSWORD` from the secret file as the one named exception; `--dry-run` listed tables and row counts.
- **`mysql` selectable** (decision changed 2026-11-11, issue #590). Before: the deprecated `mysql` plugin was still selected by the checked-in config, setup created its database, user and `MYSQL_PASSWORD`, `MYSQL_*` settings in the secret file overrode the `store` block, and `npm run migrate` ran its step files.
- **Copy, then switch** (decision changed 2026-11-11). Before: nothing copied data from MySQL to SQLite; a SQLite store started from an empty file.
- **Copy reads the config's MySQL store** (decision changed 2026-11-11, issue #590). Before: `--copy-from-mysql` read the MySQL store named in the `store` block of `factory.config.json`; with `mysql` refused at startup, the connection now comes from the command's own flags.
- **`mysql` deprecated, SQLite the only store** (decision changed 2026-11-11, owner decision). Before: `mysql` and `sqlite` were both supported stores, `mysql` was selected by the checked-in config, and it was the store for a team or several hosts.
- **Worker processes** (store methods added 2026-11-07, issue #209). Before: the store kept no per-process record; the only worker data was the lease owner on each running run.
