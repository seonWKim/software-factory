# TacitLedger

**Retire of a class removes its block, and `retired()` lists the retired classes (decision changed 2026-11-14; current; replaces "retire runs `tacit verdict <C-id> retire` only", see History).** The decision that changed: a retire verdict on a class now edits the owner's rules file as promote does (block out, verdict, sync-agents, rollback on a failed verdict), and the ledger's retire verdicts are read back for the Rules page's Retired list. Design: [09-dashboard-app.md](../design/09-dashboard-app.md), [07-self-improvement.md](../design/07-self-improvement.md).

What it does: captures the owner's pushback in their own tacit-knowledge ledger, so the owner's tools can learn from it (issue #570). A `/revise`, a `/reject` and a `/verdict changes` (also a dashboard revise, reject or changes verdict) each capture one record once the command applied. The capture is an outbound intent (action `tacit_capture`, destination `tacit:ledger`), keyed by the item and the command's comment ID, so a command delivered twice, or handled by two workers, stores one intent. The process that flushes outbound runs the ledger's CLI; the command's stage change never waits on it. Design: [04-gate-commands.md](../design/04-gate-commands.md).

The interface (`src/interfaces/tacit-ledger.ts`) has `capture` (one pushback), `pending` (the entries waiting for a verdict, each with `id`, `title` and `state`, and a proposal's `kind` and `target` when listed), `show(id)` (one entry's detail, or null; since 2026-11-13), `verdict(id, decision, reason, rule?)` (the owner's verdict on an entry; `rule` is `{ wording, default, exception }`, on promote of a class only) `rules` (the promoted rules), `applied()` (the whole rules file for the Rules page's Applied group, since 2026-11-13; optional like `show`; the runtime holder delegates it) and `retired()` (the retired classes, newest first, `{ id, reason, date }`, since 2026-11-14; optional; the UI's holder reads it from the plugin it last built, as `show`). `show` is optional in the interface because the runtime holder (`src/runtime/live-tacit.ts`) does not delegate it yet; the UI's holder (`uiTacit` in `src/ui/rules-api.ts`) reads it from the plugin it last built. `capture` is wired into outbound; `pending`, `show` and `verdict` serve the dashboard's Rules page and `rules` the learned rules in every prompt (design 07-self-improvement.md, 09-dashboard-app.md).

Plugins:

- `none`: `NoTacitLedger`. No ledger: nothing is captured and no outbound intent is recorded. `pending` and `rules` return nothing, `applied()` returns `{ rules: [], elsewhere: [] }`, `show` returns null, `retired()` returns nothing; `verdict` does nothing (a retire too). The Rules page then shows no Applied group, so no suggestion and no Retire action.
  - Enable: `"plugins": { "tacit": "none", ... }`, or leave `tacit` out (the default on every platform). Secrets: none. Settings: none.
- `agents-home`: `AgentsHomeTacitLedger`. Runs the ledger's CLIs in the owner's agents home on this machine. The home is the `AGENTS_HOME` environment variable when set, else `~/.agents`; the path is found by the plugin only, never by core or controller code.
  - Enable: the Rules page's **Turn on** (below), or `"plugins": { "tacit": "agents-home", ... }`. Secrets: none. Settings: `integrations` (runtime, owner only), `AGENTS_HOME` (optional; default `~/.agents`).
  - `capture` runs `<home>/bin/tacit capture --agent software-factory` with one JSON record on stdin, never in argv: `session` (the work item ID), `proposal` (the stored summary of the item's latest finished run: its spec, change or review), `pushback` (the owner's words, verbatim), and `root_reason`, `hypothesis`, `improvement` and `rule_draft` empty (the ledger distils those itself).
  - The other calls use the owner's real CLI forms (checked 2026-11-12 with `--help`). Each value is its own argv item, nothing goes through a shell, and only `capture` uses stdin.
    - `pending` runs `<home>/bin/evolve pending`, which prints text, not JSON, and reads it (`src/impl/tacit/ledger-text.ts`): each `- P-id [kind] target — title` row under `## proposals (open)` or `## proposals (held)`, and each `- C-id title` row under `## tacit Pending` or `## tacit Held`, is one entry whose state is the heading's word in lower case (`open`, `held`, `pending`). A proposal keeps its `kind` (`promote-learning`, `edit-asset`, `new-asset`) and `target` (the asset it changes) when the row has them. Rows under any other heading are skipped. An entry with a `{"type":"verdict","class":<its id>,"ts":…,"decision":…}` line in `<home>/private/tacit/ledger.jsonl` whose `ts` is newer than `<home>/private/tacit/rule-candidates.md`'s modification time is `judged` with that decision (the daily brief rebuilds that view, which `evolve pending` reads, at 08:30; no view file: nothing is judged). Each other class gets its `draft` from `<home>/bin/evolve show <id>`, or a `draft_error`.
    - `show` runs `<home>/bin/evolve show <id>` (example: `evolve show C-037`) for a class or a proposal and reads its text (`parseShow`). The form is assumed, not yet checked against the real CLI: field lines `기본값:` / `default:` (the draft rule), `예외:` / `exceptions:`, `범위:` / `scope:`, `근본 원인:` / `root reason:`, `kind:` and `target:`, with or without a list dash, an indented line continuing one; and an `## incidents <n>` heading whose `- <ref> — "<the owner's words>"` rows are the incidents (the count is `<n>`, else the rows). A field the text lacks is absent; an empty text is null. Any other ID throws before a CLI runs. It reads only: nothing is written to the store or the ledger.
    - `evolve show <C-id>` is read in the owner's sample form (2026-11-13): `### C-xxx <title>`, then `- 인시던트: <T-ids>`, `- 초안: 기본값: <default> / 예외: <exception>` (split on ` / 예외: `), `- 범위: <scope>`, before the `# incidents` and `# verdicts` sections. A missing part is an error, never a guess.
    - `verdict` on a class (`C-` ID) to hold or reject runs `<home>/bin/tacit verdict <id> <hold|reject> --reason <reason>`; retire is below. On a proposal (`P-` ID) it runs `<home>/bin/evolve verdict <id> <hold|promote|reject> --reason <reason>`, never with a rule (`evolve` takes no retire). Any other ID throws before a CLI runs. The CLIs take no field for who judged, so the ledger does not record it; the dashboard's log does. `--applied-to` is not used.
    - Promote of a class encodes the rule, as the owner did by hand. Checks come first, each a `TacitRefusal` (the Rules page's 409) with nothing written and no verdict: a rule is given; `<home>/private/tacit/rules.md` exists and its resolved path (symlinks followed) lies inside the resolved home; it has no `## <C-id>` heading yet; it has the `## 다른 곳에 인코딩된 규칙` heading; `<home>/bin/sync-agents` is executable; `evolve show <C-id>` reads as a draft. Then one block goes immediately before that heading, followed by a blank line: `## <C-id> <wording>`, `- 기본값: <default>`, `- 예외 (이럴 땐 override): <exception>`, `- 근거: 인시던트 <the draft's T-ids, joined by ", "> / 판정일 <today, YYYY-MM-DD>`, `- 범위: <the draft's scope>` (line breaks in a value become spaces). Then `<home>/bin/tacit verdict <C-id> promote --reason <reason> --rule <wording> --encoded-to private/tacit/rules.md`; if it fails the file is written back byte for byte and the CLI error is thrown. Then `<home>/bin/sync-agents`; if it fails the block stays (the verdict is recorded) and `TacitSyncFailed` is thrown. Nothing undoes a verdict or a sync that succeeded, and the file is not locked against the owner's own edits made at the same time.
    - Retire of a class removes the rule, as the owner did by hand. Checks come first, each a `TacitRefusal` (the Rules page's 409) with nothing written and no CLI run: `<home>/private/tacit/rules.md` exists and its resolved path lies inside the resolved home; it has a `## <C-id>` heading. Then the block (its heading line up to the next `#` heading or the end of the file, its trailing blank line included, so it undoes a promote's block; `withoutRuleBlock`) is removed and every other byte kept. Then `<home>/bin/tacit verdict <C-id> retire --reason <reason>`; if it fails the file is written back byte for byte and the CLI error is thrown. Then `<home>/bin/sync-agents`; if it fails the removal stays (the verdict is recorded) and `TacitSyncFailed` is thrown. A retire of a proposal throws before a CLI runs.
    - `retired()` reads `<home>/private/tacit/ledger.jsonl`: each class whose newest `{"type":"verdict","class":…,"ts":…,"decision":…}` line is a `retire` is one entry, `{ id, reason (the line's reason, else ""), date (the first ten characters of its ts) }`, newest first. A class promoted again after its retire is not listed. No file: nothing. Read-only.
    - `applied()` reads the same file for the Rules page (`parseApplied` in `src/impl/tacit/ledger-text.ts`), read-only. Each `## ` block up to the next `#` heading is one item: with a `C-xxx <name>` heading and a `- 기본값:` line it gives `id`, `name`, `default`, `exceptions` (`- 예외…`), `scope` (`- 범위:`), `incidents` (the T- IDs before `판정일` on the `- 근거: 인시던트 <T-ids> / 판정일 <YYYY-MM-DD>` line) and `judged` (that date), a part the block lacks being absent; any other block (no C- ID or no `기본값` line) is `{ raw }`, its text as written. `elsewhere` is the non-empty lines under `## 다른 곳에 인코딩된 규칙` up to the next `#` heading, as written. No file: `{ rules: [], elsewhere: [] }`, not an error. The route passes every text through the Withholder.
    - `rules` reads `<home>/private/tacit/rules.md` (the CLIs have no JSON listing of it): each `## C-xxx <name>` section gives its `- 기본값:` (the rule), `- 예외` (exceptions) and `- 범위:` (scope) values as written; an indented line under one continues it. No file: no rules, not an error. `AGENTS_PRIVATE` is not honoured yet: only `<home>/private` is read.
  - Each CLI call is stopped after 30 seconds and counts as a failure; a call that exits non-zero or times out throws `<cli> <subcommand> exited <code>: <stderr>` or `<cli> <subcommand> stopped after <ms> ms` (for `show`: `evolve show exited <code>: <stderr>` or `evolve show stopped after 30000 ms`; the Rules page then says "The detail could not be read." and keeps the card). A failed capture is retried with outbound's backoff (`retry_base_ms`, `retry_max_ms`) and holds only the `tacit:ledger` destination: GitHub, Slack and the factory repo keep sending.
  - The pushback and the proposal pass the egress scanner (G5) before the CLI is called; a flagged text is replaced by the notice that names the rules.
  - The factory writes one file under the home, `<home>/private/tacit/rules.md`, and only on promote or retire of a class (above); its resolved path must lie inside the resolved home, else nothing is written. Otherwise it runs the CLIs there and reads the rules file, `ledger.jsonl` and `rule-candidates.md`'s modification time. The plugin is built in the factory's processes only (the controller and worker pool, and `factory ui` for the Rules page); an agent run never gets it, and no agent environment holds the home.
  - The home is found only when `bin/tacit` and `bin/evolve` are both executable files there (`checkAgentsHome`). Otherwise the plugin behaves as `none` and startup goes on.

Not captured: a "Request changes" PR review, implicit verdicts and reverts (a follow-up issue covers the review), and pushbacks stored before the plugin was selected (no backfill). A ledger shared between people is not built (one owner, `docs/design/08-enterprise.md`).

Turn on / off (since 2026-11-12): TacitLedger is an integration (`integration: true` in `src/plugins.ts`, [selection.md](selection.md)), switched at runtime by the `integrations` setting, with no restart.

- **Turn on.** With the ledger off, the Rules page checks the agents home (`AGENTS_HOME`, else `~/.agents`). Found: it reads "Found your agents home at <path>" with one primary **Turn on** button, which stores `{ "tacit": "agents-home" }` in `integrations` through POST /api/v1/settings (the settings route's guards and the owner check), and the page then lists the rules with no reload. Not found: it names the missing file and says to put the CLIs in `<home>/bin` or start the factory and `factory ui` with `AGENTS_HOME` set. A runtime setting never names a path: the entry is only the plugin name. From a terminal: `factory settings set integrations '{"tacit":"agents-home"}'`.
- **Turn off.** The Settings page's Integrations section lists TacitLedger with its plugin and whether the setting or the config chose it; its Switch removes the entry (`settings reset integrations` when no other entry is left), so `plugins.tacit` in factory.config.json decides again.
- **Config.** `plugins.tacit` stays the default when `integrations` has no `tacit` entry: `agents-home` (on) or `none` (off, the default when left out).
- **When it applies.** The controller and the worker pool rebuild the plugin by their next tick, `factory ui` by its next Rules request. Captures already recorded and not delivered stay in outbound until a process with the plugin on flushes them.

## History

- 2026-11-14: retire of a class removes its `## <C-id>` block from the rules file before `tacit verdict <C-id> retire --reason <reason>` (rolled back if it fails), then runs `bin/sync-agents`; `retired()` added. Before: retire ran `tacit verdict <C-id> retire --reason <reason>` only, the rule's block stayed in the rules file (and in every prompt) until the owner removed it by hand, and nothing read retire verdicts back.
- 2026-11-13: `applied()` added. Before: nothing read the rules file's `근거` line, a block that was not a `C-` block, or the `## 다른 곳에 인코딩된 규칙` lines, and the Rules page could not show promoted rules.
- 2026-11-13: promote of a class writes the rule's block into `<home>/private/tacit/rules.md`, then runs `tacit verdict … --encoded-to private/tacit/rules.md`, then `bin/sync-agents`; `pending` adds the judged state and each class's draft (`evolve show`). This replaces "promote sends --rule only" and "The factory never writes under the home": before, promote ran `tacit verdict <C-id> promote --reason … --rule <wording>` and nothing else, which the owner's ledger refuses ("promote requires --rule and --encoded-to"), so no rule was encoded.
- 2026-11-13: `show(id)` added (`evolve show <id>`), and `pending` keeps a proposal's kind and target. Before: `pending` dropped them and nothing read an entry's detail, so the Rules page showed state, ID and title only.
- 2026-11-12: the ledger turns on and off at runtime from the dashboard (`integrations`), and the home needs both CLIs executable. Before, it turned on only by setting `plugins.tacit` to `agents-home` in factory.config.json and restarting the factory and `factory ui`, the Rules page listed those steps, and a home with only `bin/tacit` counted as found.

- 2026-11-12: `agents-home` uses the owner's real CLI forms; `list` became `pending`, `verdict` takes a reason and an optional rule, and `rules` was added. Before: `list` ran `tacit list --agent software-factory --state <state> --json` and `verdict` ran `evolve verdict --agent software-factory` with `{ id, verdict, reason, by, text? }` as JSON on stdin, forms written against stub CLIs that the real `tacit` and `evolve` do not have, so the Rules page and the learned rules read nothing and every verdict failed.
- 2026-11-11 (issue #570): the interface and both plugins added, `none` the default. Before, a pushback was stored only in the factory's own store and left no trace the owner's ledger could read.
- 2026-11-11: `agents-home` added; before, no plugin wrote to the owner's ledger.
