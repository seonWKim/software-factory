# AuthProvider

What it does: resolves an external identity to a factory user and decides whether it may act (submit work, approve, reject, retry, merge, record a verdict, approve a pack tool). Deny by default.

**One owner check replaces the auth plugins (decision changed 2026-11-12, issue #575; current).** The decision that changed: **one owner check, `OwnerAuth` in `src/core/authorize.ts`, judges every command from every surface**, instead of the per-origin plugins `github`, `local` and `none` over the grant sources. The factory serves one owner ([08-enterprise.md](../design/08-enterprise.md), One owner, many workers), so there is nothing left to choose: AuthProvider is no longer a plugin kind, and there is no config key for it.

- **Who is allowed.** A gate action (`approve_spec`, `approve_merge`, `record_verdict`, `use_tool`, `approve_tool`) is allowed only when the command's factory user is the owner: the store's local owner (`identity_local_users`, role `owner`). While the store has no owner, only `cli_user` (the dashboard: its own CLI identity; `factory settings`: the CLI identity) becomes it on its first check; `local:anonymous` never does. Anyone else is refused with reason `not_owner`, and the command gets the reply "only the owner may send this command". `submit_work` stays open to any resolved user: intake keeps its own gate on the source (the intake label).
- **Surfaces.** The same check for GitHub comments, Slack messages, the local CLI and the dashboard. The owner's GitHub or Slack account acts as the owner once linked to it with `/link <code>` (code from `factory link-code <owner user ID>`), or when `cli_user` is that account's user ID (`github:<id>`).
- **Resolving.** A linked account resolves to its factory user (by provider and subject only, never a display name). An unlinked GitHub account is `github:<numeric id>`; a local identity is `local:<x>` (or the `cli_user` ID itself); any other unlinked account (Slack) resolves to no user and is refused with the "not linked" reply.
- **Passports.** The controller wraps it in `AuditedAuthProvider` (`src/impl/auth/audited-auth.ts`): Identity checks a command's edge passport first, then the owner check decides, and every decision is audited, as before.
- **No remote call.** Nothing asks GitHub for a repository permission; a GitHub outage or rate limit never stops a gate command.
- Roles (`approver`, `requester`) and local users other than the owner stay in the store until they are removed (issue #568, phase 2), but grant nothing.

Enable: nothing; it is always on. Secrets: none. Switch back: none (the removed plugins and the `auth` and `permissions` config keys are gone; a config that still has either key fails at load as an unknown key).

## History

- **One owner check** (decision changed 2026-11-12, issue #575). Before: the AuthProvider plugins `github` (`GitHubAuthProvider`: GitHub accounts, with roles from the `github-permission` grant), `local` (`LocalAuthProvider`: local identities and linked Slack accounts, with roles from the stored local users and the `static` grant) and `none` (`NoAuthProvider`: allowed everything) were selected per command origin by the `auth` key (`github_issue`, `local`, `slack_thread`), and the grant sources (GrantSource: `github-permission`, `static`) were selected by `permissions.grants`; refusals were `no_role` or `denied`.
- **`github`, `local` and `none` deprecated** (decision changed 2026-11-11, owner decision). Before: the three plugins, selected per command origin, judged several people by their links, stored local roles and grants.
- **Slack accounts are judged by `local`** (decision changed 2026-11-09, issue #498). Before: the plugin selected for GitHub comments (`github`) judged Slack accounts through their links, so their rights came from GitHub grants, not from the stored local roles.
- **Auth per command origin, `local` plugin** (new decision, 2026-11-07, issue #318). Before: one `auth` plugin judged every command, so local CLI commands under `auth: github` needed a link that no command created.
- **Slack thread commands get their own origin** (decision changed 2026-11-09, issue #486). Before: `auth` knew only `github_issue` and `local`, and every non-local identity, Slack included, was judged by the `github_issue` plugin with no way to change it. With #498 merged first, the default for Slack is the `local` origin's plugin, and `slack_thread` overrides it.
