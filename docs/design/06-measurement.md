- **A skill-eval case's checks are deterministic, yes/no, rubric or pairwise, in one score (decision changed 2026-11-25, tk_dd195e55 phase 2 of 4; current; replaces "a case passes only when the judge answers every check yes" and "`judge_version` hashes `skill-judge.md` alone"; see History).** `expected` stays a list of checks or `{"checks": [...], "threshold": n}` (`skill-evals/checks.ts`). A string is a must-have yes/no check. An object's `kind` is deterministic (`contains`, `does-not-contain`, `regex`, `max length`, `valid JSON`, `JSON schema subset`), `rubric` (anchors "1" to "5") or `pairwise`, with `weight` (≥ 0, default 1) and `must` (default true except rubric and pairwise). Authoring refuses an unknown kind, a missing anchor, a weight below 0. Deterministic checks run first, no model call; a failed must-have one fails it, no judge call. The rubric judge writes its reason before its 1-to-5 score. A pairwise check asks twice, order swapped, whether the new answer beats the newest other skill version's stored one; a win needs both yes; with none to compare it is left out of the score. Values: 1/0, rubric (score − 1) ÷ 4, pairwise win 1; score = Σ weight × value ÷ Σ weight. Pass: every must-have passes and the score reaches `threshold`: 1 when all checks are strings or deterministic, else 0.8 (string-only cases: all-yes). `judge_version` is the SHA-256 over `skill-judge.md` and `skill-judge-pairwise.md`; no backfill.
