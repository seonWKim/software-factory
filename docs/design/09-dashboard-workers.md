# 9. Status page: dashboard Workers timeline and graph

- **A timeline bar's link is at least 24x24px (new decision, 2026-11-22, issue #763; current; adds to the timeline decision below, replaces none).** In the Workers timeline (`Timeline`, `web/src/views/workers.tsx`) the drawn bar (`data-bar`) keeps its time width (at least 4px) and 20px height; the item link (`data-run`) is a transparent box centred on it, the bar's size but at least 24x24px, so the responsive check's `small-target` rule passes. Highlight and dimming stay on the drawn bar.

- **The Workers timeline and the dependency graph are two cards of Health's Runs tab, read only; there is no Workers page (decision changed 2026-11-28, owner: "health and workers menu can be merged"; current; replaces "the Workers page at `/app/workers` in the sidebar's System block", see History).** `HEALTH_TABS.runs` (`web/src/views/pages.tsx`) is `runners`, `timeline`, `graph`, `failures`, `sleeps`: the cards come from `WorkersTimelineCard` and `WorkersGraphCard` in `web/src/views/workers.tsx`, after Runners ([09-health.md](09-health.md)). `/app/workers` redirects to `/app/health?tab=runs`, keeping the query. Nothing on them edits anything; the only control is the window switch (`SegmentedControl`: 1h, 6h, 24h; 6h at first), the timeline card's action, and it narrows the graph card too. `HealthPage` holds the window and the highlighted item. Both reads poll every 10 seconds while the page is visible (`useApi`, so a hidden tab stops). The reads, timeline, graph and tooltips below are unchanged.
  - **Reads.** `GET /api/v1/runs` without `window` is unchanged (running and queued runs). With `window=1h|6h|24h` it adds the runs finished in the window (`listRunsFinishedWithin`) and gives every run `finished_at`, `item_title` and `item_stage`, `error_code` (failed runs), `model` and `cost_usd` (null when unknown); any other window is a 400. `GET /api/v1/items/graph?window=` (both in `src/ui/graph.ts`; routed before `/items/:id`; no window reads 6h, any other a 400) returns `nodes` (open items and items closed in the window, each `id`, `title`, `stage`, `blocked_reason`) and `edges` (`from` → `to`): a dependency edge from the item whose source id the dependent's `controller_dependency_edges` row names, and a `phase` edge from a split parent to each phase. An edge whose other end is not a node is left out. Titles, blocked reasons, error codes and models pass the Withholder: a withheld title is its marker and the id still shows. No store method, schema or migration is added.
  - **Timeline.** Runs have no worker slot, so lanes come from time only: `packLanes` (`web/src/views/workers-layout.ts`) sorts by start and puts each run in the lowest lane free by its start, so overlapping runs never share a lane and the lane count is the most runs at once. A running run ends at now; a start before the window is cut to it. Queued runs are not drawn; a running or finished run with no `started_at` is left out and the card says how many. Bars are coloured by kind category (`kind-*` tokens: triage, implement, review, resolve, merge-check, and other for update, manual, interactive and improve); running bars pulse (still under reduced motion), failed bars have a 2px `failed` edge. A line marks now at the right edge; the axis shows the window's start, middle and now; a legend names the six kinds and the two status looks. The plot keeps a minimum width and scrolls inside its card at phone width.
  - **Graph.** Items with no edge are left out, and the card says "N items with no dependencies". `layerOrder` puts every item one layer right of its furthest-right prerequisite, rows in input order within a layer; when only a cycle is left it places the first node of it from its placed prerequisites, so a cycle never hangs. Nodes are HTML links over one plain SVG of edges (no graph library), filled by stage (pill tones; closed items dashed); phase edges are dashed.
  - **Tooltips.** Bars and nodes are links to the item page inside the shared `Tooltip` (`menu.tsx`), open on hover and keyboard focus. A bar: item title, item id, run kind and status, started, finished or "running for", duration, error code when failed, model and cost when known; an unknown field is left out, never 0. A node: title, id, stage and blocked reason. Hovering or focusing a node lights its edges and its runs and dims the rest.
