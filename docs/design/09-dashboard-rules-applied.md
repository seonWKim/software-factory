# 9. Status page: dashboard Rules page, applied rules

- **An applied rule shows how often it was seen (decision changed 2026-11-22, wi_77a69896, from rejected wi_d4201038; current; replaces the Evidence part of its Details, see History).** A row shows "Seen N times (Mon D)" ("Seen 1 time (Oct 17)"): N counts its incident IDs once each; the date is the latest day an ID starts with (`T-YYYYMMDD`, local). Undated IDs: no date; none: no line. It is an `IdDetails`: the IDs only in its tooltip. Details: Default, Exception, Judged. No API change.
- **An applied rule is edited and its evidence opened from its ⋯ menu, every default line shows, and pushbacks show before they cluster (decision changed 2026-11-22, wi_ec1a534e; current; replaces the Retire-only menu and the overwritten repeated lines, see History).**
  - **Menu.** An applied class row's `OverflowMenu` holds Edit, Open evidence and Retire (still its `danger` item, unchanged); a raw block has none. For anyone but the owner Edit and Retire are disabled and the tooltip reads "Only the owner edits or retires a rule."; Open evidence stays on.
  - **Edit.** A `Dialog` "Edit: <name>" with Promote's three `Field`/`Textarea`s (wording prefilled with the name, default, exception; each required, 1 to 2000 characters), no reason, Save the one primary action of its `ButtonRow`. It posts `{ id, text, default, exception }` to `POST /api/v1/rules/edit` behind the write guards and the owner check: 400 for a non-class ID or a bad field, 403 for anyone but the owner, 409 with no ledger, no `edit`, or a refusal with nothing written (no block, a failed file or sync-agents check), 502 when the write failed (file put back byte for byte) or "The rule was saved, but sync-agents failed". `TacitLedger.edit` rewrites only the block's heading and its `기본값` and `예외` lines (docs/plugins/tacit-ledger.md); no verdict is sent.
  - **Open evidence.** A read-only `Dialog` "Evidence: <name>" (Done closes it) holding the waiting entry's `EntryDetail`, which now takes an ID and a title.
  - **Every default line.** `parseApplied` adds a repeated `기본값`, `예외` or `범위` line after the earlier one; the Details show each line on its own line. `parseRules` is unchanged (a follow-up).
  - **Pushbacks.** A `Card` "Pushbacks" (count: its rows) after Applied in the Applied tab: a row shows the owner's words (Withholder) and date, no ID, and one secondary `sm` Dismiss: a `Dialog` says it records the pushback as noise, then posts `{ id }` to `POST /api/v1/rules/pushbacks/dismiss` (same guards and owner check; off with a tooltip for others). `GET /api/v1/rules` adds `pushbacks`: null with the ledger off or no `pushbacks` method (no card), else `{ rows, error }`; a failed read shows a Notice and the rest of the page loads. The forms `tacit show --active --unclustered` and `tacit status <T-id> noise` are assumed until the owner confirms them (decision 2).
  - **Not built:** clustering, promoting or undoing a pushback, a noise backfill, editing a proposal, scope or `근거` line.
  - **Why:** editing a rule meant a hand edit and a sync, two default lines showed as one, and unclustered pushbacks were CLI-only.
- **The Rules page suggests which applied rules to retire, and the owner retires one with a reason (decision changed 2026-11-14; current; replaces "the Applied group is read-only: no button and no route", from the 2026-11-13 Applied group decision below, see History).** The decision that changed: **each applied class has a Retire action, and a Suggest button marks the rules that look ready to retire, each with its reason.** Nothing is retired without the owner's click.
  - **Suggest.** The Applied `Card`'s action is a secondary Suggest button (shown when a block parses as a class). A press reads `GET /api/v1/rules/entry?id=<C-id>` once per applied class; nothing is read for suggestions on page load (the approver's note: one `evolve show` per rule on every load would slow the page). Each press is a new round of reads; the last round's answer stays shown until the next press or a reload. The entry read adds `retire`: for an applied class the reasons from `retireSuggestions` (`src/core/rule-retirement.ts`, pure, no imports: design 07-self-improvement.md has the three signals), `[]` for none, null for any other entry, the ledger off or a failed read of the rules file; each reason passes the Withholder. A rule with a reason shows a "Suggested to retire" `Badge` beside its ID and its reasons under its name; the others show none. Reads only: the rules file, the ledger and the verdict CLIs are untouched.
  - **Retire.** Every applied class has Retire as the `danger` item of its row's ⋯ menu (an unparsable block has none; since 2026-11-21, see the plain-words decision in 09-dashboard-rules.md), disabled for anyone but the owner, whose menu carries the owner-only tooltip. It opens the shared `Dialog` with a required reason ("Why?"), so the row's height does not change; the confirm is "Send retire". It posts `{ "id", "verdict": "retire", "reason" }` to POST /api/v1/rules/verdict (`RULE_VERDICTS` gains `retire`): 400 for a rule field or an ID that is not a class (`only a class (C-) is retired`), 403 for anyone but the owner, 409 when the plugin refuses with nothing written (`The retire was refused: …`), 502 when the CLI fails (the rules file put back byte for byte) or sync-agents fails after the verdict (recorded); the request guards are those of every verdict. The plugin removes the block and runs the verdict (docs/plugins/tacit-ledger.md).
  - **Retired.** `GET /api/v1/rules` adds `retired` (null with the ledger off; else `[{ id, reason, date }]`, newest first, through the Withholder), read through `TacitLedger.retired()` from the ledger's retire verdicts. After the Applied group a "Retired" `Section` holds a collapsed `details` ("Show retired rules"), one row per class: its ID and "Retired <date>: <reason>". Not shown when there are none.
  - **Not part of this decision.** Automatic retirement, a closed-project signal, a model call, scheduled suggestions, undoing a retire, pack learnings (`learnings.md`), and a retire history from before this change. No config key and no store state. Strings are `t()` keys in `web/src/i18n/en.ts`.
  - **Why:** rules only ever grew: nothing said which were stale, duplicated or no longer true, and retiring one needed a terminal and a hand edit of the rules file.
