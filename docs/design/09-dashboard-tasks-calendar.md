# 9. Status page: dashboard Calendar page

- **Calendar page: pressing an event opens its whole details in a popover beside it, a sheet below `sm` (new decision, 2026-11-24, owner request #91 "when we click the items on the calendar, it should display the whole information"; current; replaces the chip's tooltip and its Clamp "Show more", see History)** (`web/src/views/calendar-event.tsx`, the shared `Popover` and `ChipButton` in `web/src/components/ui/popover.tsx`). Every event chip in Week and Month is a `ChipButton` (`aria-haspopup="dialog"`, `aria-expanded`, named by its time and whole title, so a title cut at 2 lines in Week or one line in Month is still read whole); Enter or Space opens it, Esc or the close button closes it and focus returns to the chip. From `sm` up it opens a `Popover` beside the chip (right of it, else left, else under it, inside the window); below `sm` the same content opens as a sheet (`ModalPanel`) with the title wrapped whole. The panel shows, each on a row with a quiet icon and leaving out what the event does not have: the whole title (its heading); the day and the time range in the viewer's time zone with the zone's short name ("9:00 – 10:30 AM GMT+9"), or the day(s) and "All day", plus "Set in <zone>" when the event was written in another zone; the calendar's name with the source's strip colour (and the source when several are connected); the place; "Join video call" and its address; the people, organizer first, each with their answer (Going, Not going, Maybe, No answer yet); the notes; then "Open in Google Calendar" (an event page on google.com, else "Open in calendar"). Notes are shown as text, never as HTML: markup becomes plain text (line breaks kept, script and style dropped, entities decoded, a link as "label: address") and only http(s) addresses become links (`web/src/lib/plain-text.ts`), opening in a new tab with `noopener noreferrer`. **Data.** The read (`GET /api/v1/calendar/events`) answers each event's `starts_at`, `ends_at` and `details` (`calendar`, `location`, `description`, `organizer`, `attendees`, `conference_url`, `link`, `time_zone`; null for an event stored before details were kept): every text passes the egress scan as the title does (`Withholder`), and `GET /api/v1/tasks` leaves `details` out. The sync stores them in the new nullable `calendar_events.details` (JSON; migration `20261124T1500-calendar-event-details`, filled by the next sync) from what the source's events read already answers (google-calendar: `description`, `location`, `htmlLink`, `hangoutLink` and the video entry of `conferenceData`, `organizer`, `attendees` without rooms, the calendar's `summary` and time zone), no new call or scope; notes are cut to 8000 characters and attendees to 100; a link that is not http(s) is dropped. The factory links no calendar event to a work item today, so the panel shows no linked item. Tests: `tests/ui-calendar-page.test.tsx` (event details), `tests/calendar/calendar-events-api.test.ts`, `tests/calendar/google-calendar.test.ts`.

- **Calendar page: one toolbar line with Week | Month, ‹ Today ›, the period and a quiet Sync; a 7-column week that fits, a lined month grid, today on an ink dot, compact chips (decision 18 changed 2026-11-24, owner feedback "still ugly calendar design"; current; replaces the toolbar of text buttons, the period's place outside the toolbar's flow, the week that scrolled sideways, the bordered event cards and the accent-outlined today, see History)** (`web/src/views/calendar.tsx` with the grids in `web/src/views/calendar-grid.tsx`, `PAGES` entry `calendar`, icon CalendarDays, group `tasks`). **Toolbar** (`data-calendar-toolbar`, in the `PageToolbar`, one line that wraps only when narrow): the `SegmentedControl` Week / Month (Week on load); then a `ButtonRow` (4px gap) of a secondary icon Button ‹ named "Previous week"/"Previous month", a secondary Today, and an icon Button › named "Next week"/"Next month"; then the period ("Nov 23 – 29, 2026", "November 2026": the page's only h2, `CARD_TITLE`, `aria-live` polite); then, pushed to the end, Sync as a ghost icon Button (refresh icon, named "Sync", "Syncing…" with a turning icon while busy), shown once a calendar is connected. The Card holding the grid has no title and is named by the period. **Week**: Monday to Sunday as an `ol`, seven flexible columns (`xl:grid-cols-7`, since 2026-11-24 with the event details; was `lg`) split by 1px `border` lines, so at 1280px the week fits the card with no sideways scrollbar; below `xl` the days stack as a list split by lines (at 1024px beside the sidebar a column was 70px, so a long word in a title broke letter by letter). Each day's h3 (`SUB_TITLE`) is its short weekday and date number; today's number sits on a 24px filled circle in the ink colour (`bg-text-1`, `text-bg`: neutral, never accent, no outline; `data-today`). Events are compact chips on `surface-2` (no card or border inside the card): the colour strip, the time first ("all day" else, plus the source when several calendars are listed), then the title cut at 2 lines; the chip opens the event's details (decision above). **Month**: a Monday-first `role=table` grid of 7 flexible columns split by 1px lines, weekday heads, each cell the date number (today on the same ink dot), up to 3 one-line events with strip and time, then "+N more"; below `sm` an event shows only its strip (its text stays for screen readers); each event opens its details (decision above). The cells outside the month are empty. Each event's colour strip (`data-strip`) is one of the `kind-*` token colours by a stable hash of the source name. Previous and next move the period by one week or month; Today returns to the period holding today in the browser's time zone. Each day lists its events all-day first, then timed by time, read-only. Weeks start on Monday; there is no week-start setting.
  - **The route.** The page reads `GET /api/v1/calendar/events?from=YYYY-MM-DD&to=YYYY-MM-DD` (`src/ui/calendar-events-api.ts`) with the first and last day shown, inclusive (Month: the month's first and last day). For each date it answers the stored events that overlap that local day, bucketed in the server's time zone by the rule the Tasks views use (`calendarDays` in `src/core/tasks.ts`), a `synced` flag, and `calendar`, the sources' sync state (the list `GET /api/v1/tasks` answers). It answers 400 with a reason when `from` or `to` is not a `YYYY-MM-DD` date, `from` is later than `to`, or the range covers more than 62 days. It reads the stored copy only: changing the period calls no calendar source and writes nothing. No new table, column or migration.
  - **Not synced.** A day is synced only when every listed source has a successful read whose window covers the whole local day: its last scheduled sync's, `[synced_at − 1 day, synced_at + 30 days]` from `syncWindow` in `src/calendar/calendar-sync.ts` (the same function the sync asks its sources with), or one of its on-demand syncs' (`calendar_synced_ranges`; the Sync decision in [09-dashboard-tasks.md](09-dashboard-tasks.md), 2026-11-22). A source never synced makes every day not synced. A day that is not synced is shaded (`surface-2`, `data-not-synced`) and shows no text of its own, never an empty day; when any day of the period is not synced, one `info` Notice above the grid names those days in one sentence (runs of days as a range). A synced day with no events shows no text. The scheduled sync reaches one day back, so past days show not synced until the note's Sync these days or the toolbar's Sync reads them. Why: a period the stored copy does not cover must not look free.
  - **Stale and empty.** A source whose last sync failed shows the stale-sync notice (`data-calendar-stale`) with its last synced time, and its stored events stay listed. With no calendar in the read's `calendar` list the empty state links to Settings → Calendar (`/app/settings#calendar`, the Calendar section's id `calendar`). The old "Event" badge on each row is gone (every row there is an event).
