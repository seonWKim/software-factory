# 9. Status page: dashboard Calendar page

- **The Calendar shows schedules as agent entries, with an All / Human / Agent filter (decision added 2026-11-28, phase 1 of 2 of local-task-tk_00ebf1cf; current; replaces the page that showed only calendar and local events, see [History](history/09-dashboard-tasks-calendar.md)).** The decision that changed: **the read also answers each schedule run and next slot, and the toolbar filters them.**
  - **Read.** `GET /api/v1/calendar/events` adds entries with `kind` `agent` and source `agent`, titled with the schedule's title: each run (`listScheduleRuns`) on the day of its `occurrence_at`, and each unpaused schedule's `next_due_at` (`next` true) on its day. A paused schedule (`next_due_at` null) gives none. They come from the store at read time, load the schedule reads by dynamic import (`readScheduleSlots`), call no calendar source and store nothing. Human events keep `kind` `event`, their fields, colours and actions.
  - **Filter.** A second `SegmentedControl` in the toolbar, `All`, `Human`, `Agent` in that order, All on load. Human hides agent entries, Agent hides human events, in Week, Month and the compact month. View only: not a query parameter, not kept across reloads.
  - **Agent entry.** A chip with the time, a `Badge` (level `info`) "Agent" (its colour is the Badge's tone) and the title; the next slot adds "Next run". It opens the same details as any chip, with no Edit, no Delete and no event link. Strings are in `web/src/i18n/en/tasks.ts`. Tests: `tests/calendar-events-api.test.ts`, `tests/ui-calendar-page.test.tsx`.

- **The New event dialog ends with the Switch "Also add to Google Calendar"; an edited event shows its copy's last error (decision changed 2026-11-25, phase 3 of 3 of local-task-tk_dc8c579a; current; replaces the dialog that only saved here, see [History](history/09-dashboard-tasks-calendar.md)).** The decision that changed: **a new event can also be added to a connected calendar that takes writes, from the same dialog** (the copy itself is in [02-tasks-calendar.md](02-tasks-calendar.md)). `web/src/views/calendar-event-dialog.tsx` reads `copy` from the one-day read of its date (no new prop from `calendar.tsx`). With a calendar that has a sync port, the last Field is the shared `Switch` "Also add to <label>" ("Also add to Google Calendar" with the Google plugin): on by default when `copy.writable` (stored write access), else off and read-only with the Field's help "Reconnect Google Calendar with write access to add events there"; with none, no Switch. The fields above it, the order and the footer are unchanged. A save whose copy did not happen ("Saved here only: <reason>", or "Saved here, but the copy in <label> failed: <error>") keeps the dialog open on that line, the event already saved, and its button then closes it. An edited event whose copy failed shows above the button "The copy in <label> failed: <error>. The event is kept here; save it again to retry.": saving it again retries the copy. Tests: `tests/ui-calendar-event-dialog.test.tsx`, `tests/calendar/calendar-local-sync.test.ts`.

- **New event, Edit and Delete on the Calendar page; local events show with no calendar connected (decision changed 2026-11-25, phase 2 of 3 of local-task-tk_dc8c579a; current; replaces the read-only page and the empty state shown with no calendar connected, see [History](history/09-dashboard-tasks-calendar.md)).** The decision that changed: **the page adds, edits and deletes the owner's own events on the routes of [02-tasks-calendar.md](02-tasks-calendar.md), and shows them with no calendar connected.**
  - **Open.** A primary `New event` Button at the end of the toolbar's period row (after Sync) opens the shared `Dialog` for today at 09:00 to 10:00; a click on a day's empty area (Week and Month cells; not on an event, button or link) opens it for that day.   - **No calendar connected.** The grid shows the local events, no day is shaded as not synced, and an info Notice above it, "No calendar is connected." with the Settings link, replaces the empty state.

Weeks start on Monday; there is no week-start setting.
  - **The route.** The page reads `GET /api/v1/calendar/events?from=YYYY-MM-DD&to=YYYY-MM-DD` (`src/ui/calendar-events-api.ts`) with the first and last day shown, inclusive (Month: the Monday before its first day to the Sunday after its last, since 2026-11-24; was its first and last day). For each date it answers the stored events that overlap that local day, bucketed in the server's time zone by the rule the Tasks views use (`calendarDays` in `src/core/tasks.ts`), a `synced` flag, and `calendar`, the sources' sync state (the list `GET /api/v1/tasks` answers). It answers 400 with a reason when `from` or `to` is not a `YYYY-MM-DD` date, `from` is later than `to`, or the range covers more than 62 days. It reads the stored copy only: changing the period calls no calendar source and writes nothing. No new table, column or migration.
  - **Not synced.** A day is synced only when every listed source has a successful read whose window covers the whole local day: its last scheduled sync's, `[synced_at − 1 day, synced_at + 30 days]` from `syncWindow` in `src/calendar/calendar-sync.ts` (the same function the sync asks its sources with), or one of its on-demand syncs' (`calendar_synced_ranges`; the Sync decision in [09-dashboard-tasks.md](09-dashboard-tasks.md), 2026-11-22). A source never synced makes every day not synced. A day that is not synced is shaded (`surface-2`, `data-not-synced`) and shows no text of its own, never an empty day; when any day of the period is not synced, one `info` Notice above the grid names those days in one sentence (runs of days as a range). A synced day with no events shows no text. The scheduled sync reaches one day back, so past days show not synced until the note's Sync these days or the toolbar's Sync reads them. Why: a period the stored copy does not cover must not look free.
  - **Stale and empty.** A source whose last sync failed shows the stale-sync notice (`data-calendar-stale`) with its last synced time, and its stored events stay listed. With no calendar in the read's `calendar` list the empty state links to Settings → Calendar (`/app/settings#calendar`, the Calendar section's id `calendar`). The old "Event" badge on each row is gone (every row there is an event).
