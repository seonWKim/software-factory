# 9. Status page: dashboard Calendar page

- **Calendar page: one toolbar with the period title, a 7-column week, a month grid, today circled, quiet days (decision 18 changed 2026-11-20, owner feedback; current; replaces the Card-titled period, the per-day notes and the source on every event, see History)** (`web/src/views/calendar.tsx`, `PAGES` entry `calendar`, icon CalendarDays, group `tasks`). One toolbar row (`data-calendar-toolbar`) holds the period heading ("Nov 9 – 15, 2026" in Week, "November 2026" in Month; the page's only h2, section-title type, `aria-live` polite), a `SegmentedControl` Week / Month (Week on load), then a `ButtonRow` of secondary Buttons: previous, next and Today; no second control row. The Card holding the week or month has no title (the period names it for assistive tech). Today's date is circled in both views (an `accent` outline on the week day heading and the month cell number, `data-today`); no other day is. Each event has a colour strip (`data-strip`) in one of the `kind-*` token colours, chosen by a stable hash of the source name (no stored colour, no hex); an event names its source only when the read lists more than one calendar. Previous and next move the period by one week or month; Today returns to the period holding today in the browser's time zone. Week is the seven days Monday to Sunday as seven columns side by side in one row (an `ol` with `grid-cols-7`, each column keeping its `data-day`); on a narrow window the week scrolls sideways inside the card and the page does not (owner answer, 2026-11-20); Month is a Monday-first grid of the month, each cell listing up to 3 events and then "+N more", with the cells outside the month empty. Each day lists its events all-day first, then timed by time, each with its time or "all day", read-only. Weeks start on Monday; there is no week-start setting.
  - **The route.** The page reads `GET /api/v1/calendar/events?from=YYYY-MM-DD&to=YYYY-MM-DD` (`src/ui/calendar-events-api.ts`) with the first and last day shown, inclusive (Month: the month's first and last day). For each date it answers the stored events that overlap that local day, bucketed in the server's time zone by the rule the Tasks views use (`calendarDays` in `src/core/tasks.ts`), a `synced` flag, and `calendar`, the sources' sync state (the list `GET /api/v1/tasks` answers). It answers 400 with a reason when `from` or `to` is not a `YYYY-MM-DD` date, `from` is later than `to`, or the range covers more than 62 days. It reads the stored copy only: changing the period calls no calendar source and writes nothing. No new table, column or migration.
  - **Not synced.** A day is synced only when every listed source has a successful read whose window covers the whole local day: its last scheduled sync's, `[synced_at − 1 day, synced_at + 30 days]` from `syncWindow` in `src/calendar/calendar-sync.ts` (the same function the sync asks its sources with), or one of its on-demand syncs' (`calendar_synced_ranges`; the Sync decision in [09-dashboard-tasks.md](09-dashboard-tasks.md), 2026-11-22). A source never synced makes every day not synced. A day that is not synced is shaded (`surface-2`, `data-not-synced`) and shows no text of its own, never an empty day; when any day of the period is not synced, one `info` Notice above the grid names those days in one sentence (runs of days as a range). A synced day with no events shows no text. The scheduled sync reaches one day back, so past days show not synced until the note's Sync these days or the toolbar's Sync reads them. Why: a period the stored copy does not cover must not look free.
  - **Stale and empty.** A source whose last sync failed shows the stale-sync notice (`data-calendar-stale`) with its last synced time, and its stored events stay listed. With no calendar in the read's `calendar` list the empty state links to Settings → Calendar (`/app/settings#calendar`, the Calendar section's id `calendar`). The old "Event" badge on each row is gone (every row there is an event).
