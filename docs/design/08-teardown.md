# 8. Enterprise: teardown

- **Teardown copies the SQLite store out (decision changed 2026-11-11, issues #590 and #567; before: teardown skipped saving a shared store and printed database drop instructions, see History).** The store is SQLite only (`05-coordination.md`): teardown always copies the state folder's `db/` out before it goes, and neither its plan nor its hand-step list names another database or how to drop it. The old test-database URL file entry in `src/setup-paths.ts` stays, so a file left on an old machine is still described and denied to agents.
- **`factory teardown` undoes setup on this machine (new decision, 2026-11-11, issue #538; current).** `make teardown` runs `npm run factory -- teardown`; the documented flow to start over is pull → teardown → setup (`SET_UP.md`, `docs/setup.md`). Code: `src/teardown.ts`, the command in `src/cli/handlers/teardown/`.
  - **One list of what setup leaves.** `src/setup-paths.ts` names every top-level path the factory creates in the state folder, the worktree locations it makes (run folders `sbx_<8 hex>`, merge scratch folders and the empty hooks folder in `worktrees_dir`; version copies in `<state_dir>/versions/`) and its ref prefixes (`refs/factory/`, besides `branch_prefix` branches). Teardown reads it to describe each entry it removes; `tests/teardown.test.ts` runs the solo setup and fails when setup writes a path the list does not name. The writers outside setup's own code keep their constants; the list imports them where they are exported (host id, passport key, supervisor files, progress file, hooks folder).
  - **Decision 1, unfinished work: remove only what is safe, never force (owner's default).** Teardown removes the factory's own worktrees with no uncommitted changes (a version copy's own pid file does not count) and run folders that, in addition, hold no commit the repository lacks; `factory/*` branches already merged into the base branch (local or `origin/`) and not checked out in any remaining worktree; and `refs/factory/*` refs whose commit is merged the same way. It keeps and lists everything else: other folders in `worktrees_dir` (a person's own checkouts), dirty worktrees and run folders, unmerged branches and refs, branches checked out somewhere. Worktrees go through `git worktree remove` without `--force`, then `git worktree prune`; refs go through `git update-ref -d <ref> <old value>`. `removeWorktree` in the updater forces, so teardown does not reuse it. The state folder is removed around a kept worktree inside it.
  - **Refuse while running.** Teardown reads `<state_dir>/supervisor.json` (supervisor, claiming and draining children, unless it says `stopped`) and each version copy's pid file; any live pid makes a real run refuse with exit 1 and remove nothing. `--stop` reuses the `npm run migrate` drain handshake (`src/migrate-drain.ts`): the supervisor drains its children, and once drained teardown sends SIGTERM to it (before it reads the handshake's start request) and to any process left, then waits up to `run_timeout_ms` plus the drain margin. `--dry-run` never refuses: it lists what a real run would remove and notes the running factory.
  - **Confirmation.** A real run asks the person to type `teardown`; any other answer exits 1 with nothing removed. `--yes` skips that question only. `--secrets` always asks its own (`secrets`), also under `--yes`, because the secret file is outside the factory's folders and its values cannot be recovered.
  - **Stores.** Solo default (SQLite, one machine): before the state folder goes, its `db/` folder (`factory.db` and migration backups) is copied to `backups/teardown-<time>/` in the secret file's folder, and the path printed. That folder is outside the repository and already denied to agents (G3), so the copy is never readable by a run, unlike a copy in the checkout. After `make setup` the factory starts empty. (Changed 2026-11-11: the store is SQLite only; see the decision above.)
  - **Never removed; printed as hand steps.** `factory.config.json` (setup's edits stay; undo with git), the secret file (unless `--secrets`, which removes only the template's keys and every name a plugin declares, keeps every other line and leaves mode 600), `github-app.pem`, GitHub issues and pull requests, the GitHub App and the Slack app.
  - **Idempotent.** A second run finds nothing the factory made, prints that there is nothing to delete and exits 0.
