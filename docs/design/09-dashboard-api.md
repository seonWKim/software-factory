# 9. Status page: dashboard JSON API, serving and checks

Split from [09-dashboard-shell.md](09-dashboard-shell.md) (2026-11-21, moved text, no decision changed).

- **The app is the only UI: the server-rendered classic page is removed (decision changed 2026-11-16, phase 4 of 4 of local-task-tk_3164aaa9-e569-4086-9e6d-013b63474c69-phase-2; current; replaces "the server-rendered page moved to `/classic` and stays until the app covers everything it shows" of the app-is-the-default decision, "`/classic` keeps its GitHub API section" of the GitHub budget tab decision and "the `/classic` Health panel shows a Run now button" of the Run now decision, see History).** The decision that changed: **`GET /classic` and `GET /items/<id>` answer the 404 page; `/` still answers 302 to `/app/`.** `src/ui/html.ts` is only the error page shell, with no script. The JSON API, `/api/health` and the app are unchanged. The deleted files, the error page and its CSP are listed in History.

- **`server_rev` is the build stamp in dist/ (decision changed 2026-11-13; current; replaces "server revision = folder git HEAD", see History).** The decision that changed: `/api/v1/overview`'s `server_rev` is the revision the UI server's build was made from, the stamp `npm run build` writes into `dist/revision` ([08-self-update.md](08-self-update.md)), not its code root's git HEAD; null without a stamp, and then no banner. The page's `WEB_REV` is the same build's HEAD, so a docs-only update (checkout moved, nothing rebuilt) shows no banner, a page older than its server still gets "Dashboard out of date: it was built from …, the server runs …" with "reload / restart `factory ui`", and a reload clears it. The "UI server and factory differ" action is unchanged.

- **Responsive check (new decision, 2026-11-10; current).** The decision that changed: **the layout at other window sizes is checked by a script on every change**, not only by hand. `npm run check:responsive` (`scripts/responsive-check.mjs`) builds, seeds a throwaway SQLite store with layout-stressing items (`scripts/responsive/fixture.mjs`), serves it with the real UI server on a free port, and opens every sidebar page (read from `web/src/pages.ts`), an item page, a parent with phases and a transcript in the system's headless Chrome over the DevTools protocol (`scripts/responsive/cdp.mjs`; no Playwright, no new dependency; a slow launch is retried, see History) at 1280×800, 1024×768, 768×1024, 390×844 and 390×560, in light and dark, with every `<details>` open. It fails on the rules in `scripts/responsive/rules.mjs` (sideways scroll, overflow past the right edge, words broken in a narrow box, a fixed element covering the page, an open overlay past the viewport, hidden vertical overflow) and on any console error, failed request or 4xx/5xx response (the full list is in History). One line per failure (page, size, theme, rule or `console` and the message, CSS selector) and a screenshot with the failing elements outlined under `.playwright-mcp/responsive/` (git ignored). CI and the merge queue run it (the CI and merge-queue details are in History). It is a local development check, not a factory feature.

- **Dashboard app and read API (new decision, 2026-11-02, issue #124; steps 1 and 2 of the dashboard plan).** The status UI moves to a client app. **Stack:** Vite, React, TypeScript, Tailwind, shadcn/ui (components copied into `web/` as plain files, not a dependency), lucide icons and TanStack Query; the system font stack, nothing from a CDN. The app lives in `web/`, `npm run build` builds the app into `web/dist/` (git-ignored) after the server, through a staging folder swapped in at the end (`08-self-update.md`), so `/app/` serves the shell (it answers 503 only when the app is not built), and `isCodePath` counts `web/` as code so the updater rebuilds on a change there. Once the server-rendered pages are retired (step 6, `src/ui/html.ts` and `src/ui/pages.ts`), the app supersedes them; until step 3 it is served at `/app/` and the old pages stay at `/` and `/items/<id>` unchanged (same HTML, same CSP).
  - **JSON API** (`src/ui/api.ts`), `GET`/`HEAD` on every route, plus five writes, `POST /api/v1/settings`, `POST /api/v1/items/:id/commands`, `POST /api/v1/pauses/resume`, `POST /api/v1/standing` and `POST /api/v1/improve/run` (below); the same Host guard, `cache-control: no-store` and security headers as the page, errors as JSON `{ error }` (404 for an unknown path or item id, 400 for an unknown filter value): `/api/v1/overview` (items per stage, human-blocked count, running and queued run counts, runs succeeded and failed and tokens in the last 24 h: the page's numbers), `/api/v1/items` (the page's ranked list with the same filters `state`, `stage`, `tier`, `kind`, `unblocks`, `closed`, `q`, plus the facet counts; the ranking moved to `src/ui/list.ts` so the page and the API share it), `/api/v1/items/:id` (facts, timeline, runs; each run has an `attempts` array, see below), `/api/v1/runs` (running then queued runs: kind, item id, attempt, owner, last heartbeat, start, lease expiry; never the fencing token), `/api/v1/queue` (queued runs, oldest first), `/api/v1/settings` (the Settings page's read model and the per-process CSRF token; see `08-settings.md`), `/api/v1/workers` (`workers`: each current lease owner once, by ID, with its running count; history is step 5. `processes`, since 2026-11-07: one entry per live worker process, see below) and `/api/v1/health` (the same `HealthMonitor.report` as `/api/health`, which keeps its response). Every free-text value (titles, blocked reasons, state-change values and reasons, actor and owner ids, run errors) passes through the `Withholder` as plain text or `[withheld: <rule>]`. The API calls only store read methods; no store method, interface, migration or schema changed. Orphaned-run rules (heartbeat older than 2 × `heartbeat_ms`, or lease expired) belong to the floor view (step 3), which applies them to the raw owner, heartbeat and lease expiry returned here.

- **Revisions, system actions and the tab title (decision changed 2026-11-07, issue #311; current).** **Revisions:** `/api/v1/overview` adds `server_rev`, the git revision the UI server runs (since 2026-11-13 the build stamp in `dist/`, see the first decision; before, `git rev-parse HEAD` of its code root, read once at start; null when git cannot say), beside `factory.rev`, which stays the supervisor's. The app has its own revision built in through Vite `define` (`__FACTORY_REV__` from `git rev-parse HEAD` at build time, `web/vite.config.ts`; `WEB_REV` in `web/src/api.ts`, null in tests) and sends it on each overview poll as `?rev=`. When both are known and differ, a banner under the top bar says "Dashboard out of date: reload / restart `factory ui`" (`web/src/views/system-banner.tsx`); equal or unknown revisions show none. It says only that they differ, never which is newer. Under `git-worktree` the supervisor restarts the page on each new revision ([08-self-update.md](08-self-update.md)). **System actions:** the overview adds `system_actions` and counts them in `needs_you` ([09-status-page.md](09-status-page.md)); the Floor lists them at the top of Needs you, each with its command. **Tab title:** `(N) <page> · software-factory` with N the overview's `needs_you`, no prefix at 0. **Health:** ok rows fold behind their count ([09-health.md](09-health.md)). No store method, schema or migration changed.
