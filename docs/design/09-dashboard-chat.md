# 9. Status page: dashboard chat (side panel and Runners Chat Card)

- **The dashboard has a chat side panel, opened by a Chat button in the top bar, and the Runners tab has a Chat Card (decision added 2026-11-26, local-task-tk_eea9af6d phase 2 of 2; current; replaces none).** Phase 1 declared `chat.send`, `chat.transcript` and `chat.turns` on the API registry ([04-chat-agent.md](04-chat-agent.md), [09-api-registry.md](09-api-registry.md)); this phase is their dashboard. Both parts call the generated typed client (`web/src/api/generated.ts`: `chatSend`, `chatTurns`, `chatTranscript`, `itemsList`) and nothing else: no hand-written `fetch`, no new route (`tests/ui-chat-panel.test.tsx` reads the source for both). The panel only answers: it creates no item and runs no command. Code: `web/src/views/chat-panel.tsx`, texts in `web/src/i18n/en/chat.ts` (key prefix `chat.`).

- **Layout (owner answer 1, the default accepted).** `ChatPanel` is an `aside` beside the page in the app's flex row, not a modal: the current page stays visible and keeps its place behind it (below `lg` it floats over the page's right edge). Inside, a `PageHeader` (title Chat, a close icon Button), then one `Card` (the page's Card) holding the conversation (`Clamp` paragraphs), a `Textarea` and the primary `Button` Send (⌘/Ctrl+Enter sends too). The Chat button is a ghost icon Button before Refresh's More menu ([09-dashboard-shell.md](09-dashboard-shell.md)); it toggles the panel (`aria-pressed`). The panel stays mounted while closed, so closing it keeps the conversation and its session.

- **Each message carries the open page and item (owner answer 1 of the spec: "What is this?" is about the open item).** `chat.send` takes only `text` and `session_id`, so the panel puts one context line before the message: "Open page: Work." and, on an item page, "Open item: “<title>”, state <state label>, stage <stage>." The title, state and stage are the item's row in the stored items list (`itemsList`, read once per 10 s at send), so the turn can answer "What is this?" about the open item and about nothing else of it. A shown transcript takes the line off again. The model is the Ask model; with none set (`chat.send` answers 503) the panel says chat is off and where to add a model.

- **A reply is plain words, and a code block or a table sits in a Card.** `replyParts` splits a reply into paragraphs (each a `Clamp`), fenced code blocks and pipe tables. A code block (a diff) has no shared component in `design-system/components.md`; until one is added it is a `Card` holding `<pre>` text in `font-mono text-xs`. A table is a `Card` holding a `DataTable`. No Markdown component and no new component is used.

- **The Runners tab's Chat Card shows the chat's autonomous work (design-system `patterns.md`, "Autonomous work is visible").** `ChatCard` (in `RunnersTab`, [09-dashboard-runners.md](09-dashboard-runners.md)) reads `chat.turns` (10, polled every 3 s while visible): the current activity ("Answering 2 questions now." or none), then a table of recent turns with when, outcome (Answered, Held back, Failed, Answering: one `Badge`), the reason in plain words (never the stored code) and a Transcript Button that opens that turn's stored messages (`chat.transcript`) in a `ModalPanel`. No turn, session or item ID shows anywhere on the panel, the Card or the dialog.
