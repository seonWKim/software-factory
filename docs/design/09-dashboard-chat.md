# 9. Status page: dashboard chat (the Chat page and the Runners Chat Card)

- **Every reply, your own message and every fenced code block has a Copy icon Button, and "Copied" is announced (decision added 2026-11-27, schedule chat-vs-top-llm-apps-review; current; replaces none, nothing offered Copy).** A reply ends with a `ButtonRow` holding a Copy icon Button named "Copy reply" that writes the reply's stored text, on the Chat page and in the Runners transcript dialog; each of your messages on the page has "Copy your message", which writes what you typed without the context line; each fenced code block, in a reply and in the shared `Markdown` component (so on the item, thread and rules pages too), has "Copy code" under it that writes the code without its fence lines. All are one `CopyIcon` (`web/src/components/ui/copy.tsx`: a ghost, `icon` Button with the lucide Copy icon over `copyToClipboard`); after a copy "Copied" shows beside it for 1.5 s in an always-present `aria-live="polite"` element, and with no clipboard nothing shows and the text stays selectable. Send stays the page's one primary Button. Copy runs in the browser only: no fetch, no route. Edit and resend of your last message was offered and not built (owner answer: Copy only). Tests: `tests/ui-copy.test.tsx`, `tests/ui-chat.test.tsx`.

- **Chat is a page of its own, in the sidebar, laid out as one centred conversation column (decision changed 2026-11-27, owner design feedback: "Chat should be extracted as a menu + it should resemble chat GPT UI … for slickness"; current; replaces the side panel and its Chat button in the top bar, see History).** `PAGES` (`web/src/pages.ts`) has `chat` (label Chat, icon MessageSquare, group `tasks`) first in the sidebar, above Tasks (since 2026-11-27, [09-dashboard-shell.md](09-dashboard-shell.md)), so `/app/chat` routes to `ChatPage` (`web/src/views/chat-page.tsx`); the top bar has no Chat button and there is no side panel, so the page is the one chat surface ([09-dashboard-shell.md](09-dashboard-shell.md)). The page calls the generated typed client (`web/src/api/generated.ts`: `chatSend`, `itemsList`) and nothing else: no hand-written `fetch`, no new route (`tests/ui-chat.test.tsx` reads the source). It only answers: it creates no item and runs no command. Texts in `web/src/i18n/en/chat.ts` (key prefix `chat.`). Only the layout pattern follows the familiar chat apps; no other product's name, mark or words.

- **Layout.** The page marks itself `data-page-fill`, and `<main>` (`web/src/App.tsx`) then grows to the content column's height, so the page is window-high. Inside, one column centred in the page, at most 48rem (768px) wide (`max-w-[48rem]`: a reading column inside the page, like a prose width, not a page width; `<main>` stays `--page-wide`): the `PageHeader` (h1 Chat), the conversation, the composer. Your message is a right-aligned `surface-2` bubble (`rounded-card`, at most 85% of the column, kept as written in `[data-raw]`); a reply is plain left-aligned text with no bubble. Messages are 32px apart. While the chat answers, three dots that pulse (still with reduced motion) sit in the reply's place, a `role=status` read as "Answering…".

- **Composer.** A `Textarea` (`rounded-card`, `shadow-sm`) starts one line high and grows with its text up to 8 lines, then scrolls; the send icon Button (primary, round, arrow up, named Send) sits inside its right edge, disabled while the text is empty or an answer is on its way (you can type the next message meanwhile). Enter sends; Shift+Enter makes a new line; an Enter that ends an input method's composition (Korean, Japanese) does neither. A one-line hint under it says so. The composer is `sticky` at the bottom of the scrolling content column, on the page colour faded in above it, with the safe-area inset below it, so it stays in view while the conversation scrolls.

- **Empty page and scrolling.** With nothing asked, a short greeting and four example questions in plain words (What needs me today?, and three more) as round secondary Buttons; a click puts the question in the composer and focuses it, and sends nothing. The column follows each new message and the answering mark to the end, unless you scrolled up more than 80px from it.

- **A failed send reads as the chat's turn, at the left (decision changed 2026-11-27, owner screenshot at 767px: the red error sat right-aligned under the bubble and the column ran past the right edge; current; replaces "errors sit under the failed message", see History).** A send that fails (chat off with no model: "Add one in Plugins, then try again"; a refused or failed turn, its reason in plain words; a lost connection) adds a `data-from="chat"` row where the answer would be: its words in the `failed` colour (the danger token, as the `danger` Button; `role=alert`) and a Try again Button beside them that sends the same message again in its place, so it never shows twice. The words break anywhere (`wrap-anywhere`, `min-w-0`: an error can hold one long request id or path), and Try again wraps under them when the row runs out of room. Every level of the column (`data-page-fill`, the list, each row) is `min-w-0`, so nothing in a turn widens the column: it fits 320 to 1920px with the 16px gutter. Tests: `tests/ui-chat.test.tsx` (the row's place), `npm run check:responsive`'s `chat-error` page (no horizontal overflow at every viewport).

- **The conversation outlives the page, not a reload.** It is kept in the query cache (key `chat`/`conversation`, never refetched, never collected): going to another page and back keeps the messages and the session (`chat.send` continues it with `session_id`), and an answer that comes while the page is away still lands. A reload starts a new conversation, as the side panel did.

- **An optional item context.** `/app/chat?item=<id>` names one item: each message then starts with "About item: “<title>”, state <state label>, stage <stage>." from the stored items list (`itemsList`, read once per 10 s at send), so "What is this?" is about that item. Without it the message is sent as typed. Nothing links there yet. A shown transcript takes the line (or an older "Open page: …" line) off again.

- **A reply is readable markdown.** `replyParts` splits a reply; its paragraphs, lists and fenced code blocks render through the shared `Markdown` component (code in its `surface-2` mono block, scrolling sideways inside the column), a pipe table as a `DataTable` (cards below `sm`).

- **The Runners tab's Chat Card shows the chat's autonomous work (design-system `patterns.md`, "Autonomous work is visible").** `ChatCard` (`web/src/views/chat-card.tsx`, in `RunnersTab`, [09-dashboard-runners.md](09-dashboard-runners.md)) reads `chat.turns` (10, polled every 3 s while visible): the current activity ("Answering 2 questions now." or none), then a table of recent turns with when, outcome (Answered, Held back, Failed, Answering: one `Badge`), the reason in plain words (never the stored code) and a Transcript Button that opens that turn's stored messages (`chat.transcript`) in a `ModalPanel`. No turn, session or item ID shows anywhere on the panel, the Card or the dialog.
