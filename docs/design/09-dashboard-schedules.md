- **The Schedules page lists schedules with a Switch and a row menu, shows the selected one's runs, and creates or edits one in a Dialog (decision added 2026-11-24, local-task-tk_0ae5a8e9 phase 2 of 2, wi_85d730fa1f614affaa897cbd9cbe6aa0; current; replaces none).** `web/src/views/schedules.tsx` (the form in `web/src/views/schedules/form.tsx`, the catalog keys of each word in `schedules/labels.ts`), route `/app/schedules`, `PAGES` entry `schedules` (icon CalendarClock, group `tasks`, after Calendar), text in `web/src/i18n/en/schedules.ts`.   - **Schedules Card.** A `DataTable` (`GET /api/v1/schedules`, polled like the other pages; the schedule's title leads each row) with the columns Schedule, Repeats (plain words, see the first decision), Next run (local time; "Paused" for a paused schedule), State (a Badge: Paused, Running, Waiting), Does and On, then a "⋯" `OverflowMenu`. No raw ID is shown anywhere: the table has no ID column, and the page makes a new schedule's ID from its title (lower-case words joined by `-`, a number after it when taken), never shown.
  - **Runs Card.** Titled "Runs of <title>" for the selected schedule, else "Runs" with "Select a schedule to see its runs." A `DataTable` of the rows of `GET /api/v1/schedules/runs?schedule=<id>` (read only while a schedule is selected), newest first, with Started (the run's `occurrence_at`, the slot it was due for, not the time it was claimed), Result (Ran, Skipped: still running, Skipped: factory busy, Held: waiting for your approval, Rejected), Cost (USD) and Output (read for people, see the Output decision above); a column empty in every row is left out, as `DataTable` does.
  - **New schedule and Edit.** One `Dialog` (`ScheduleDialog`), built from `Field`, `Input`, `Select`, `Textarea`, `Switch` and the Dialog's `ButtonRow`, so a row's input opens a modal and never changes the row's height. Fields as the CLI's flags: Title, Repeats (interval, daily, weekly, cron), When (the cadence's spec, with a help line per kind), Time zone (the browser's zone to begin with), Does (build, agent, feedback: owner answer 2; Check a page too on New, see the decision above), Text (the build's description, or the agent's and feedback's prompt), If the factory was off or busy at the time (a `Select`, see the missed-time decision above), Run now too (New only) and Token limit (a number; blank means the default and is left out). New posts `/add` with every field. Edit posts `/edit` with only the fields the owner changed (so an unchanged cadence does not move the next run), a changed kind always with its text, and closes with no request when nothing changed. A refusal stays in the Dialog with its reason. Delete: see the delete decision above.
