# 9. Status page: dashboard Rules page, standing rules

- **A standing rule is turned on, paused, edited and removed in a dialog (decision changed 2026-11-22, wi_5c1c03d0, "Rules page: add, edit, pause and remove rules"; current; replaces "the rule's Switch writes on or off at once", see History).** A standing rule's row (`standing.tsx` `StandingRule`: In effect, under Details, and the ledger-off card) keeps its Switch and gains a ⋯ menu: Turn on (Pause when on), Edit, and Remove (its `danger` item, off for a rule with no stored row). The Switch and each item open the shared `Dialog` (rendered into `document.body`, so the row's height never changes); nothing is sent before its confirm. Turn on and Pause show the rule's `Switch` set to the state to save; Edit a `Field` and a number `Input` for the threshold ("Approvals in a row before the factory suggests a rule", a whole number from 1); Remove only its consequence. The footer is the Dialog's `ButtonRow`: Cancel (secondary), then the confirm last (primary; `danger` for Remove). Before the confirm each dialog lists "Waiting items this rule covers" by title (no ID), from `waiting` of `GET /api/v1/standing`, when the change leaves the rule on; else "none". A refusal (the server's text names the missing permission) stays in the dialog. The confirm exists only while its dialog is open, so the page keeps one primary action in view. Writes and the change record: `05-standing-approvals.md`. **Not built:** a history view of the change records. **Why:** the owner asked to manage rules on the page (2026-11-20).

Approve, hold, or reject them here." A standing rule shows one sentence ("Approves tier 1 plans for you", also its Switch's name) and on or off; its ID, gate, tier, threshold, setter and dates sit in a Details (`RawDetails`). No rule ID, provider ID, ISO time or kind shows outside Details.
