Text gets 6px above it and keeps it when it wraps, so a control in another cell stays level with the first line of a multi-line title; a cell holding a 32px button starts it at the top, a 28px one (small Button, `IdDetails`) 2px down, a Switch (24px) 4px down (`:has()` on the cell's content). It applies to every `Table`: Schedules, Routines, the item page's Runs, Data, Work's list and Running now. The DataTable select button is 32px, the cell's whole first line. Below `sm`, a card's column name is centred on its value (`items-center` on the card's list), so "On" sits level with its Switch and "More" with its "⋯". `IdDetails` (a worker or person name) takes the surrounding text size instead of `text-sm`, so "worker 10" matches its row's meta. The chevron's 32px column before the badge shows only when some top-level row can expand (nested rows keep it). Tests: `tests/ui-table.test.tsx`, `tests/ui-tree.test.tsx`, `tests/web-ui-components.test.tsx`.
- **A DataTable card keeps long values inside the card: value cells shrink and wrap anywhere, ID links are cut (decision changed 2026-11-24, owner UI review of the Data page at 390 px; current; replaces the card cell's `break-words`, see History).** Below `sm` every card cell (`Td` in a card, `CARD_CELL` in `web/src/components/ui/parts.tsx`) is `min-w-0 wrap-anywhere`, and the card title is `wrap-anywhere`: prose wraps at any character when a word is longer than the line, and an inline-block link is no wider than its longest piece. A column's `break-words` is dropped in a card, like its width classes and `whitespace-nowrap`, so it cannot undo `wrap-anywhere`. At `sm` and up the table's cells are unchanged. Of the DataTable pages at 390 px only the Data page changed: its `work_item_id` and run ID links (`CellView` in `web/src/views/data.tsx`, also the Ask result) ran past the card's right edge and are now cut; Work, Tasks, Schedules, Routines, Rules, the Plugins and Health tabs lay out the same. Test: `tests/ui-table.test.tsx`.

- **A shared Toast for a short notice that goes by itself (new decision, 2026-11-24, owner design review #78; current; replaces none).** `Toast` (`web/src/components/ui/toast.tsx`; design-system/components.md "Toast"): a surface box with the box radius and `shadow-lg`, fixed at the top right under the top bar, its content beside a Dismiss Button; `role="status"`; it fades out after `TOAST_MS` (6 s), waits while hovered or focused, and closes at once on Dismiss. - **Every control is at least 24x24px (decision changed 2026-11-22, issue #763; current; replaces "Switch is a 20 by 36px button", "a Disclosure summary and a Copy button are one text line high" and "a Tooltip is above or below its trigger", see History).** The responsive check fails a painted button, link, input, select, textarea, summary or `role` button, menuitem, checkbox, radio, switch or tab under 24x24 CSS px (rule `small-target`, `LIMITS.minTarget` in `scripts/responsive/rules.mjs`), links inside running text included. So: `Switch` is a 24px tall button holding the drawn 20 by 36px track; the `Disclosure` summary, `CopyButton` and `IdDetails` are at least 24px (`min-h-6`, and `min-w-6` for the buttons); `LINK_CLASS`, `ID_CLASS` and `BANNER_LINK_CLASS` are `inline-block min-h-6`, and a link that must be a block (a one-line title cut with an ellipsis) takes the new `BLOCK_LINK_CLASS`, because `inline-block` would win over its `block`. `Tooltip` gains `placement="beside"`: level with the trigger's top, to its right (`start`) or left (`end`), for a trigger inside a scroller that would clip a bubble above it.

- **Dashboard pages follow written guides (new decision, 2026-11-12; current).** The decision that changed: **how a page is laid out, worded and checked is written down** in `design-system/patterns.md` (layout, list rows, actions, confirmations, status, loading, empty and error states, forms and keyboard), `design-system/writing.md` (sentence case, the next step, no raw IDs, no command as the main text, compact times, `t()`) and `design-system/dx.md` (build steps, each check with its test and npm script, a PR checklist for UI changes; `AGENTS.md` points to it). Existing pages move onto the components in follow-up issues, the Needs you redesign (wi_fc2c) first. No page, route or component changed. **Why:** the rules lived in the heads of earlier changes and in single tests.

- **The English catalog barrel is generated (decision changed 2026-11-18, issue #694; current; replaces the hand-written import list and spread line in `web/src/i18n/en.ts`, see History).** The decision that changed: **`web/src/i18n/en.ts` is written by `npm run i18n:catalog` (`scripts/i18n-catalog.ts`) from the area files in `web/src/i18n/en/`, never by hand.** It holds one import per area file, one spread per area in file-name order, and the `MessageKey` type; each area file exports one `export const <name> = { ... }`. A change that adds an area file runs the script instead of editing a shared line, so two such items no longer conflict on it (the improve run counted 2 conflict runs and 12 held items on the file in 7 days). `tests/web-i18n-keys.test.ts` fails when the checked-in barrel differs from the script's output. Keys and English text are unchanged; the large area files (settings, work, health) stay whole until conflicts on them continue (owner decision 2). The script is a local development step, not a factory feature. Triage's i18n companion rule adds the barrel beside each area file (design 04-triage).

- **New UI text goes through `t()` (decision changed 2026-11-13; current; replaces "the remaining views keep their English inline until follow-ups move them", see History).** The decision that changed: **every text the dashboard shows is read with `t()` from `web/src/i18n/en.ts`, so a new view or change adds its keys there and never an inline English string.** This covers JSX text, the `aria-label`, `title` and `placeholder` attributes, and English held in constants and props (dialog titles, consequences, field, option and filter labels, step-kind and state labels). The five views that were left (`item-commands.tsx`, `item-decisions.tsx`, `rules.tsx`, `transcript.tsx`, `tree.tsx`) now read their text through the catalog. A value the server receives stays as it is sent (command names, verdict kinds and severities, reject reasons, spec section headings, the `N: <answer>` lines); only its shown label is a key. Relative times stay compact (`12s`, `4m`, `3h`, `2d`): the unit letters come from the `unit.*` keys. `tests/web-i18n-text.test.ts` covers all of `web/src` with no baseline: it reads JSX text and the three attributes, and does not check JavaScript string literals, so English in constants is held by review.

- **App shell text through a catalog (decision changed 2026-11-12; current; replaces "the catalog holds the app shell's text only", see History).** The decision that changed: **the text of the app shell and of the Pages, Settings, Standing approvals, Tasks and Data views is no longer inline strings.** `web/src/i18n/en.ts` holds the English text of the sidebar, top bar, Refresh, theme control, the Needs you heading and these views (`web/src/views/pages.tsx`, `settings.tsx`, `standing.tsx`, `tasks.tsx`, `data.tsx`), keyed by name, a sentence with values as one key with `{name}` placeholders; `t(key)` in `web/src/i18n/index.ts` reads it, with no i18n library. The active locale is the first language in `navigator.languages` that has a catalog (`fr-FR` matches `fr`), English when none does; a key missing in the active catalog shows its English text. Nothing is stored: no config key, store column or per-person setting. `main.tsx` sets `<html lang>` to the active locale, and `web/src/lib/format.ts` passes it to every `Intl` call. Only English ships. **Add a locale:** one catalog file `web/src/i18n/<tag>.ts` with the same keys as `en.ts` (`tests/web-i18n.test.tsx` fails otherwise) and one registration line in `CATALOGS` in `web/src/i18n/index.ts`.
