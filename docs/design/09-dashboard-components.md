# 9. Status page: dashboard shared components and text

Split from [09-dashboard-shell.md](09-dashboard-shell.md) (2026-11-21, moved text, no decision changed).

- **The shared page pieces are PageHeader, Card, CardSection, EmptyState and one pill Badge, and `ListRow` for list rows (decision changed 2026-11-19, wi_de565ffb, `ListRow` added 2026-11-20, wi_a2e1243f; current; replaces `Section`, the square `Badge`, `StatusBadge`, `Empty` and the `text-lg` title, see History).** `PageHeader`'s h1 is `text-xl` semibold, primary action last; `Card` is `surface`, 1px `border`, `card` radius, 24 px padding, `shadow-sm`; every empty list is an `EmptyState`; list rows are a `ListRow` (09-dashboard-tasks). Details: `design-system/components.md`.

- **One shared Disclosure draws every show/hide section (decision changed 2026-11-18, issue "Shared disclosure component"; current; replaces the per-page raw `<details>` blocks, see History).** `Disclosure` (`web/src/components/ui/disclosure.tsx`) renders one native `<details>` with a `<summary>` that has one chevron marker (turned down when open) and one label style (`text-xs text-text-2`, no box). The open state is held in React so `aria-expanded` on the summary and the `open` attribute agree; click, Enter and Space toggle it. `defaultOpen` keeps each call site's start state, `lazy` mounts the body only while open (the Rules card's "Why and where" reads its detail on first open, never on page load), and `data-*` props pass through to the `<details>` (`data-how`, `data-decided`, `data-retired`, `data-ids`, `data-alarm-full`, `data-details`, `data-testid="ok-checks"`). `web/src/views/` and the Markdown fold use it and write no raw `<details>`. Use it only for long content (decision rule 2 in `design-system/patterns.md`).

- **A readable name shows its full ID in a tooltip and copies it on click, with no disclosure (decision changed 2026-11-15; current; replaces the "IdDetails opens to the full ID and a Copy button" rule of the readable-names decision, see History).** `IdDetails` (`web/src/components/ui/copy.tsx`) is a button showing only the label ("worker 2", "you"), wrapped in the shared `Tooltip` that holds the full ID on hover and focus; a click copies the ID and shows "Copied" for 1.5 s in place of the label, so a row never grows. It shares its copy helper with `CopyButton`. Callers and props are unchanged.

- **Each page renders its own `PageHeader`; the app shell draws no title (decision changed 2026-11-14; current; replaces "the app shell draws an h1 with the page name on every page except Needs you", see History).** Every sidebar page, the item page (the item's title) and the transcript page (the run's title) start with `PageHeader`, so each has exactly one h1 (a test in `tests/ui-shell.test.tsx` counts them). Rules keeps its description in that header, under the title "Rules". Runners shows the factory state (`FactoryBanner`) as a `Notice` of the matching tone, keeps `data-testid="factory-banner"`, and stacks its blocks in a `flex flex-col gap-6` column; the page has no banner tone classes of its own.

- **Every action opens the shared Dialog; sentence-case rows; token classes only (decision changed 2026-11-13, UI review; current; replaces "the item page's approve is an inline confirm and its verdict is three buttons with a severity choice", "the dialog's title names the item's ID" and "a Needs-you row's buttons are lowercase command names in the Why column", see History).** **Item page:** approve in the four approve phases (spec gate, revision limit, floor block, Rule of Two) opens `ApproveDialog` (`web/src/views/item-decisions.tsx`): each question with its answer, an optional note (it starts as the page's note box text), the Next line, then Cancel on the left and Approve on the right; focus moves into it. Verdict opens `VerdictDialog` (`item-commands.tsx`): an Accept, Changes or Reject choice, a severity select and a reason field; the reason is required for Changes and Reject and not for Accept; the usage text is no placeholder anywhere (`VERDICT_PLACEHOLDER` is removed). The item page keeps the note box for the other commands and the one-tap Good, Bad and Feedback beside the Verdict button. No inline approve confirm or verdict form remains; reject, revise, verdict and approve all use the one `Dialog`. Approve outside those phases still sends at once. **Dialog:** the title is the action and the item's title (`Reject Spec waiting`), one truncated line with the full text in its tooltip; the item's ID shows only when the item has no title. The confirm is filled with the accent (`Button` primary), the reject confirm with the failed token, Cancel stays an outline. The dialog, the row menu and the toast use token utilities only, never a palette class or `rounded-md` (the classes and spacing are in History). **Row:** a Needs-you row's Actions column (`NeedActions`, the Needs you page decision below) keeps its one primary button first, then the "⋯" menu; every cell of the row is vertically centred, and the reject, revise and verdict dialogs it opens are titled with the item's title. Labels are sentence case (Approve, Merge, Retry, Revise, Reject, Verdict) in the row, the menu and the item page. The Merge button's behaviour is unchanged (no confirm dialog). No route, store, command or controller change.

- **Dashboard pages follow written guides (new decision, 2026-11-12; current).** The decision that changed: **how a page is laid out, worded and checked is written down** in `design-system/patterns.md` (layout, list rows, actions, confirmations, status, loading, empty and error states, forms and keyboard), `design-system/writing.md` (sentence case, the next step, no raw IDs, no command as the main text, compact times, `t()`) and `design-system/dx.md` (build steps, each check with its test and npm script, a PR checklist for UI changes; `AGENTS.md` points to it). It changes no earlier decision: it names the rules of the decisions above (readable names, the catalog) and the tests that enforce them. The raw-controls test (wi_5b2b) is the one check, with no ratchet list or allow-list of existing raw controls. Existing pages move onto the components in follow-up issues, the Needs you redesign (wi_fc2c) first. No page, route or component changed. **Why:** the rules lived in the heads of earlier changes and in single tests.

- **Pages show plain words, one relative time and raw fields behind Details (decision changed 2026-11-19, "Plain words instead of internal names"; current; replaces four relative-time shapes and raw names in page text, see History).** A page never prints a stored code (`blocked_on`, `agent_needs_human`, `approve_spec`, `token_cost` and the like) as text: `termLabel` (`lib/format.ts`) gives its catalog label (`term.*` in `i18n/en/shell.ts`; `blocked_on` is "Waiting on"), else the code with spaces. A stored field a developer may want sits in `RawDetails` (`views/common.tsx`), a `Disclosure` marked `data-raw` and labelled "Details". Status words: "Done", "Closed", "Succeeded", "Merged without review". `relativeTime` is the only relative time: "just now" under a minute, then "4m ago", "3h ago", "in 4m"; `When` puts the exact time in `title`. `⌘K` lists the Data page, which keeps its raw names, as a "Developer page". `tests/web-plain-words.test.tsx` fails on `/\b[a-z]+_[a-z_]+\b/` in page text outside `data-raw`, code and Data. CLI text and API fields are unchanged.

- **The English catalog barrel is generated (decision changed 2026-11-18, issue #694; current; replaces the hand-written import list and spread line in `web/src/i18n/en.ts`, see History).** The decision that changed: **`web/src/i18n/en.ts` is written by `npm run i18n:catalog` (`scripts/i18n-catalog.ts`) from the area files in `web/src/i18n/en/`, never by hand.** It holds one import per area file, one spread per area in file-name order, and the `MessageKey` type; each area file exports one `export const <name> = { ... }`. A change that adds an area file runs the script instead of editing a shared line, so two such items no longer conflict on it (the improve run counted 2 conflict runs and 12 held items on the file in 7 days). `tests/web-i18n-keys.test.ts` fails when the checked-in barrel differs from the script's output. Keys and English text are unchanged; the large area files (settings, work, health) stay whole until conflicts on them continue (owner decision 2). The script is a local development step, not a factory feature. Triage's i18n companion rule adds the barrel beside each area file (design 04-triage).

- **New UI text goes through `t()` (decision changed 2026-11-13; current; replaces "the remaining views keep their English inline until follow-ups move them", see History).** The decision that changed: **every text the dashboard shows is read with `t()` from `web/src/i18n/en.ts`, so a new view or change adds its keys there and never an inline English string.** This covers JSX text, the `aria-label`, `title` and `placeholder` attributes, and English held in constants and props (dialog titles, consequences, field, option and filter labels, step-kind and state labels). The five views that were left (`item-commands.tsx`, `item-decisions.tsx`, `rules.tsx`, `transcript.tsx`, `tree.tsx`) now read their text through the catalog. A value the server receives stays as it is sent (command names, verdict kinds and severities, reject reasons, spec section headings, the `N: <answer>` lines); only its shown label is a key. Relative times stay compact (`12s`, `4m`, `3h`, `2d`): the unit letters come from the `unit.*` keys. `tests/web-i18n-text.test.ts` covers all of `web/src` with no baseline: it reads JSX text and the three attributes, and does not check JavaScript string literals, so English in constants is held by review.

- **App shell text through a catalog (decision changed 2026-11-12; current; replaces "the catalog holds the app shell's text only", see History).** The decision that changed: **the text of the app shell and of the Pages, Settings, Standing approvals, Tasks and Data views is no longer inline strings.** `web/src/i18n/en.ts` holds the English text of the sidebar, top bar, Refresh, theme control, the Needs you heading and these views (`web/src/views/pages.tsx`, `settings.tsx`, `standing.tsx`, `tasks.tsx`, `data.tsx`), keyed by name, a sentence with values as one key with `{name}` placeholders; `t(key)` in `web/src/i18n/index.ts` reads it, with no i18n library. The active locale is the first language in `navigator.languages` that has a catalog (`fr-FR` matches `fr`), English when none does; a key missing in the active catalog shows its English text. Nothing is stored: no config key, store column or per-person setting. `main.tsx` sets `<html lang>` to the active locale, and `web/src/lib/format.ts` passes it to every `Intl` call. Only English ships. **Add a locale:** one catalog file `web/src/i18n/<tag>.ts` with the same keys as `en.ts` (`tests/web-i18n.test.tsx` fails otherwise) and one registration line in `CATALOGS` in `web/src/i18n/index.ts`.
