# 9. Brand and design tokens

- **The product is Gongbang, and its mark is one master SVG (new decision, 2026-11-12, phase 3).** The decision that changed: **the product had no name or mark of its own ("Software Factory" in the app, "software-factory" in the dashboard); it is now Gongbang (공방, a workshop), with one mark drawn from `design-system/icon.svg`.** The mark is a white bold 공 on a rounded `#1C1C1E` square on the macOS icon grid (an 824 px square, radius 185, on 1024), with the 공 drawn as outlines (its ㄱ, ㅗ and the ring of ㅇ) so no installed font is needed, and an ember dot (`#FF6A2B`) top right that is drawn only at 64 px and up (`data-min-px="64"`), since it turns to noise below that.
  - **The icon builder.** `scripts/build-icons.mjs <folder>` (`npm run build:icons -- <folder>`) writes `icon-<n>.png` at 16, 32, 64, 128, 256, 512 and 1024 px, and on macOS `icon.icns` through `iconutil` from an `.iconset` of those files; elsewhere it skips `icon.icns` and says so. No rasterizer is installed and none can be added offline, so the script draws the SVG itself: only `<rect>` (with `rx`), `<circle>` and `<path>` with absolute `M L H V C Z`, hex fills and `fill-rule`, and it refuses anything else rather than drawing it wrong. Each row is sampled on 16 scanlines with exact coverage across, so the output is deterministic. `tests/desktop/build-icons.test.ts` covers both platform branches (iconutil faked) and the ember threshold.
  - **Where the mark goes.** The app bundle's `icon.icns` (`docs/design/09-desktop-app.md`); `web/public/favicon.png`, the 16 px render, linked from `web/index.html` (`tests/design-system.test.ts` checks it equals the builder's output); and the sidebar top (`web/src/components/ui/brand.tsx`): the same square and 공 path inline, coloured from the tokens (square `text-1`, 공 `surface`; in dark, square `surface-2`, 공 `text-1`), so the dark square with a light 공 holds in both themes and `web/src/` keeps no hex colour. The test keeps its path equal to the master. The wordmark "Gongbang" (`app.name`) stands beside it and hides below `sm`; the tab title is `(N) Page · Gongbang`.
  - **Not part of it.** The ember colour is not a token (the dashboard does not draw the dot); the server-rendered status page title in `src/ui/` stays "software-factory status" until a follow-up; the package, repository, Slack app and GitHub app keep their names; Windows and Linux icons. The app's CSP (`src/ui/app.ts`, `default-src 'none'`) has no `img-src`, so a browser may refuse the favicon until a follow-up adds `img-src 'self'`.
- **One token source, generated CSS (new decision, 2026-11-11, phase 1).** `design-system/tokens.json` is the only place a dashboard colour, type size, spacing step or radius is defined: light and dark colours, status pill colours (ok, warn, bad, info), type sizes, spacing and radius. `scripts/build-tokens.mjs` (`npm run build:tokens`) writes `web/src/tokens.css` from it: light values on `:root`, dark values under `.dark` (the class the theme toggle sets). The output is deterministic and carries a header that names the script; nobody edits it. `web/src/index.css` imports it and maps the Tailwind theme (`@theme inline`), so `bg-surface`, `text-text-2`, `bg-accent` and `rounded-card` exist. Every colour value equals the Tailwind palette colour the pages use today (zinc, blue, emerald, amber, red), so phase 1 changes no look.
  - **The hex rule.** No file under `web/src/` except `tokens.css` holds a hex colour (six or eight digits always; three or four only when a letter a-f is among them, so `#192` is not flagged). `tests/design-system.test.ts` enforces it, and fails when `tokens.css` differs from the generator's output.
  - **Phase 2 is done (2026-11-12).** Every view, component and `LINK_CLASS` under `web/src/` uses token classes (`text-text-1/2/3`, `bg-bg`, `bg-surface`, `bg-surface-2`, `border-border`, `border-border-strong`, `text-accent`, `outline-focus`, `bg-pill-*-bg text-pill-*-fg`) and `rounded-control`, `rounded-card` or `rounded-pill`; no `dark:` variant is needed because the tokens switch with `.dark`. `tests/design-system.test.ts` fails on a Tailwind palette colour class, a default radius class or an arbitrary `text-[...]` size. The pages' own light/dark choice still comes first (`web/src/theme.ts`: stored choice, then `prefers-color-scheme`), covered in `tests/ui-shell.test.tsx`. The three button kinds are ghost, outline and the destructive confirm (still the theme's red variable, which `tests/web-dialog.test.tsx` pins; moving it to `pill-bad` is a follow-up). The `/classic` page keeps its own CSS.
  - **Not built yet.** A written brand brief; the `/classic` page's colours.
