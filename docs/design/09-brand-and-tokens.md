# 9. Brand and design tokens

- **Accent is only for the primary Button and the selected-tab underline (decision changed 2026-11-19, owner request "Orange only for the primary action"; current; replaces accent as the colour of links, IDs, the selected segment and the Select check, see History).** Links are `text-1` with underline on hover (`LINK_CLASS`), IDs `text-3` mono (`ID_CLASS`), both in `web/src/components/ui/link-style.ts`; the SegmentedControl's selected segment is neutral (`surface` fill, `border-strong` ring, `text-1`); the Select check is `text-1`. `tests/ui-link-style.test.tsx` fails on `text-accent` under `web/src`. Accent as a fill or border (spend bar, Radio ring, Switch track) is a follow-up.
- **Select opens its own list below the field (decision changed 2026-11-17, owner request "Dropdowns open below the field"; current; replaces "Select is a native select that draws its own chevron" under the component set decision below, see History).** The decision that changed: **`Select` (`web/src/components/ui/select.tsx`) wrapped a native `<select>`, so the browser drew the option list, which on macOS opened over the field and hid the label above the next field (Settings > plugin choices); it is now a `role=combobox` button that opens its own `role=listbox` directly below the field, or above it when a measured check finds no room below in the viewport.** No positioning library and no new dependency: one component file. The list has the OverflowMenu's look (`menu.tsx`: `surface`, 1px `border`, `rounded-control`, shadow, items `text-sm` with hover `surface-2`) with `control.ts`'s `FOCUS` and `DISABLED`, and marks the current choice `aria-selected` with a `text-1` check; tokens only, no hex. Keys: Enter, Space or an arrow opens; ArrowDown and ArrowUp move the highlight; Enter picks; Esc closes and keeps the focus on the field; typed letters move the highlight to the first option starting with them. The props stay (`id`, `aria-label`, `value`, `disabled`, `className`, `wrapperClassName`, `onChange`, `<option>` children with a disabled placeholder), and `onChange` gets `{ target: { value } }`, so no page changed. No hidden native select is kept beside it (owner answer). Not part of it: multi-select, free text and search beyond type-to-find; the list sits by CSS inside its field's box, so a parent that clips its overflow also clips the list.
- **No server-rendered page keeps colours of its own (decision changed 2026-11-16, phase 4 of 4 of local-task-tk_3164aaa9-e569-4086-9e6d-013b63474c69-phase-2; current; replaces "the `/classic` page's colours" under Not built yet and "the server-rendered status page title stays software-factory status" of the Gongbang mark decision below, see History).** The decision that changed: **`/classic` and `/items/<id>` are removed (design 09-dashboard-app), so the dashboard's colours are the tokens and nothing else.** The only HTML outside the app is the error page shell (`src/ui/html.ts`): system colours (`Canvas`, `CanvasText`, `GrayText`) under `color-scheme: light dark`, no hex colour and no token, titled with its status code, with a home link to `/app/`.
- **Tabs are underline tabs (decision changed 2026-11-15, owner request "a tab like Grafana"; current; replaces "Tabs copy SegmentedControl's look", see History).** The decision that changed: **the project row was a bordered box with the selected tab filled `accent`, which read as one orange button with a single project; `Tabs` (`web/src/components/ui/tabs.tsx`) is now plain text on a 1px `border` line across the whole row, tabs 16px apart and 32px tall (`min-h-8`), unselected `text-2` (hover `text-1`), selected `text-1` with a 2px `accent` bottom border on the line, no fill.** An optional `action` prop draws one quiet action (an icon-only `ghost` Button) at the end of the same row, inside the border and outside the tablist. Semantics, keys and sideways scrolling are unchanged. Tokens only, no hex. The view control stays a `SegmentedControl`.
- **Every token has a Tailwind name (decision changed 2026-11-19, issue "Map remaining tokens"; current; replaces "`web/src/index.css` maps no `--color-sidebar`, so there is no `bg-sidebar` utility", see History).** `web/src/index.css` maps every token of `tokens.css` inside `@theme inline` except the type tokens `--fs-*` and `--lh-*` (left to wi_de565ffb): colours `--color-sidebar`, `--color-running`, `--color-done` and `--color-pill-{ok,warn,bad,info}-border` join the earlier ones, `--radius-box` (`var(--r-box)`) joins the other radii, and `--spacing-1`, `-2`, `-3`, `-4`, `-6`, `-8`, `-12` (each `var(--sp-N)`) give `p-3`, `gap-6` and so on at the token's value. `tests/design-system.test.ts` fails when a token in `tokens.css` has no `var(--token)` in `index.css` (excluding `--fs-*`, `--lh-*`), with a self-check that a missing mapping is caught. No existing class changed.

- **A `sidebar` token, and the app on `bg` (decision changed 2026-11-13, sidebar follow-ups of wi_4b98; current; replaces "the app wrapper paints `surface` and the sidebar has no colour of its own", see History).** `design-system/tokens.json` adds `sidebar`: `#F3F1EC` light, `#1D1D21` dark (owner answer), regenerated into `web/src/tokens.css`; the sidebar `aside` paints it with `bg-(--sidebar)` (the sidebar keeps `bg-(--sidebar)`; `bg-sidebar` exists too since 2026-11-19, see the full mapping below). The app wrapper in `web/src/App.tsx` uses `bg-bg` (`#FBFAF7` light, `#17171A` dark), so a page reads as the page background and cards on `surface` stand out. `tests/design-system.test.ts` checks `text`, `text-2` and `text-3` at 4.5:1 or more on `sidebar` in both themes. The CSP `img-src` is unchanged here (wi_4debd adds it).
- **The design system is code and docs only (new decision, 2026-11-13, owner request).** The decision that changed: the dashboard had a "Design system" page (a gallery of every shared component); it is removed, with its sidebar entry, route and text. A UI change reads `design-system/components.md` and `design-system/patterns.md` and composes from `web/src/components/ui/`. The guard stays: `tests/web-ui-components.test.tsx` fails when an exported component has no section in `components.md`.
- **The favicon loads: the app's CSP allows `img-src 'self'` (decision changed 2026-11-12; current; replaces "the app's CSP has no `img-src`, so a browser may refuse the favicon", see History).** The decision that changed: **every dashboard page logged two console errors because the browser refused `/app/favicon.png` under `default-src 'none'`; the app's CSP (`src/ui/app.ts`) now adds `img-src 'self'` after `style-src` and changes nothing else:** `default-src 'none'; script-src 'self'; style-src 'self'; img-src 'self'; connect-src 'self'; form-action 'self'; base-uri 'none'; frame-ancestors 'none'`. `npm run check:responsive` now reads each page's console errors and failed requests and fails on any one (`09-dashboard-app.md`, Responsive check), so a refused favicon fails it. `style-src 'self'` stays as it is (no `'unsafe-inline'`, no hash): react-aria's `usePress` prepends an inline `<style id="react-aria-pressable-style">` (`touch-action: pan-x pan-y pinch-zoom` on `[data-react-aria-pressable]`) that the policy refused, so `web/src/main.tsx` adds an empty `<meta>` with that id before render, which makes react-aria skip it, and `web/src/index.css` carries the rule in `@layer base`; `tests/ui-app.test.ts` fails if the marker, the rule or react-aria's id drift apart. Not part of it: react-aria's `usePreventScroll` injects a `<style>` on iOS only (not reached by the check). Not part of it either: the desktop app's own pages (`quick-add.html`, `settings.html`) keep `default-src 'none'` with no `img-src`.
- **Controls are composed by the design rules (decision changed 2026-11-12, controls follow-ups).** The decision that changed: **the danger button had no border, so Reject read as a text link beside Accept and Changes; now danger has secondary's box (1px `border-strong`, bg `surface`) with text in `failed`**. The solid danger of a confirm dialog's destructive confirm is unchanged. With it, from the design review of 2026-11-12 (measured):
  - **Separate actions sit 24 px (`space-6`) apart.** On the item page, Merge is its own block 24 px below the verdict row (`not-first:mt-6` on its row, which collapses with the list's 8 px), so it never reads as a fourth verdict.
  - **SegmentedControl** (`segmented-control.tsx`): one choice of a few views, a 32 px box (1px `border-strong`, bg `surface`) holding 28 px segments in one row that never wraps. The selected segment has `aria-pressed` and is neutral (`surface` fill, `border-strong` ring, `text-1`; was filled `accent`), so it reads in light and dark; the others are `text-2`. The Tasks page picks Inbox, Today, Upcoming and Project with it (it was a row of toggle buttons that wrapped to two rows at 390 px, the selected one hard to see in dark).
  - **Settings.** The models form is a two-column grid (tier label | 7rem field, gap-x 8 px, gap-y 12 px), so the three fields start at one x, with Save in its own ButtonRow 12 px below. Long unbroken values in the settings table (Value and File value) break anywhere (`wrap-anywhere`), "Applies at" is at least 6rem instead of 8rem, and a project value's editor and its Reset wrap, so at 1280 px the table fits its card and Reset keeps its 12 px cell padding from the card's edge.
  - **Rules empty state.** 12 px (`space-y-3`) between the empty box and its button, the field-to-buttons spacing.
- **Controls come from one component set (new decision, 2026-11-12).** The decision that changed: **the dashboard had three button kinds (ghost, outline and the dialog's destructive confirm in the theme's red variable) and each page styled raw form elements with its own classes; now every control is a component in `web/src/components/ui/`, built only from token classes, and no raw `<button>`, `<select>`, `<textarea>` or `<input>` appears in `web/src/` outside it** (`switch.tsx` keeps its own button). `tests/design-system.test.ts` fails when one comes back, also when the tag spans several lines.
  - **Button** (`button.tsx`): variants primary (bg `accent`, text `on-solid`, the one main action of a view), secondary (bg `surface`, 1px `border-strong`, the default), ghost (no border, hover `surface-2`) and danger (secondary's box, 1px `border-strong` on `surface`, text `failed`; filled `failed` with `on-solid` text and no border only as a confirm dialog's destructive confirm, `solid`). Sizes md (height 32 px, padding-x 12 px `space-3`, text-sm, font-medium), sm (height 28 px, padding-x 8 px `space-2`, text-xs) and icon (32 px square; it replaces the size-9 button). md and sm set the height as a minimum, so a long label wraps at a narrow width instead of spilling out. Radius `control`. Primary and danger hover drop to opacity 0.9; secondary and ghost hover show `surface-2`; a pressed toggle (`aria-pressed`, `aria-checked`) shows `surface-2`.
  - **Focus and disabled, every control.** Keyboard focus is a 2px outline in the `focus` token, offset 2 px, never the browser's ring (`control.ts` `FOCUS`). Disabled is opacity 0.5 on the whole control and a not-allowed cursor; hover applies only when enabled, so border and text keep their colours.
  - **Select, Input, Textarea** (`select.tsx`, `input.tsx`, `textarea.tsx`): 1px `border-strong`, radius `control`, bg `surface`, text-sm, placeholder `text-3` (`control.ts` `FIELD`). Select and Input are 32 px high with padding-x 12 px; Textarea has padding-x 12 px and padding-y 8 px. Select draws its own chevron and its own list (the Select decision at the top). **Radio** (`radio.tsx`): a 16 px circle with a `text-2` ring, checked an `accent` ring around a `surface` dot, label beside it.
  - **Layout.** ButtonRow (`button-row.tsx`): horizontal, gap 8 px (`space-2`), wraps at narrow widths, primary action last (macOS order). Field (`field.tsx`): label (text-sm, font-medium) above the control with a 4 px (`space-1`) gap, optional help text (text-xs, `text-2`) below. Spacing: 12 px (`space-3`) between a control and its button row, 24 px (`space-6`) between sections.
  - **Dialog** (`dialog.tsx`): radius `card`, padding 24 px (`space-6`), title text-base font-semibold, a right-aligned ButtonRow footer: Cancel (secondary), then the confirm (primary, or danger `solid`).
  - **The item page's Commands block.** The verdict severity is a Select; Accept (secondary), Changes (secondary), Reject (danger) and Done (ghost: a handled verdict's outcome, which hides it when pressed) are one ButtonRow, in that order. Read it is a secondary Button.
  - **One token added: `on-solid`**, the text on a filled `accent` or `failed` background: `#FFFFFF` in light, `#17171A` (the dark page background) in dark. `tests/design-system.test.ts` checks it at 4.5:1 or more on both, in both themes.
  - **Not part of it.** Type sizes are still Tailwind's `text-xs`/`text-sm`/`text-base`, not mapped to the `--fs-*` tokens: mapping them changes every page and is a follow-up.

Every colour is hex. Type has five steps of size and line height (28/34, 20/26, 15/22, 13/18, 11/14 px; `--fs-*` and `--lh-*`), spacing adds 48 px (key 12), radius is control 6, box 10, card 14 and pill. `tests/design-system.test.ts` fails below 4.5:1 for text, text-2 and text-3 on bg, surface and surface-2, for accent, running, done and failed on surface, and for each pill fg on its pill bg, in both themes. `design-system/README.md` keeps the changelog.
- **The product is Gongbang, and its mark is one master SVG (new decision, 2026-11-12, phase 3).** The decision that changed: **the product had no name or mark of its own ("Software Factory" in the app, "software-factory" in the dashboard); it is now Gongbang (공방, a workshop), with one mark drawn from `design-system/icon.svg`.** The mark is a white bold 공 on a rounded `#1C1C1E` square on the macOS icon grid (an 824 px square, radius 185, on 1024), with the 공 drawn as outlines (its ㄱ, ㅗ and the ring of ㅇ) so no installed font is needed, and an ember dot (`#FB923C`, the `ember` token in both themes) top right, at (800, 224) with radius 44 on the 1024 grid, drawn at every size (decision changed 2026-11-12: it was drawn only at 64 px and up, see History). At 32 px and below its radius is at least 2.5 px at that size (`data-small-r="2.5"` on the circle, read by the builder: radius `max(44, 2.5 × 1024 / size)`, so 80 at 32 px and 160 at 16 px, where it overlaps the ㄱ's top-right corner by about 1 px). The sidebar mark draws the same circle with the `fill-ember` class at the 24 px radius.
  - **The icon builder.** `scripts/build-icons.mjs <folder>` (`npm run build:icons -- <folder>`) writes `icon-<n>.png` at 16, 32, 64, 128, 256, 512 and 1024 px, and on macOS `icon.icns` through `iconutil` from an `.iconset` of those files; elsewhere it skips `icon.icns` and says so. No rasterizer is installed and none can be added offline, so the script draws the SVG itself: only `<rect>` (with `rx`), `<circle>` and `<path>` with absolute `M L H V C Z`, hex fills and `fill-rule`, and it refuses anything else rather than drawing it wrong. Each row is sampled on 16 scanlines with exact coverage across, so the output is deterministic. `tests/desktop/build-icons.test.ts` covers both platform branches (iconutil faked) and the ember dot at 16, 32, 64 and 1024 px.
  - **Where the mark goes.** The app bundle's `icon.icns` (`docs/design/09-desktop-app.md`); `web/public/favicon.png`, the 16 px render, linked from `web/index.html` (`tests/design-system.test.ts` checks it equals the builder's output); and the sidebar top (`web/src/components/ui/brand.tsx`): the same square and 공 path inline, coloured from the tokens (square `text-1`, 공 `surface`; in dark, square `surface-2`, 공 `text-1`), so the dark square with a light 공 holds in both themes and `web/src/` keeps no hex colour. The test keeps its path equal to the master. The wordmark "Gongbang" (`app.name`) stands beside it and hides below `sm`; the tab title is `(N) Page · Gongbang`.
  - **Not part of it.** The package, repository, Slack app and GitHub app keep their names; Windows and Linux icons. The app's CSP now allows the favicon (see the first decision).
- **One token source, generated CSS (new decision, 2026-11-11, phase 1).** `design-system/tokens.json` is the only place a dashboard colour, type size, spacing step or radius is defined: light and dark colours, status pill colours (ok, warn, bad, info), type sizes, spacing and radius. `scripts/build-tokens.mjs` (`npm run build:tokens`) writes `web/src/tokens.css` from it: light values on `:root`, dark values under `.dark` (the class the theme toggle sets). The output is deterministic and carries a header that names the script; nobody edits it. `web/src/index.css` imports it and maps the Tailwind theme (`@theme inline`), so `bg-surface`, `text-text-2`, `bg-accent` and `rounded-card` exist. (Replaced 2026-11-12: the colours were the Tailwind palette, see History.)
  - **The hex rule.** No file under `web/src/` except `tokens.css` holds a hex colour (six or eight digits always; three or four only when a letter a-f is among them, so `#192` is not flagged). `tests/design-system.test.ts` enforces it, and fails when `tokens.css` differs from the generator's output.
  - **Phase 2 is done (2026-11-12).** Every view, component and `LINK_CLASS` under `web/src/` uses token classes (`text-text-1/2/3`, `bg-bg`, `bg-surface`, `bg-surface-2`, `border-border`, `border-border-strong`, `text-accent`, `outline-focus`, `bg-pill-*-bg text-pill-*-fg`) and `rounded-control`, `rounded-card` or `rounded-pill`; no `dark:` variant is needed because the tokens switch with `.dark`. `tests/design-system.test.ts` fails on a Tailwind palette colour class, a default radius class or an arbitrary `text-[...]` size. The pages' own light/dark choice still comes first (`web/src/theme.ts`: stored choice, then `prefers-color-scheme`), covered in `tests/ui-shell.test.tsx`.
