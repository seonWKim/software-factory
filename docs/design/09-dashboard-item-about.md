# 9. Status page: dashboard item page, closed status, About and the short ID

Part of the item page ([09-dashboard-item.md](09-dashboard-item.md)).

- **About prose is capped at 75ch (new decision, 2026-11-25, daily design review; current).** `TEXT` in `web/src/views/item-about.tsx` carries `max-w-[75ch]` (design-system/patterns.md: prose widths stay), and the `prose-width` rule of `check:responsive` fails an About paragraph of more than 2 lines with a line over 75 characters; a closed spec Disclosure is not painted, so it is measured only when open.

- **A closed item reads as closed (decision changed 2026-11-24, owner review #76; see History).** On a `CLOSED` item the reason is `ClosedStatus` (`web/src/views/item-facts.tsx`): "Closed: <the closing timeline entry's sentence, else the close reason> · <time> · Read the reason" (the owner's last thread message, else "See the history", `#timeline`). No "nothing applies" line on a closed item; on an open one `commands.none` is reworded plainly. `ItemFacts` hides Tier, PR, Plan (was "Spec comment"), Review loops and Restarts on a closed item when empty or 0 (`item-page.test.tsx`).

- **About lists each done-when line with its check and latest result (new decision, 2026-11-22, phase 3 of wi_7b57e550, RFC 0024 WP3, "Item page shows each done-when check"; current; replaces the spec's criteria list in About for an item with checks, see History).** `GET /api/v1/items/<id>` adds `item.checks` (`src/ui/item-checks.ts`): null when the item's `done_checks` is null (triaged before them; no backfill), else one row per check in order, `{ line, check: { kind: command|test|manual, text }, result, output_tail }`. A manual line is always `manual`. Any other line takes the result the newest implement run stored in its outcome's `done_checks` (design 04-pre-push-gates) when that run's line at the same place has the same text, else `not_run`; a newer run that stored none (it failed before its checks) does not hide it. A `fail` line carries that run's failed outcome's `output_tail`, others null. Each text passes the Withholder, the tail on the run_outcome channel. The page (`web/src/views/item-checks.tsx`, inside About under the request, outside the spec `Disclosure`) lists each line with its check in plain words ("Checked by running …", "Checked by the tests in …", "A person checks it: …") and a `Badge` placed before the line text (changed 2026-11-28: it was at the row's far end, a card width from its criterion; see History): Pass (ok tone), Fail (bad), Manual (info), Not run (neutral). A failed line's tail sits behind a closed `Disclosure` ("What the check printed") in a wrapping `pre`; no tail, or a withheld one, shows no block. While checks show, the spec `Disclosure` leaves out its criteria list. No new route, store method or colour.

- **About says what the work is (new decision, 2026-11-22, wi_baff910a, "Item page shows what the work is about"; current, except the request line, changed 2026-11-25 (wi_c77bdc55, see History), and the spec's criteria list, changed by the checks decision above, see History).** `GET /api/v1/items/<id>` adds `item.request`, the body's first paragraph: the stored `issue_text` is `title`, a blank line, then the body, so the stored title is dropped when the text starts with it (then a blank line or the end) and the first paragraph of the rest is taken (`requestOf`, `src/ui/item-checks.ts`). Null when no body is left or the paragraph equals the item's title, so About never repeats the h1. Read-side only, no backfill; an item whose title was edited after intake can still show its old title (follow-up). It also adds `item.spec`, `{ problem, desired_output, done_criteria }`, null while `done_criteria` is null (the owner has not confirmed the spec). Each text, each criterion on its own, passes the Withholder on the default channel, so a flagged one is `[withheld: <rule>]`. The list rows are unchanged; stored fields only, no backfill or migration. The page (`web/src/views/item-about.tsx`) shows an About `Card` under the title: the request in text-sm, then the spec in a collapsed `Disclosure` (problem, desired output, and the criteria as a list only while the item has no done-when checks; see the checks decision above). A withheld value shows a withheld note, never the marker. No request and no spec: no About. Text wraps (break-words).

- **An item's short ID is built from its work item ID (decision changed 2026-11-21, wi_8c693a8b, "Dashboard IDs work in every command"; current; replaces the short ID taken from the source ID, see History).** `shortItemId` (`web/src/lib/format.ts`) is the 8 hex characters after `wi_` (`wi_c86970ff1a73401c952d9228d6156b6d` gives `c86970ff`), any other ID as it is. The Work list's tree (an untitled row and the waits-for hover), the item breadcrumb (hover: the full item ID) and the Source fact of a source with no web address show it. The CLI takes the same short ID or any unique prefix (design 05-sources, short IDs), so one item has one short ID everywhere. The source ID stays in the IDs disclosure; `shortSource` stays for source references (`SourceLink`, the Work items table and the Tasks page). Why: the page showed `f77945b7` (from `local-f77945b7-…`), and `factory task show f77945b7` printed `no work item f77945b7`.
