# 2. Work item (one shape, all sources)

`source{type, link}`, `requester_id`, `problem`, `resources` (pointers), `done_criteria` (frozen after confirm), `desired_output`, `scope` + *`allowed_paths`*, `tier 1–5`, `stage NEW|READY|RUNNING|REVIEW|CLOSED`, `blocked_on none|human|upstream|ci|budget` + `blocked_reason`, `close_reason completed|duplicate|wont_do|failed|rejected`, `loop_count`, `restart_count`, `token_cost`, `project`, `pr_number`, `merge_sha`, *`fixes_pr`*, `issue_text` (the issue as received at intake; triage overwrites `problem`, so a revision reads this), `revision_count` (`/revise` commands that started a triage run; not `loop_count`, which counts review loops), `spec_feedback` (text of the latest `/revise` or `/reject`; untrusted), `origin factory|adopted`, `head_branch` (an adopted PR's own branch), `last_head_sha` (the PR head the factory last recorded; §5, pull requests a person opens). Every change → `state_changes` row (IDs only, never names).

**Projects are keyed by the forge's repository ID.** A renamed or transferred repository split its items between the old and new path, and the path could not tell apart repositories on different hosts or providers. Now every project column (`work_items.project`, `unreviewed_merges.project`) and every lookup by project holds the **key** `<provider>:<host>:<repository id>`; for GitHub, `github:github.com:<repo node id>` (e.g. `github:github.com:R_kgDOabc123`). The node ID never changes with a rename or a transfer, so lookups by key still find the items created before one. The readable path is only a **label**, `<host>/<owner>/<name>` (e.g. `github.com/seonWKim/software-factory`): at startup the composition root resolves the configured `repo` through GitHub (`GET /repos/{owner}/{name}`: `node_id` and the current `full_name`), uses the key for all writes, and stores the label in the store (a `cursors` row `project_label:<key>`), so the status page shows it without calling GitHub. If the repo cannot be resolved, startup stops with a message naming the configured repo and the reason. The status page, comments and log lines show the label, never the key. The store refuses a project value that is not a key, and refuses to open while any row still holds `owner/name`. `npm run migrate` rewrites existing rows (SQLite and MySQL), resolving each `owner/name` through GitHub first and writing nothing if one fails; `--dry-run` lists the rows and changes nothing, a second run changes nothing. Rollout: run `npm run migrate` after stopping the old controllers and before starting the new ones. `factory.config.json` still names per-project settings by `owner/name`; they are re-keyed at startup. Only GitHub is implemented; the format leaves room for other providers and hosts. `source.id` values (`owner/repo#12`) are unchanged.
