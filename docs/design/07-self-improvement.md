# 7. Self-improvement

- Behavior changes only through what agents read or may do: all files in the factory-definition repo.
- Additive learnings: automatic. Prompt / gate / permission / tool changes: improver PR with replay evidence → human.
- Recurring failure class → hard fix (gate, permission), not a softer prompt.
- Progressive disclosure: index → body → references; `CapabilitySearch` (BM25, vector, hybrid) finds skills/tools/MCP. Finding ≠ permission.
  - **Doc index in the prompt (new decision, 2026-11-01):** the worker takes an optional `CapabilitySearch` and appends the top 8 results to the triage, implement and review prompts as a short index (path, name, ≤200-character snippet); agents read full text on demand with `Read`, which they already have. The index grants nothing: tools, `deny_paths` and grants are unchanged. BM25 comes first (`bm25` plugin: `*.md` under `docs/` and `skills/`, headings boosted, rebuilt from files when they change, per process); vector and hybrid stay later. `Capability.kind` gains `doc` for markdown docs (`skill` for `skills/`). The default stays `list-all`, which finds nothing, so prompts do not change until config selects `bm25`.
- **Daily improve run and its report (new decision, 2026-11-07, issue #306):** a run kind `improve` reviews failed runs. It is phase 1 of the self-improvement plan: the run only reads and reports.
  - **Schedule:** on each poll interval the controller queues the improve run of the current UTC calendar day for its project, with key `improve:<project>:daily:<YYYY-MM-DD>`. A repeat that day, on any replica, is a no-op. That run reports the previous UTC day, `[day−1 00:00Z, day 00:00Z)`. `factory improve` queues one run at once, with key `improve:<project>:manual:<nonce>`, over the last 24 hours. It takes no daily slot and is not gated by one. The window is stored on the run (`input.improve`), so a rerun reports the same runs. No config key sets the time or the window.
  - **System item:** a run needs a work item, so each project has one system item. Its source type is `system` and its source id is `improve:<project>`. It is created on first use and never triaged, labelled or transitioned through a source adapter. Every improve run of the project belongs to it. The controller acks a finished improve run on it with an empty patch (`improve_reported` or `improve_failed`) and does not retry a failed one: the next day's run covers the failures again.
  - **Run:** a worker claims it through the common claim path. Its rank is last; grants are unchanged. It uses no sandbox, no agent and no model. It reads the project's runs that finished inside the window (`listRunsFinishedBetween`: start inclusive, end exclusive) and groups the failed ones by error code and normalized detail. Normalizing replaces timestamps, UUIDs, hex ids and numbers with placeholders, folds case and whitespace, and cuts the detail to 200 characters. A group of two or more runs is a group. A single run is a one-run pattern. Both are sorted, so the same runs always give the same report.
  - **Store:** one `improve_reports` row per run, written once, holds the window, the groups and the one-run patterns, with run IDs and item IDs only. It was added in SQLite migration 26 and MySQL step 0026. Numbers 25 and 0025 were already taken by the merge checks. The `filed_patterns` table is created empty, and nothing writes to it yet. Filing patterns and calling a model come in later phases.

## History

- **Daily improve run and its report** (new decision, 2026-11-07). Before it, no run kind reviewed failed runs. Failed runs could only be read by time window (`listRunsFinishedWithin`), nothing grouped them, and every run was queued by a work item's transition.
- **Doc index in the prompt** (new decision, 2026-11-01). Before this, no agent received any capability list (`list-all` existed but nothing built it).
