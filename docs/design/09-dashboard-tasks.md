- **Every list of work items uses one `ItemRow` (decision changed 2026-11-22, wi_37bb601c, "One ItemRow for every list of work items"; current; replaces "every row is one `ListRow` with its actions in the ⋯ menu" for task and Needs you rows, see History).** `ItemRow` (`web/src/views/item-row.tsx`) draws every row of Tasks (`TaskCard`, `tasks/row.tsx`), Needs you (`WorkRow`, `task-work.tsx`), Work's table and tree, Runners' running runs and the item page's Runs. Slots in one order: StatusBadge · title (the link to the item) · why · project · worker · age · one primary action · "⋯" menu; a second line only for "held behind X" or an error. The row carries `data-item-id` (the work item's ID); the ID is never row text, only Copy ID in "⋯" (not in the Needs you menu, which keeps the item's commands). Variants change spacing only: `compact` (Work, Runners), `comfortable` (Tasks, its Needs you). **Tasks rows:** the shared `Checkbox` (`components/ui/checkbox.tsx`; click, Space and Enter toggle it) sits before the badge slot, as a completion control; the badge slot holds Overdue and the work item's state; why is the due time, project `#list`, then done time, close reason, sub-task parent, minutes, priority, `+projects`, recurrence. An unbuilt task has no work item: its title is plain text, its row carries `data-task` and no `data-item-id`, and its primary action is Build this; Description, sub-task, Projects… and Delete are in "⋯" for every open task. A done row is `text-2`, no strikethrough, no checkbox and no primary action: Reopen is in "⋯"; ⌘Z still reopens the last completion. Check rows stay `ListRow`. Tests: `tests/ui-item-row.test.tsx`, `tests/ui-tasks-page.test.tsx`, `tests/ui-tasks-done.test.tsx`.
