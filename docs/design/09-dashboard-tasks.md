Delete opens `DeleteProjectDialog` (`web/src/views/tasks/dialogs.tsx`), the shared `Dialog` with `danger`: "Delete <name>?", "The project leaves the Tasks page. This cannot be undone.", and the project's task count, read from the page's loaded (filtered) read, open and done, each task once: "It holds N tasks. The tasks are kept: they only leave the project." (one task and none have their own text). Confirm posts `{ project: <slug> }` with the CSRF token to `POST /api/v1/projects/delete` (`writeProjectDelete`, `src/ui/projects-api.ts`, a `TASK_WRITES` route, so the same request guards and commands-actor check as the other task writes), which calls the store's `deleteProject`, as `factory project delete <slug>` does: the project and its task links go, no task changes; 404 for an unknown slug. On success the page drops the project from every loaded tasks read at once (no reload), the filter falls back to All projects, and the reads reload; a refusal stays in the dialog with its reason. The CLI command and its output are unchanged. Tests: `tests/tasks-api.test.ts`, `tests/ui-tasks-projects.test.tsx`.

Cancel, Esc or the backdrop close it and post nothing. The dialog renders into `document.body`, so no row changes height (the learned rule: input in a list opens a modal). Tests: `tests/ui-tasks-page.test.tsx`, `tests/ui-tasks-done.test.tsx`, `tests/ui-link-style.test.tsx`.
