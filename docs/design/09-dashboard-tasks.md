  - **Calendar page: Week and Month with previous, next and Today (decision changed 2026-11-15; current; replaces "a Day / Upcoming control over today through 7 days ahead from `GET /api/v1/tasks`", see History)** (`web/src/views/calendar.tsx`, `PAGES` entry `calendar`, icon CalendarDays, group `tasks`). A `SegmentedControl` Week / Month (Week on load), then a `ButtonRow` of secondary Buttons: previous, next and Today. Previous and next move the shown period by one week (Week) or one month (Month); Today returns to the period holding today in the browser's time zone. The heading names the period: "Nov 9 – 15, 2026" (Week), "November 2026" (Month). Week is the seven days Monday to Sunday as seven rows, one per day, so it reads on a phone; Month is a Monday-first grid of the month, each cell listing up to 3 events and then "+N more", with the cells outside the month empty. Each day lists its events all-day first, then timed by time, each with its time or "all day" and its source, read-only. Weeks start on Monday; there is no week-start setting.
    - **The route.** The page reads `GET /api/v1/calendar/events?from=YYYY-MM-DD&to=YYYY-MM-DD` (`src/ui/calendar-events-api.ts`) with the first and last day shown, inclusive (Month: the month's first and last day). For each date it answers the stored events that overlap that local day, bucketed in the server's time zone by the rule the Tasks views use (`calendarDays` in `src/core/tasks.ts`), a `synced` flag, and `calendar`, the connected sources' sync state (the Calendar read decision at the top). It answers 400 with a reason when `from` or `to` is not a `YYYY-MM-DD` date, `from` is later than `to`, or the range covers more than 62 days. It reads the stored copy only: changing the period calls no calendar source and writes nothing. No new table, column or migration.
    - **Not synced.** A day is synced only when every listed source has a successful sync whose window covers the whole local day; the window is `[synced_at − 1 day, synced_at + 30 days]`, from `syncWindow` in `src/calendar/calendar-sync.ts`, the same function the sync asks its sources with. A source never synced makes every day not synced. A day that is not synced shows "Not synced" where its events would be, never an empty day; a period with no synced day says it is not synced above the days. The sync reaches one day back, so past days mostly show not synced. Why: a period the stored copy does not cover must not look free.
    - **Stale and empty.** A source whose last sync failed shows the stale-sync notice (`data-calendar-stale`) with its last synced time, and its stored events stay listed. With no calendar in the read's `calendar` list the empty state links to Settings → Integrations (`/app/settings?tab=integrations#calendar`, the Calendar section's id `calendar`). The old "Event" badge on each row is gone (every row there is an event).
