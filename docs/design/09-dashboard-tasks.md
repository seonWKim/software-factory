Below `sm` the title's base width is its text's: a short title and its badge keep the first line, a long title takes it alone (cut) with the badge under it, and the details start the next line; before, every title with a badge dropped to a line of its own (its 160px base width). Tables keep the State column first. Tests: `tests/ui-item-row.test.tsx`, `tests/ui-tasks-page.test.tsx`.

- **A list row's Checkbox, badge, title and menu share one 32px centre line; the title is the row title, underlined on hover only (decision changed 2026-11-24, owner feedback #81 "fix the design alignments"; current; replaces "a list row's title is a 24px `LINK_CLASS` link, underlined at rest", see History).** In `ItemRow`'s list layout (Tasks, Needs you) the title is one 32px line with its text centred (`LIST_TITLE`: `min-h-8 leading-8 font-medium`), and the badge slot is at least 32px tall (`min-h-8`), the height of the Checkbox's hit area, the primary action and the "⋯" button. A linked title uses `ROW_LINK_CLASS` (`link-style.ts`: text-1, underlined on hover only): it stands alone on its row, never inside a sentence, so the underline at rest that `LINK_CLASS` keeps for links in running text is not needed; at rest it reads like an unbuilt task's plain title (same weight, same colour). Tables and the Work tree keep `LINK_CLASS`. `ListRow`'s leading control is pulled up 6px as its menu is, so a 32px Switch or Checkbox centres on its 20px title line. Why: the owner's screenshot at about 740px showed the Checkbox 7px below the title's centre, more space under the title than above it (the title was a 24px box, its 20px text at the top, in a row the 32px Checkbox and menu set), and the titles drawn as raw underlined links. Tests: `tests/ui-item-row.test.tsx` ("gives a list row's title, badge line and Checkbox the same 32px line"), `tests/web-ui-components.test.tsx` (ListRow).
- **A task row's actions carry their `factory task` verb (decision changed 2026-11-23, local-task-tk_791a5df3, "One action set for people and agents"; current; replaces "only Build this carries `data-action`", see History).** On a task row (`web/src/views/tasks/row.tsx`) the Complete checkbox is `data-action="done"`, Build this `build` and Reopen `reopen` (`factory task reopen`: there is no bare `reopen`), each with `data-item`, the task's ID; a waiting work item's commands in the row's menu carry the item's (09-dashboard-item-commands). Description, Add sub-task, Projects and Delete open a dialog or form and carry no action name.
- **Every list of work items uses one `ItemRow` (decision changed 2026-11-22, wi_37bb601c, "One ItemRow for every list of work items"; current; replaces "every row is one `ListRow` with its actions in the ⋯ menu" for task and Needs you rows, see History).** `ItemRow` (`web/src/views/item-row.tsx`) draws every row of Tasks (`TaskCard`, `tasks/row.tsx`), Needs you (`WorkRow`, `task-work.tsx`), Work's table and tree, Runners' running runs and the item page's Runs. Slots in one order: StatusBadge · title (the link to the item) · why · project · worker · age · one primary action · "⋯" menu; a second line only for "held behind X" or an error. The row carries `data-item-id` (the work item's ID); the ID is never row text, only Copy ID in "⋯" (not in the Needs you menu, which keeps the item's commands). Variants change spacing only: `compact` (Work, Runners), `comfortable` (Tasks, its Needs you). A list or tree row's title is one line cut with an ellipsis (`data-row-title`, the responsive check's title-wrap rule); a table row's title (Work's list, Running now, Runs) wraps as a table column and a card do (`data-cell-title`, no `truncate`). A stored title is `data-raw`, also where a "held behind X" line quotes it. **Tasks rows:** the shared `Checkbox` (`components/ui/checkbox.tsx`; click, Space and Enter toggle it) sits before the badge slot, as a completion control; the badge slot holds Overdue and the work item's state; why is the due time, project `#list`, then done time, close reason, sub-task parent, minutes, priority, `+projects`, recurrence (the row line is `data-details`; the due text is `dueText`: a date its heading names is left out). Each acting control carries `data-action` and `data-item` (the task row `data-action` decision above); an open row's menu ends with Copy as CLI command, then Copy ID for a built task. An unbuilt task has no work item: its title is plain text, its row carries `data-task` and no `data-item-id`, and its primary action is Build this; Description, sub-task, Projects… and Delete are in "⋯" for every open task. A done row is `text-2`, no strikethrough, no checkbox and no primary action: Reopen is in "⋯"; ⌘Z still reopens the last completion. Check rows and the merged-without-you and worth-sampling rows (PRs, not work items) stay `ListRow`. Tests: `tests/ui-item-row.test.tsx`, `tests/ui-tasks-page.test.tsx`, `tests/ui-tasks-done.test.tsx`.

- **The Calendar page syncs the days on screen: Sync after Today, and Sync these days in the not-synced note (decision changed 2026-11-22, wi_76e42fbc, owner request 2026-11-21 "provide a way to sync easily", screenshot of the week Nov 16 – 22, 2026; current; replaces "a not-synced day has no action on the page", see History).** The toolbar row (`data-calendar-toolbar`) ends with a secondary `Button` "Sync" after the period group (Previous, Next, Today), shown only when the read lists at least one calendar. The not-synced `info` Notice keeps its sentence ("Not synced: Nov 16 – Nov 20. Both post the days on screen, the first through the last day of the week or month shown, with the session's CSRF token to `POST /api/v1/calendar/sync` `{ from, to }` (`postCalendarSync`, `web/src/api/calendar.ts`; owner only, design 02-tasks-calendar), then re-read. Strings: `calendarPage.sync`, `calendarPage.syncDays`, `calendarPage.syncing` (`web/src/i18n/en/tasks.ts`). Tests: `tests/ui-calendar-page.test.tsx`.
