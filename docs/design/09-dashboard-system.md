- **The Data page says what each table holds and answers plain-text questions (decision changed 2026-11-14; current; replaces "the Data page lists tables by name only, and free-form SQL is out of scope", from the 2026-11-07 Data page decision below, see History).** The decision that changed: **each table has a line, an owner and column meanings, and the owner can ask a question that becomes one read-only query.**
  - **Table docs.** Each component keeps a `table-docs.ts` beside its migrations (`src/<component>/table-docs.ts`: bus, calendar, controller, identity, inbound, outbound, runtime, state, worker): `TABLE_DOCS`, one line per table it declares (key `table`) and a meaning for a column whose name does not say (key `table.column`). State describes `schema_migrations` and the extension pack tables; a `legacy_` copy gets no line (changed 2026-11-15 with the legacy contract, design 10-event-driven; see History): every value of a table no component describes shows as `[hidden]`, so `HIDDEN_COLUMNS` lists no `legacy_` copy, and the test skips `legacy_` tables; the bus describes its run-time topic tables by suffix. `src/ui/data.ts` gathers them (`TABLE_DOCS`, `tableDoc`); one source, no list in `web/`. `tests/data-table-docs.test.ts` fails when a table of a freshly migrated SQLite store has no line, or a line names a table or column the store lacks. `GET /api/v1/data/tables` adds `description`, `owner` and `column_docs` per table (null and `{}` for a table no component describes; a hidden column gets no meaning) and `csrf_token` (the Settings token; null when the Ask route is not wired). No table, column or migration was added.
  - **Ask route.** `POST /api/v1/data/ask` with `{ question }` (1 to 1000 characters; `src/ui/data-ask.ts`), wired through `UiSettings.ask` (`buildUiParts` builds the Model plugin, `plugins.llm`, in the UI process; null when it cannot be built). Guards in order: Host, Origin, Content-Type, the CSRF token, the body size, JSON, then the owner check (`ownerOf`, 403 for anyone else) before any model call; then the question (400). A store with no read-only query answers 409. No model: 503 with a message; a model error or no query: 502 with a message; no query runs in either case, and the table list still loads.
  - **Model input.** One `LLMProvider.complete` call (`standard` class, JSON output `{ sql }`): the instruction, the question, today's UTC date (the Spend page's day), and each table's and column's name with its line and meanings. Hidden columns and tables no component describes (the `legacy_` copies until the contract migration) are left out; no row value and no row count is sent. The request passes the egress scan (`log` channel) first; a flagged request is not sent (400). A single-value answer line is built by code from the one result cell (`<column>: <value>`), never by a second model call.
  - **Query checks and connection** (`FactoryStore.readOnlyQuery`, `src/impl/store/sqlite/readonly-query.ts`). Before running: one statement (one trailing `;` allowed) that begins with `SELECT` or `WITH` and has a `SELECT`; ATTACH, DETACH, PRAGMA and every write or transaction word anywhere in the code (comments and string literals blanked) is refused, each with its reason (422 with the query and `refused`). A query that names a hidden column (`HIDDEN_COLUMNS`, quoted or not) is refused the same way; a result column with a hidden column's name shows `[hidden]`, and the query's reads of hidden columns give NULL. The query runs in a child process (`readonly-query-worker.ts`) on its own connection, opened read-only (`readOnly`, SQLITE_OPEN_READONLY) with `query_only` on and, on Node 24.10 and later, an authorizer that allows only reads; each of the three refuses a write alone. On an older Node (22.13 to 24.9, as on CI) no authorizer runs: an ATTACH or `PRAGMA query_only = OFF` still leaves nothing writable (attached databases open read-only), and a query whose plan (EXPLAIN) reads a hidden column, or opens an index holding one, is refused instead of reading NULL, since the name check alone misses a hidden column read under another name (a renamed CTE column) (decision changed 2026-11-14: hidden-column reads are refused, not NULL, where no authorizer runs). At most 500 rows (`truncated` when cut); past 5 seconds the child is killed and the query refused with a time-limit message. Why a process: `node:sqlite` cannot interrupt a running statement, a process can be killed.
  - **Results.** Every text cell, the query text and the column names pass the Withholder (`[withheld: <rule>]`). The response: `{ as_of, sql, columns, rows (arrays, in column order), truncated, answer }`.
  - **Cost.** Each model call writes one `data ask: model call` log record (model class, provider, input and output tokens, `cost_usd`) through the page's logger. It is not in the Spend totals: spend counts run outcomes only (06-spend), and the Ask has no run and no table of its own.
  - **Page.** Below the Autonomy line, an "Ask" section (shown when `csrf_token` is set): a `Field` with a `Textarea`, a primary Ask button, then the query, the one-line answer, a cut notice and the result table; a refusal is a `warn` `Notice` under the query, a message alone a `bad` one. The table list shows each table's owner and line under its name; the table card shows the line, `Owner: <component>`, and the column meanings (also as the column header's title). Strings are `data.*` keys in `web/src/i18n/en.ts`.
  - Not built: typed SQL when the model is off, saved questions, charts, any write.
