- **Why an item waits (decision changed 2026-11-07, issue #310; current, except the deadlock level, moved to History)** One pure function, `whyWaiting` (`src/ui/why.ts`, no store, no clock), turns an item's state, its queued or running run (with its queue position), the run's latest claim decision, the claim pauses in effect, the run's `not_before` (passed only while still ahead) and its phases into `{ code, text, next_actor, refs }`. **Precedence, first match wins:** closed; blocked on a person or the budget (`Ready to merge: …`, `Waiting for a person to approve the spec`, `#41 was closed without a merge: …`, a failed run, …); a deadlock claim on the current run (`Started past a deadlock with #92: a person checks the overlap`, `next_actor` `factory`); running (`Running implement`); a claim pause that stops the run's kind, by the store's claim rule (`rate_limit` and `model_stall` any kind, `forge_auth` and `preflight_access` implement and update only); a dependency (`Waiting for #A and #B to merge`, from the stored `blocked_reason`); a phase hold (`Waiting for the previous phase #N to merge`); a coordination hold (`Held behind #92, which has an open PR` / `which is running` / `which is queued ahead of it`, while the decision is `held`, not approved and on the current run); a retry's `not_before` (`Retry waits until …`); the queue position (`Queued at position N`); else `Nothing moves it: no run is queued`. `next_actor` is `human`, `factory`, `other_item` or `none`; `refs` are the same-repo `#N` numbers of the sentence (numbers only, never `owner/name#N`). **API:** `why` on each row of `/api/v1/items`, on the `item` of `/api/v1/items/:id` and on each row of `/api/v1/queue` (null for a run whose item is gone), all from the same helper (`whyOf`, `src/ui/list.ts`), so the three read the same `text`; the text passes the `Withholder`, and `ref_url` is the item's repository issue URL (from its GitHub source link; null otherwise) to append a ref to. **Levels:** a dependency blocker is `waiting_on_issue` (badge `waits on #N`) even while its run is queued, no longer `queued`. **App:** the Why column of Needs you and Work items shows the sentence; the Queue's Starts column shows it for any row that is not plainly queued or waiting out a retry (so a held run no longer reads "now"); the item page shows the full sentence under the title (no `truncate`) and no longer the raw Blocked on row; each `#N` in `refs` links to `ref_url` + N. **Reads:** only existing store reads: `getClaimPause` (four names, once per request), `listClaimDecisions` (per item with an active implement run on the item page and the Queue; this read cost is accepted for now; the Items list reads them in one `listLatestClaimDecisions` call since issue #295), `listRunsByStatus`, `getWorkItem`, and `listWorkItemsWhere` for phases only when an item is blocked upstream. No store method, interface, migration or schema changed.
