# 9. Status page: dashboard Tasks quick add

- **Quick add shows what it parsed, and a row shows its projects and only a stored duration (decision changed 2026-11-20, wi_a03550f9, "Quick-add shows what it parsed"; current; replaces "quick add shows only the server's refusal, and a timed row shows 30 min when no duration is stored", see History).** The decision that changed: **a live preview under the quick-add field shows what the words set before the owner submits, and the row no longer shows values nobody typed.** Found by the dogfood review of 2026-11-19 (F15): "… every week +backend tomorrow 09:00" kept "every week" in the title with no repeat, the row showed 30 min, and the project was not on the row.
  - **Preview.** `QuickAdd` (`web/src/views/tasks/forms.tsx`) asks `GET /api/v1/tasks/preview?words=<text>` (`readTaskPreview` in `src/ui/tasks-api.ts`, served beside the tasks read in `server.ts`) 250 ms after the last keystroke, and shows only the answer for the words now in the field. The route runs `parseQuickAdd`, the parser `POST /api/v1/tasks` uses (owner decision: a server route, not a copy of the parser in the web code), resolves the due day at the server's clock, reads no store row and writes nothing; the title and unread words go through the Withholder. Under the field, one muted line: Date, Time, Repeat, Project (`+slug`; the tab's project when none is typed) and Priority, each "none" when not given; then, in the warn colour, "Not understood, kept in the title: …" listing the unread words; or "Cannot add: <reason>" for words the parser refuses. A failed read hides the preview; Add still answers with the server's reason. Strings: `tasks.preview*`.
  - **Unread words.** `every …` is the repeat only as the last two words (owner answer 1, design 02-tasks-quick-add); any other `every` and its next plain word stay in the title and are listed as not understood, so "every week" is either the weekly repeat shown as "Repeat: every week" or a flagged title phrase, never dropped silently.
  - **Row.** The details line shows each of the task's projects as `+slug` (`TaskRow.projects`, after `#list`), and a timed row's duration only when one is stored: the row's `DEFAULT_MINUTES` (30) is removed (owner answer 2: no default duration at add time).
  - Tests: `tests/ui-tasks-quick-add.test.tsx` (the preview's fields, unread words, refusal, the tab's project, `+slug` on the row), `tests/ui-tasks-page.test.tsx` (no duration for a null one), `tests/ui-api.test.ts` (the route: fields, unread words, refusal, 400s, Withholder, no write).
- **Quick add on a project tab adds to that project (decision changed 2026-11-18; current; replaces "quick add posts only `{ id, words }`, so a task added on a project tab had no project", see History).** On a tab (`?project=<slug>`) `QuickAdd` posts `{ id, words, project }`; on All projects the body stays `{ id, words }`. `POST /api/v1/tasks` takes an optional `project` slug and links the new task to it in the add's transaction, unless the words name a project with `+slug`: then only that project is linked, the tab's is not added. A project that is not a slug, or is unknown or archived, answers 400 and stores nothing. The desktop box and `factory task add` still send `{ id, words }`.
