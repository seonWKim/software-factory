# 9. Status page: dashboard Runners page

- **The Runners tab has a Chat Card (decision added 2026-11-26, local-task-tk_eea9af6d phase 2 of 2; current; replaces none).** After Worker processes, `RunnersTab` draws `ChatCard` (`web/src/views/chat-card.tsx`): the chat's current activity, its recent turns with outcome and reason, and a Transcript button for each, opened in a dialog. The decision, its texts and the panel are in [09-dashboard-chat.md](09-dashboard-chat.md).

- **Runners is Health's Runners tab, without Running now (decision changed 2026-11-22, wi_149faba7; current; replaces the Runners page at `/app/runners` and its Running now Card, see History).** The page's factory banner, worker setting line and Worker processes Card are Health's Runners tab (`RunnersTab`, `web/src/views/pages.tsx`, [09-health.md](09-health.md)); the code-revision line shows once, above Health's tabs. Running now is on Work's Activity section only. `/app/runners` redirects to `/app/health?tab=runners`. The decisions below apply to the tab's texts and rows.

- **The Runners page says what runs in plain words, and a process's pid and max slots show only in a tooltip (decision changed 2026-11-20, wi_1a2e8925, "Runners and Plugins pages in plain words"; current; replaces "Factory running: revision …", "Worker setting: N (source)", the process row's host / pid / slot counts and its "draining" badge, and the code-revision line's origin/main words, see History).** The decision that changed: **the page states versions, counts and states as a reader says them** (design-system/writing.md, "Say what a value means"). The texts, all in `web/src/i18n/en/health.ts`:
  - **Factory line** (the Runners banner and the shell banner, one key `factory.running`): "Running version 3dc0029 · started 11m ago" (the short revision, the one relative time).
  - **Worker setting:** "Up to 3 tasks at once (changed in Settings)" for an override, "(set in the config file)" for a file value, "(default)" for the default; "Up to 1 task at once" for one.
  - **Code revision:** "Running version {rev}" with the badge "Up to date with the latest code", "{n} commits behind the latest code" or "Not compared with the latest code yet". The latest code is still the code checkout's origin/main (design 08-self-update); only the words changed.
  - **Process row:** the main line "This Mac · running 3 of 3" (tasks running of the slots that may claim now), then its start time. "This Mac" is the host of the process whose pid is the factory's `child_pid` (the process the supervisor runs, on the UI server's machine), for every process on that host; another host keeps its name (owner answer 2). A draining process (0 slots) reads "{host} · running N" with the badge "Finishing up before it stops". The pid and max slots show only in the main line's tooltip ("pid 26252 · max slots 10"), the name + Tooltip pattern of a worker's ID, not a Details block: the page shows no raw value in a `details` element under a name (`tests/ui-ids.test.tsx`, writing.md).
  - **Internal words** (owner answer 3, as writing.md has no list): no snake_case token and none of pid, slots, override, draining, revision, HEAD, outbound, origin/main shows on the Runners or Plugins page outside Details and tooltips (`tests/ui-workers-page.test.tsx`). Out of scope: the other factory states' texts ("Revision {target} failed to build" and the update banners), unchanged.

- **Runners' blocks are Cards (decision changed 2026-11-19, wi_de565ffb, "Professional polish: shared page header and cards"; current; replaces its `Section`s, see History).** Processes and Running now were titled `Card`s in the page's column under its `PageHeader` (since 2026-11-22 Processes is a Card of Health's Runners tab, the decision at the top); no process is an `EmptyState`; Draining and the code-revision state are the one `Badge`.

- **Migrate now, Start and Restart now are buttons, and no banner names `npm run` (decision changed 2026-11-16, phase 3 of 4 of local-0ffe3059-d863-4717-b3eb-1c72a06e444e; current; replaces the stopped and migration banners' `npm run` commands and the Needs-you migration row's `npm run migrate`, see History).** The decision that changed: **the page acts on the supervisor itself** (design 08-self-update). `SupervisorActions` (`web/src/views/system-banner.tsx`) reads `GET /api/v1/supervisor` and draws the buttons it offers, each behind the shared `Dialog`; when it offers none, it shows the first refusal's plain-words reason instead, and nothing while the read fails (an older server). The Runners page's `FactoryBanner` shows Migrate now while an update waits for its migration, else Start and Restart now; the Needs-you migration row shows Migrate now, and its command reads "Migrate now, or factory migrate". Migrate now's dialog shows the dry run (the pending steps and each line it prints) before its confirm is enabled; the confirm starts the migration and the banner follows it through `supervisor.json`. `postMigrate` and `postSupervisor` (`web/src/api.ts`) send the CSRF token from the same read. The texts: "Factory stopped. No runs start. Start it from a terminal with factory dev." and "Update to {target} waits for its migration[ (pending: …)]: Migrate now applies it." The server-rendered `/classic` page keeps its own wording.
