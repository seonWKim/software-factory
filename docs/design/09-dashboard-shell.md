# 9. Status page: dashboard shell (sidebar, top bar, theme, mode)

- **One shared Loading names what it waits for and gives up at 30 s (decision changed 2026-11-23, wi_926cad13; current; replaces bare bars, see History).** `Loading` (`parts.tsx`) takes `label` (an i18n key under `loading.`) and `onRetry`: bars for about 1 s, then "<label>: Still loading… (n s)", then at 30 s `ErrorNote` with Retry, which calls `onRetry` and restarts the steps. `ErrorNote`'s optional `onRetry` adds the button. Every `<Loading` in `web/src/views/` passes both (`tests/ui-loading.test.tsx`).

- **⌘K runs actions, shortcuts show where they apply, and the sidebar footer opens the shortcut list (decision changed 2026-11-23, local-task-tk_791a5df3, "One action set for people and agents"; current; replaces "⌘K finds pages and items and runs nothing" and "the shortcut list is only behind `?`", see History).** **⌘K** (`web/src/search.tsx`) lists, after the pages and items, an Actions group: "Approve: <title>" (`search.approve`) for each loaded open item whose row's `commands` has an allowed `approve` while the session's commands are on, and "Go to Runners" (`search.goRunners`), which opens `/app/health?tab=runners`. Approve goes through the item page's route, `POST /api/v1/items/:id/commands` with `approve` (`useCommandSend`): where the item's Approve button opens the approve dialog (`approvePhase`: a held spec, floor tier or Rule of Two step), ⌘K opens the same `ApproveDialog` with the spec's default answers and sends nothing before its confirm; else it sends at once, as the button does. The Actions come last, so Enter on a title search still opens the item. "Pause factory" is not offered: no route or CLI command pauses the factory yet (a follow-up). **Shortcut hints:** a "⋯" item with a key (`MenuItem.shortcut`, `web/src/components/ui/menu.tsx`) shows it in a `Kbd` after its label and names it with `aria-keyshortcuts`; the `Kbd` (`hint`) draws the key with CSS from `data-key`, so the item's text stays its label for scripts and agents. A Needs-you row's primary entry shows `p`. `Tooltip` takes a `shortcut`: the top bar's Search button shows `⌘K`. **Footer:** the sidebar ends with a quiet "? Shortcuts" button (`ShortcutsLink`, `web/src/shell/sidebar.tsx`, `keys.footerLink`) that opens the shortcut list (`HelpDialog`), as `?` does; the icon sidebar shows only `?`. No new keyboard shortcut. `tests/ui-actions.test.tsx` checks the ⌘K approve request, its dialog, Go to Runners and the footer link.

- **The top bar labels the running revision "Factory version", with a tooltip (decision changed 2026-11-23, issue #758; current; replaces "`FactoryRevision` shows the short `factory.rev`" with no visible label, of the update note decision below, see History).** `FactoryRevision` (`web/src/views/system-banner.tsx`) shows the visible label "Factory version" (`update.revLabel`, `web/src/i18n/en/shell.ts`) before the short revision and its "up to date" or "N behind"; the revision's tooltip (`update.revTooltip`) says it is the commit the factory runs. The label shows from `sm` up, so the top bar stays on one row (the top bar decision below); below `sm` the tooltip names it. The lower-case mode word next to it is unchanged (a follow-up). `tests/owner-text.test.ts` checks the label and the tooltip.

- **A Disclosure summary can take its panel's colour (decision changed 2026-11-22, "Warn panels pass AA contrast"; current; replaces the summary always being `text-text-2`, see History).** `Disclosure` (`web/src/components/ui/disclosure.tsx`) keeps `text-text-2` by default; its optional `summaryTone` prop sets another, so a Disclosure on a pill fill passes that pill's `text-pill-*-fg`: the update note's Changes toggle (`UpdateNote`, `web/src/views/system-banner.tsx`) on the info fill passes `text-pill-info-fg`. The Paused banner's Details and `FactoryText` in `pages.tsx`, which this was first written for, were removed on main by 1f2ba048 after the reviewed commit e51a9d7a (a claim pause is now a Needs-you row on a plain surface), so `RawDetails` takes no tone and no `PILL_FG` constant is needed. Text inside a warn, bad, ok or info panel uses the pill's fg token or `text-1`, never `text-2` or `text-3` (`text-2` is 4.15:1 on the dark warn fill); `tests/design-system.test.ts` checks both on each pill fill in both themes.

- **A mode chip in the top bar, an icon sidebar below 1024px, and no page link to Runners (decision changed 2026-11-22, wi_149faba7, "Tidy Tasks vs Work, hidden pages, Mode chip"; current; replaces the top bar's mode switch, the icon-only sidebar below 640px, Runners as a hidden page in ⌘K and the "g a" label "Go to Work (its Running now and feed)", see History).** The decisions that changed: **the top bar shows the mode and never writes it; the sidebar collapses at tablet widths; every page has a sidebar or tab home.** **Mode chip** (`ModeChip`, `web/src/shell/mode-chip.tsx`): the shared `Badge` inside a link to `/app/settings#mode`, reading "Auto · merges ≤ tier N" (N is the configured project's `auto_merge_max_tier`, its own value when it has one) in the `running` tone when the mode is auto, "Manual" in neutral otherwise; the same tooltip as the old switch (what auto does, the auto stop's reason above it). The mode changes only in Settings, behind a confirmation ([09-dashboard-settings.md](09-dashboard-settings.md)). **Sidebar:** the labels, the brand name and the Tasks count are `sr-only` below `lg` (1024px, Tailwind `max-lg`), so the sidebar is 56px of icons there and 176px (`w-44`) from 1024px up. **Pages:** Runners is no longer a page: it is Health's Runners tab ([09-health.md](09-health.md)), so `PAGES` has no Runners entry, ⌘K lists no Runners and Settings > Advanced's "More pages" links only Data. **Redirects** (`web/src/page-redirects.ts`, the query string kept): `/app/spend`, `/app/failures` and `/app/runners` go to `/app/health?tab=spend`, `?tab=failures` and `?tab=runners` (`/app/failures?window=7d` → `/app/health?tab=failures&window=7d`); `/app/activity` and `/app/queue` keep theirs. `/app/workers` stays the Workers page (decision of 2026-11-20 below): the spec's "/app/workers → Runners tab" predates that page, so it is not redirected. **Shortcuts:** `g a` and `g w` both go to Work and both read "Go to Work" in the `?` list. **Check:** `npm run check:responsive` adds an 800×1024 viewport and the `title-wrap` rule: a row title (`data-row-title`: Work's tree and table titles, Tasks' titles, the Runners tab's run titles) fails when it takes more than two lines.

- **The top bar stays on one row at every width (decision changed 2026-11-22, issue #763; current; replaces "the top bar wraps onto a second row when it does not fit", see History).** The header (`web/src/App.tsx`) is `flex` without wrap: the revision and the status text shrink (the status text is cut with an ellipsis); the Mode chip, Stop all agents, Search, Refresh and Theme controls keep their size, so Theme stays on the header row at 390px in both themes. Controls are ghost icon `Button`s and `OverflowMenu`; none is under 24x24px (responsive check rule `small-target`).

- **Stop all agents in the top bar (new decision, 2026-11-21, wi_0f56f105; current; adds to the top bar decision below, replaces none).** The top bar (`web/src/App.tsx`) holds `StopAllAgents` (`web/src/views/system-banner.tsx`) after the "update failed" text: the shared `Button`, `secondary`, labelled "Stop all agents", so each page keeps its one primary action. It opens the shared `Dialog` (default variant: primary confirm "Stop all agents", Cancel) whose consequence says building and review stop within a minute with their work kept, other steps finish first, nothing new starts until you resume, and tasks you work on yourself keep going; only the confirm posts (POST /api/v1/agents/stop with the page's CSRF token, design 05-restart-pauses). A refusal shows in the open dialog. After a stop it reloads the pauses and the overview, so Needs you shows "Agents stopped by you at 16:03" with Resume now, the way back. The button is hidden while the agents are stopped and while the server has no pause routes (no CSRF token). Text: `stop.*` in `web/src/i18n/en/system.ts`. The top bar stays on one row at every width (the top bar decision above).

- **A sidebar link is named by its text (decision changed 2026-11-21; current; replaces `aria-label` on each sidebar link, see History).** `SideLinks` (`web/src/shell/sidebar.tsx`) sets no `aria-label`: a link's accessible name is its visible label plus its count. The count span keeps its place and gets `role="img"` with the label `nav.needYou` (", {count} need you", `i18n/en/shell.ts`), so Tasks reads "Tasks, 4 need you", also below `sm` where the label and count are `sr-only`. `tests/ui-axe.test.tsx` runs axe on every page in `web/src/pages.ts` for `label-content-name-mismatch` and `heading-order`.

- **The current sidebar link has a 2 px leading bar (new decision, 2026-11-20; current).** `SideLinks` draws the current page's link (`relative`, `before:` pseudo-element, `bg-nav-active`, 2 px wide, full height of the row) on top of `bg-surface-2 font-medium` and `aria-current="page"`. Other links get no bar. Token and contrast: `09-brand-and-tokens.md`.

- **One page template, kept by a structure check (decision changed 2026-11-20, wi_bdd36b09, "Page template with a structure check"; current; replaces each page's own width, heading styles and control placement, see History).** The decision that changed: **a page no longer sets its own layout; the shared pieces do, and `npm run check:responsive` fails a page that drifts.** `PageHeader`'s `width` (`wide` by default; `read` for Settings and Rules) picks `--page-wide` (1232px) or `--page-read` (960px) for `<main>`; no page sets a page `max-w-*`. `Card` owns every page h2 (`CARD_TITLE`, the decision box's included); every sub-group h3 is `SUB_TITLE` (`text-xs font-medium text-text-2`). `PageToolbar` under the title holds the tabs (row 1) and the search, view switch and filters (row 2), never a Card: Workers' window, the Transcript's step filters, the Settings Advanced search (shown with that tab) and the Rules applied-rules search (Suggest stays in In effect) included. Buttons and Disclosure triggers are 28 or 32px; a chart's bar (`data-chart-bar`, Spend and Efficiency) is as tall as its chart and is the one exception. `data-raw` marks all text shown as stored or as written (titles, bodies, check messages, error details, transcripts, Data), not only Details. The check adds `one-h1`, `heading-size` (also across pages), `page-width`, `button-height` and `raw-name` (`scripts/responsive/rules.mjs`). Details: `design-system/patterns.md` and `components.md`.
- **Every instant is shown in the viewer's local time and sent as a field (decision changed 2026-11-20, wi_6a288f26; current; replaces "the API words some instants into its sentences, in UTC or as ISO", see History).** No API message or page sentence embeds an instant. The API sends it as an ISO field: a why reason's `until` param, a system action's `until`, `auto_stop.at`, a Health check's `since` and `next`, the improve report's `window_start`, `window_end` and `created_at`. The page formats it with `localDateTime` or `When` (`web/src/lib/format.ts`); the auto-stop line keeps its local clock time. `factory status` prints local time with its offset (`2026-11-20 01:11 +09:00`, `localWithOffset`). Spend keeps UTC days, labelled "Cost per UTC day". `tests/web-visible-times.test.tsx` renders every page in `web/src/pages.ts` and fails on an ISO instant or a text ending in ` UTC`. Stored rows keep their ISO form.

- **Workers is a sidebar page again, after Health (decision changed 2026-11-20, wi_ca3ff607; current; replaces the `/app/workers` to `/app/runners` redirect, see History).** System reads Work, Health, Workers (`PAGES`, `web/src/pages.ts`; label `page.workers`, `i18n/en/shell.ts`). `/app/workers` opens the Workers page ([09-dashboard-workers.md](09-dashboard-workers.md)), no longer a redirect; `/app/runners` still opens Runners.

- **An update note and the running revision in the top bar (new decision, 2026-11-19, wi_fcf04fac; current; adds to the top bar decision below, replaces none).** The decision: **an open tab says once that the factory moved to a new revision, and the top bar shows the revision it runs** (dogfood-review 2026-11-19, F22: an update c0147 → 3dc0029 changed an open tab with no note). `UpdateNote` (`web/src/views/system-banner.tsx`, under `RevisionBanner`) keeps this browser's last seen `factory.rev` in localStorage (`sf-factory-rev`). When a load or poll finds another revision than a stored one, it shows one note, "Updated to <short rev>: N changes", the commit subjects behind a Changes toggle (the shared Disclosure, at most 20, then "and N more") and Dismiss (the shared Button). The revision with a waiting note is kept under `sf-update-note`; Dismiss removes it, so a reload or poll for that revision shows nothing. A first visit (nothing stored) only stores the revision; a tab opened after an update with no stored earlier revision is not told. N and the subjects are the overview's `factory.changes` (`previous_rev..rev`, [08-self-update.md](08-self-update.md)); with no count (git failed, no `previous_rev`) the note names the revision only. Info pill tokens, no new colour; text under `update.*` in `web/src/i18n/en/shell.ts`. `FactoryRevision` in the top bar shows the short `factory.rev` with "up to date" or "N behind" from `factory.behind`: the revision alone when `behind` is absent (self-hosting) or null (not checked yet), nothing when `factory` is null or absent (the `none` updater). The reload banner and Health's code row are unchanged.

- **The top bar has no Needs you chip or age text, one Theme menu, a spinning Refresh and a mode tooltip (decision changed 2026-11-18; current; replaces the chip, "updated Ns ago" and the three theme buttons, see History).** The top bar (`web/src/App.tsx`, theme menu in `web/src/shell/top-bar.tsx`) holds the mode chip (since 2026-11-22, the decision at the top; before, the mode switch), "update failed" when the overview request fails, Search, Refresh and Theme; the count is the sidebar Tasks badge. **Theme** is one button opening the shared `OverflowMenu` (`web/src/components/ui/menu.tsx`, with an `icon` and `checked` items): System, Light, Dark, the current one `aria-checked`. **Refresh**'s icon spins while any query fetches. **The mode chip** has a `Tooltip` saying what auto does, the auto stop's reason above it.

- **A fixed sidebar with untitled groups, Settings at its bottom, and one queued count (decision changed 2026-11-13, sidebar follow-ups of wi_4b98; the group titles it added were removed 2026-11-18, design 09-status-page; current; replaces "the sidebar scrolls with the page, Settings is a top-bar link, and Work's summary counts items at level queued", see History).** **Sidebar** (`web/src/shell/sidebar.tsx`, placed by `web/src/App.tsx`): the app is a window-high shell (`h-dvh`) whose content column (`data-scroll-root`) scrolls instead of the window, and the `aside` beside it is `overflow-y-auto` on the `sidebar` token (`bg-(--sidebar)`, design 09-brand-and-tokens), so it stays in view while the page scrolls and scrolls by itself when taller than the window; it is not `sticky` or `fixed`, which `check:responsive` fails above 40% of the window's height (`tall-fixed`), and a navigation resets the content column's scroll, not the window's; the page behind it is `bg-bg`. The groups show no titles (since 2026-11-18, design 09-status-page); each `nav` is named by `aria-label` (`nav.tasks`, `nav.system`, `nav.setup`), always open, with no icon, no chevron and no `details` element. Sidebar links use the shared `FOCUS` ring from `web/src/components/ui/control.ts`, like buttons and fields (since 2026-11-19; before, the browser's default outline). **Settings** is a row at the bottom of the sidebar (group `bottom` in `web/src/pages.ts`, below System, outside its group), with `aria-current="page"` and the selected-row look while Settings shows; the top-bar Settings link is gone. **Queued:** Work's "N queued" counts queued runs from one helper (`useQueuedRuns`, `GET /api/v1/queue`), the same runs as `overview.queued` (owner answer: queued runs); the Queued filter now lists them (the 2026-11-14 decision at the top). **Tree rows** indent by depth with classes (`pl-0`, `pl-4`, … from the row's `level`), with no inline `style`, which the app's CSP forbids. **Not changed here:** the app's CSP `img-src` for the favicon, which another work item (wi_4debd) adds.

- **A three-way theme choice (decision changed 2026-11-12; its control became one menu 2026-11-18; current; replaces "a single toggle pins the theme", see History).** The top bar offers System, Light and Dark (`ThemeControl`, `web/src/shell/top-bar.tsx`). System is the default: the page follows the system colour scheme (`prefers-color-scheme`) at load and while it is open, with no reload, and the listener is removed when another choice is made (`applyChoice`, `web/src/theme.ts`). Light and Dark override the system. The choice is kept per browser under the existing key `sf-theme`: only `light` or `dark` is ever stored, and choosing System removes the value, so a stored `light` or `dark` still applies on load. Links on coloured banners use `BANNER_LINK_CLASS` (`web/src/components/ui/link-style.ts`): the banner's own `pill-*-fg` text token with an underline, readable on the `pill-*-bg` banner in light and dark, because `LINK_CLASS` (the accent token) fails 4.5:1 there in dark mode.

- **Menu names, groups and keyboard shortcuts (decision changed 2026-11-11; current; replaces the sidebar's "Floor, Work items, Workers, Queue, Health, Failures, Settings, Users" and the Users page, see History).** **Sidebar** (`PAGES` in `web/src/pages.ts`, names in `web/src/i18n/en.ts`): *Tasks* (the Tasks page at `/app/tasks`, whose Inbox, Today, Upcoming and Project tabs replaced the disabled "coming" entries on 2026-11-12, issue #607), *Factory* (Needs you at `/app/`) and *System*, collapsed by default and open while one of its pages shows (Work at `/app/items`, Activity at `/app/activity`, Health, Failures, Runners at `/app/runners`, Data; since 2026-11-15, the decision at the top). Settings is the row at the bottom of the sidebar (the decision of 2026-11-13 above). Each page's heading is its menu name. **Pages:** the Floor is split: Needs you holds the factory banner, claim pauses, system actions and the needs-you list; Activity holds the running-runs table, the unreviewed-merges line and the last 24 hours. The Floor's Queue section is gone (the Queue page was removed on 2026-11-14). **Old routes** redirect in place (`redirectFor`, address bar replaced; the list is in History). **Shortcuts** (`web/src/keys.ts`, one document listener): `⌘K` opens a search of the pages and the items already loaded in the query cache (`/api/v1/items` reads; no search endpoint, `web/src/search.tsx`); Enter or a click goes there, Escape closes. `g n`, `g w`, `g a` go to Needs you, Work, Activity; `g i`, `g t`, `g u` and `q` (quick add) do nothing until #569 adds their views. `j`/`k` move the selected row (any `main [data-key]` row), Enter opens its first link, `?` lists all shortcuts. None fires while focus is in an input, textarea, select or contenteditable element, or with Ctrl or Alt held. Phone width keeps the icon-only sidebar. No server, store or schema change.

- **The mode in the top bar and on the Settings page (decision changed 2026-11-08, issue #444; the top bar's switch became a chip and the Settings switch asks first on 2026-11-22, the decision at the top; see History).** The top bar shows the configured project's mode as a chip that links to Settings. The Settings page opens with a Mode section: the mode switch and, next to it, the auto-merge tier (0 to 3). Both read `GET /api/v1/settings` (`mode` has kind `mode` and project values; `auto_merge_max_tier` is a number) and write through `POST /api/v1/settings`, so a flip goes through `runSettings`: it needs `approve_merge` on the project (the page's Merge-button check, `UiSettings.mayApproveMerge`), a refusal (422) shows in the confirmation and writes nothing, and a confirmed flip writes one audit row naming the page's actor. The switch writes the project's own mode when it has one, else the global one. An `auto_stopped` alarm (design 03-risk) shows in Needs you, with "factory mode auto (after the cause is fixed)" as its command; it is not tied to any item.
