# 9. Status page: dashboard shell, shared components, JSON API and serving

- **Every instant is shown in the viewer's local time and sent as a field (decision changed 2026-11-20, wi_6a288f26; current; replaces "the API words some instants into its sentences, in UTC or as ISO", see History).** No API message or page sentence embeds an instant. The API sends it as an ISO field: a why reason's `until` param, a system action's `until`, `auto_stop.at`, a Health check's `since` and `next`, the improve report's `window_start`, `window_end` and `created_at`. The page formats it with `localDateTime` or `When` (`web/src/lib/format.ts`); the auto-stop line keeps its local clock time. `factory status` prints local time with its offset (`2026-11-20 01:11 +09:00`, `localWithOffset`). Spend keeps UTC days, labelled "Cost per UTC day". `tests/web-visible-times.test.tsx` renders every page in `web/src/pages.ts` and fails on an ISO instant or a text ending in ` UTC`. Stored rows keep their ISO form.

- **Workers is a sidebar page again, after Health (decision changed 2026-11-20, wi_ca3ff607; current; replaces the `/app/workers` to `/app/runners` redirect, see History).** System reads Work, Health, Workers (`PAGES`, `web/src/pages.ts`; label `page.workers`, `i18n/en/shell.ts`). `/app/workers` opens the Workers page ([09-dashboard-workers.md](09-dashboard-workers.md)), no longer a redirect; `/app/runners` still opens Runners.

- **The shared page pieces are PageHeader, Card, CardSection, EmptyState and one pill Badge, and `ListRow` for list rows (decision changed 2026-11-19, wi_de565ffb, `ListRow` added 2026-11-20, wi_a2e1243f; current; replaces `Section`, the square `Badge`, `StatusBadge`, `Empty` and the `text-lg` title, see History).** `PageHeader`'s h1 is `text-xl` semibold, primary action last; `Card` is `surface`, 1px `border`, `card` radius, 24 px padding, `shadow-sm`; every empty list is an `EmptyState`; list rows are a `ListRow` (09-dashboard-tasks). Details: `design-system/components.md`.

- **The `⌘K` search includes closed items, after open ones, labelled Merged or Closed (decision changed 2026-11-20; current; replaces "the search lists only the items the page has loaded", see History).** `SearchDialog` (`web/src/search.tsx`) reads the existing `GET /api/v1/items?closed=1` when it opens (`useApi`, the same cached read as Work's tree; no new endpoint) and merges it with the cached open items. Hits order: pages, open items, then closed items. A closed hit's right-hand label is `Merged` (`close_reason` completed) or `Closed` (any other), instead of `Items` (`search.merged`, `search.closed` in `web/src/i18n/en/shell.ts`). The read is capped at `LIST_LIMIT` (200 newest rows), so older closed items are not found; a store-side title search is a follow-up. A withheld title is not matched, and the hit shows the id.

- **The `?` dialog and the `⌘K` search hold the command help (decision changed 2026-11-19; current; adds to "Menu names, groups and keyboard shortcuts", whose help listed only shortcuts and whose search only pages and items, see History).** `HelpDialog` (`web/src/search.tsx`) shows a Commands section under the shortcuts: each item command as typed, what it does and where to type it (an issue or Slack reply, or `factory <command> <item>`), from one list (`COMMAND_HELP`). `SearchDialog` shows it under its hits, filtered by the search text. It replaces the item page's command prose and "From a terminal" line (design 09-dashboard-item). Text is in `web/src/i18n/en/work.ts` (`commands.help.*`, `commands.helpWhere`).

- **The top bar has no Needs you chip or age text, one Theme menu, a spinning Refresh and a mode tooltip (decision changed 2026-11-18; current; replaces the chip, "updated Ns ago" and the three theme buttons, see History).** The top bar (`web/src/App.tsx`, theme menu in `web/src/shell/top-bar.tsx`) holds the mode switch, "update failed" when the overview request fails, Search, Refresh and Theme; the count is the sidebar Tasks badge. **Theme** is one button opening the shared `OverflowMenu` (`web/src/components/ui/menu.tsx`, with an `icon` and `checked` items): System, Light, Dark, the current one `aria-checked`. **Refresh**'s icon spins while any query fetches. **The mode switch** has a `Tooltip` saying what auto does, the auto stop's reason above it.

- **One shared Disclosure draws every show/hide section (decision changed 2026-11-18, issue "Shared disclosure component"; current; replaces the per-page raw `<details>` blocks, see History).** `Disclosure` (`web/src/components/ui/disclosure.tsx`) renders one native `<details>` with a `<summary>` that has one chevron marker (turned down when open) and one label style (`text-xs text-text-2`, no box). The open state is held in React so `aria-expanded` on the summary and the `open` attribute agree; click, Enter and Space toggle it. `defaultOpen` keeps each call site's start state, `lazy` mounts the body only while open (the Rules card's "Why and where" reads its detail on first open, never on page load), and `data-*` props pass through to the `<details>` (`data-how`, `data-decided`, `data-retired`, `data-ids`, `data-alarm-full`, `data-details`, `data-testid="ok-checks"`). `web/src/views/` and the Markdown fold use it and write no raw `<details>`. Use it only for long content (decision rule 2 in `design-system/patterns.md`).

- **A readable name shows its full ID in a tooltip and copies it on click, with no disclosure (decision changed 2026-11-15; current; replaces the "IdDetails opens to the full ID and a Copy button" rule of the readable-names decision, see History).** `IdDetails` (`web/src/components/ui/copy.tsx`) is a button showing only the label ("worker 2", "you"), wrapped in the shared `Tooltip` that holds the full ID on hover and focus; a click copies the ID and shows "Copied" for 1.5 s in place of the label, so a row never grows. It shares its copy helper with `CopyButton`. Callers and props are unchanged.

- **Each page renders its own `PageHeader`; the app shell draws no title (decision changed 2026-11-14; current; replaces "the app shell draws an h1 with the page name on every page except Needs you", see History).** Every sidebar page, the item page (the item's title) and the transcript page (the run's title) start with `PageHeader`, so each has exactly one h1 (a test in `tests/ui-shell.test.tsx` counts them). Rules keeps its description in that header, under the title "Rules". Runners shows the factory state (`FactoryBanner`) as a `Notice` of the matching tone, keeps `data-testid="factory-banner"`, and stacks its blocks in a `flex flex-col gap-6` column; the page has no banner tone classes of its own.

- **Every action opens the shared Dialog; sentence-case rows; token classes only (decision changed 2026-11-13, UI review; current; replaces "the item page's approve is an inline confirm and its verdict is three buttons with a severity choice", "the dialog's title names the item's ID" and "a Needs-you row's buttons are lowercase command names in the Why column", see History).** **Item page:** approve in the four approve phases (spec gate, revision limit, floor block, Rule of Two) opens `ApproveDialog` (`web/src/views/item-decisions.tsx`): each question with its answer, an optional note (it starts as the page's note box text), the Next line, then Cancel on the left and Approve on the right; focus moves into it. Verdict opens `VerdictDialog` (`item-commands.tsx`): an Accept, Changes or Reject choice, a severity select and a reason field; the reason is required for Changes and Reject and not for Accept; the usage text is no placeholder anywhere (`VERDICT_PLACEHOLDER` is removed). The item page keeps the note box for the other commands and the one-tap Good, Bad and Feedback beside the Verdict button. No inline approve confirm or verdict form remains; reject, revise, verdict and approve all use the one `Dialog`. Approve outside those phases still sends at once. **Dialog:** the title is the action and the item's title (`Reject Spec waiting`), one truncated line with the full text in its tooltip; the item's ID shows only when the item has no title. The confirm is filled with the accent (`Button` primary), the reject confirm with the failed token, Cancel stays an outline. The dialog, the row menu and the toast use token utilities only, never a palette class or `rounded-md` (the classes and spacing are in History). **Row:** a Needs-you row's Actions column (`NeedActions`, the Needs you page decision below) keeps its one primary button first, then the "⋯" menu; every cell of the row is vertically centred, and the reject, revise and verdict dialogs it opens are titled with the item's title. Labels are sentence case (Approve, Merge, Retry, Revise, Reject, Verdict) in the row, the menu and the item page. The Merge button's behaviour is unchanged (no confirm dialog). No route, store, command or controller change.

- **A fixed sidebar with untitled groups, Settings at its bottom, and one queued count (decision changed 2026-11-13, sidebar follow-ups of wi_4b98; the group titles it added were removed 2026-11-18, design 09-status-page; current; replaces "the sidebar scrolls with the page, Settings is a top-bar link, and Work's summary counts items at level queued", see History).** **Sidebar** (`web/src/shell/sidebar.tsx`, placed by `web/src/App.tsx`): the app is a window-high shell (`h-dvh`) whose content column (`data-scroll-root`) scrolls instead of the window, and the `aside` beside it is `overflow-y-auto` on the `sidebar` token (`bg-(--sidebar)`, design 09-brand-and-tokens), so it stays in view while the page scrolls and scrolls by itself when taller than the window; it is not `sticky` or `fixed`, which `check:responsive` fails above 40% of the window's height (`tall-fixed`), and a navigation resets the content column's scroll, not the window's; the page behind it is `bg-bg`. The groups show no titles (since 2026-11-18, design 09-status-page); each `nav` is named by `aria-label` (`nav.tasks`, `nav.system`, `nav.setup`), always open, with no icon, no chevron and no `details` element. Sidebar links use the shared `FOCUS` ring from `web/src/components/ui/control.ts`, like buttons and fields (since 2026-11-19; before, the browser's default outline). **Settings** is a row at the bottom of the sidebar (group `bottom` in `web/src/pages.ts`, below System, outside its group), with `aria-current="page"` and the selected-row look while Settings shows; the top-bar Settings link is gone. **Queued:** Work's "N queued" counts queued runs from one helper (`useQueuedRuns`, `GET /api/v1/queue`), the same runs as `overview.queued` (owner answer: queued runs); the Queued filter now lists them (the 2026-11-14 decision at the top). **Tree rows** indent by depth with classes (`pl-0`, `pl-4`, … from the row's `level`), with no inline `style`, which the app's CSP forbids. **Not changed here:** the app's CSP `img-src` for the favicon, which another work item (wi_4debd) adds.

- **Dashboard pages follow written guides (new decision, 2026-11-12; current).** The decision that changed: **how a page is laid out, worded and checked is written down** in `design-system/patterns.md` (layout, list rows, actions, confirmations, status, loading, empty and error states, forms and keyboard), `design-system/writing.md` (sentence case, the next step, no raw IDs, no command as the main text, compact times, `t()`) and `design-system/dx.md` (build steps, each check with its test and npm script, a PR checklist for UI changes; `AGENTS.md` points to it). It changes no earlier decision: it names the rules of the decisions above (readable names, the catalog) and the tests that enforce them. The raw-controls test (wi_5b2b) is the one check, with no ratchet list or allow-list of existing raw controls. Existing pages move onto the components in follow-up issues, the Needs you redesign (wi_fc2c) first. No page, route or component changed. **Why:** the rules lived in the heads of earlier changes and in single tests.

- **A three-way theme choice (decision changed 2026-11-12; its control became one menu 2026-11-18; current; replaces "a single toggle pins the theme", see History).** The top bar offers System, Light and Dark (`ThemeControl`, `web/src/shell/top-bar.tsx`). System is the default: the page follows the system colour scheme (`prefers-color-scheme`) at load and while it is open, with no reload, and the listener is removed when another choice is made (`applyChoice`, `web/src/theme.ts`). Light and Dark override the system. The choice is kept per browser under the existing key `sf-theme`: only `light` or `dark` is ever stored, and choosing System removes the value, so a stored `light` or `dark` still applies on load. Links on coloured banners use `BANNER_LINK_CLASS` (`web/src/components/ui/link-style.ts`): the banner's own `pill-*-fg` text token with an underline, readable on the `pill-*-bg` banner in light and dark, because `LINK_CLASS` (the accent token) fails 4.5:1 there in dark mode.

- **Menu names, groups and keyboard shortcuts (decision changed 2026-11-11; current; replaces the sidebar's "Floor, Work items, Workers, Queue, Health, Failures, Settings, Users" and the Users page, see History).** **Sidebar** (`PAGES` in `web/src/pages.ts`, names in `web/src/i18n/en.ts`): *Tasks* (the Tasks page at `/app/tasks`, whose Inbox, Today, Upcoming and Project tabs replaced the disabled "coming" entries on 2026-11-12, issue #607), *Factory* (Needs you at `/app/`) and *System*, collapsed by default and open while one of its pages shows (Work at `/app/items`, Activity at `/app/activity`, Health, Failures, Runners at `/app/runners`, Data; since 2026-11-15, the decision at the top). Settings is the row at the bottom of the sidebar (the decision of 2026-11-13 above). Each page's heading is its menu name. **Pages:** the Floor is split: Needs you holds the factory banner, claim pauses, system actions and the needs-you list; Activity holds the running-runs table, the unreviewed-merges line and the last 24 hours. The Floor's Queue section is gone (the Queue page was removed on 2026-11-14). **Old routes** redirect in place (`redirectFor`, address bar replaced; the list is in History). **Shortcuts** (`web/src/keys.ts`, one document listener): `⌘K` opens a search of the pages and the items already loaded in the query cache (`/api/v1/items` reads; no search endpoint, `web/src/search.tsx`); Enter or a click goes there, Escape closes. `g n`, `g w`, `g a` go to Needs you, Work, Activity; `g i`, `g t`, `g u` and `q` (quick add) do nothing until #569 adds their views. `j`/`k` move the selected row (any `main [data-key]` row), Enter opens its first link, `?` lists all shortcuts. None fires while focus is in an input, textarea, select or contenteditable element, or with Ctrl or Alt held. Phone width keeps the icon-only sidebar. No server, store or schema change.

- **The mode in the top bar and on the Settings page (decision changed 2026-11-08, issue #444; see History).** The top bar shows the configured project's mode (`ModeSwitch`, `web/src/views/settings/general.tsx`) as a switch (on: auto, off: manual). The Settings page opens with a Mode section: the same switch and, next to it, the auto-merge tier (0 to 3). Both read `GET /api/v1/settings` (`mode` has kind `mode` and project values; `auto_merge_max_tier` is a number) and write through `POST /api/v1/settings`, so a flip goes through `runSettings`: it needs `approve_merge` on the project (the page's Merge-button check, `UiSettings.mayApproveMerge`), a refusal (422) shows beside the switch and writes nothing, and a flip writes one audit row naming the page's actor. The switch writes the project's own mode when it has one, else the global one. An `auto_stopped` alarm (design 03-risk) shows in Needs you, with "factory mode auto (after the cause is fixed)" as its command; it is not tied to any item.
