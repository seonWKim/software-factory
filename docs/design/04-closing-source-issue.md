# 4. Agents: closing the source issue

**Closing the source issue.** Intake now also reads closed factory-labelled issues on every poll (`issues?state=closed&labels=<intake_label>`, its own `closed` cursor inside the same intake cursor, `since` inclusive, the issue numbers at the boundary time skipped; pull requests in the list are skipped). Each becomes a `source_closed` event carrying the closer from the single-issue endpoint's `closed_by`, or null, and GitHub's `state_reason` (`completed`, `not_planned`, or null for none or any other value). The rule: **closing the issue stops the item.** If the item exists and is not already `CLOSED`, one conditional transition sets `CLOSED` with `close_reason` `completed` when the state_reason is `completed` and `wont_do` otherwise (no `merge_sha` is written), writes one `state_changes` row with reason `source_closed` and the closer's user id as actor, and in the same transaction cancels the item's `queued` runs (triage, or a retry waiting on backoff; `TransitionInput.cancel_queued_runs`) and stops its `running` runs of any kind (`TransitionInput.cancel_running_runs`: status `cancelled`, lease cleared, no outcome). A stopped run's worker gets `lease_lost` on its next heartbeat, its handoff writes and its completion are refused (its outcome is not stored), and the tool broker refuses its calls with `lease_lost`, so nothing is pushed after the close. Cancelled runs go through the normal ack path and are recorded as `run_ignored`; the controller posts nothing for them. The reaper cancels, rather than requeues, an expired run whose item is `CLOSED`. Store first, no login check: an item already `CLOSED` (by `/reject`, a merge, or an earlier delivery of the same close) gets no row, so repeats and the factory's own close are no-ops. A closer GitHub does not name, or who maps to no user, is recorded as the system actor (`system:intake`) with a warning. No comment is posted on the closed issue; its status label moves to `done` for `completed` and `rejected` for `wont_do`. **The item's PR:** an item with a `pr_number` is closed as `CLOSED` with `blocked_on: upstream` / `blocked_reason: pr_close_pending` in the same transition. The controller then asks the source to close that PR without merging (`SourceAdapter.closePr`), after one comment on it, keyed on marker `pr-closed:<item id>`: "Closed because the issue was closed by @<login>.", or "Closed because the issue was closed." when GitHub names no closer (the source reads `closed_by` again, so no login is stored). A PR already merged or closed is left alone, with no comment. Then the mark is cleared (`pr_closed_for_source`). If the comment or the close fails, the item stays `CLOSED` and marked, a warning is logged, and every intake tick tries again; the comment goes first and carries its marker, so it is never posted twice. The `pr_closed` event GitHub then sends finds the item `CLOSED` and changes nothing. Closes are delivered after the poll's PR events, so a merged PR whose `Closes #N` closed the issue is recorded as `completed` first. Reopening the issue or re-adding the label does not restart a closed item: intake returns the existing item, so a human files a new issue. Known gaps: an issue whose factory label was removed before it closed is not seen; an item closed as `completed` with no merge still counts as merged in budget stats (§6), left for its own item. `/reject` still leaves the PR open.

## History

- **Closing the source issue** (decision changed 2026-11-01). Before: intake read only open issues, so closing a factory issue did not stop its work item, and a human had to `/reject` a closed issue by hand.
- **Decision changed 2026-11-02 (issue #104):** before, every source close was recorded as `wont_do`, a running run finished and its result was ignored (an implement run could still push a PR), and the item's open PR stayed open with no note. Now the close reason follows GitHub's, running runs stop in the same write as the close, and the open PR is closed with a comment naming the closer.
