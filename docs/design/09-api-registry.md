# 9. Status page: the API registry

- **A POST capability may declare `max_body`, its largest body, and a `bytes()` field is never withheld (new decision, 2026-11-27, spec chat-images; current; replaces none: every capability POST took the write routes' 64 KB).** `Capability.max_body` (`src/api/registry.ts`) is read by the server through `registryMaxBody` before it reads the body; a larger body is a 413 as on every write route. `chat.send` declares `CHAT_SEND_MAX_BODY` for its images. `bytes()` (`src/api/schema.ts`) is a string checked as base64, typed `contentEncoding: base64` in OpenAPI and left out of the Withholder (bytes are not text; `chat.image` answers an image's bytes through it).

- **The schedules and items pages call the generated typed client, and a breaking schema change needs a version bump (decision changed 2026-11-26, phase 3 of 3 of local-task-tk_c6ba6e00-9024-4701-b9b6-24adb4fb8cdb; current; replaces "no route, page or client call moves" of phase 1, see History).**
  - **Pages:** `web/src/api/schedules.ts` reads through `schedulesList`, `schedulesRuns` and `schedulesSuggestions`, writes through `schedulesAdd`, `.Edit`, `.Pause`, `.Resume`, `.Run` and `.Delete` (`postSchedule` maps the verb to its call; `ScheduleVerb` is that map's keys) and drafts and improves through `schedulesDraft` and `schedulesImprove`. `useItems` (`web/src/api/items.ts`) calls `itemsList`. Each hook keeps its `routes.ts` query key and polls every `POLL_MS`, so the Schedules page's reload of every key starting with `API.schedules` still reaches the reads. Neither file holds an `/api/v1/` string outside comments; `routes.ts` drops `scheduleWrite` and `itemsIn`. The item detail, changes, commands and merge-check reads are not capabilities yet and stay on `routes.ts`.
  - **Version:** `API_VERSION` (`src/api/registry.ts`) is `docs/api/openapi.json`'s `info.version`. `tests/api-openapi.test.ts` `breakingChanges(previous, next)` lists a removed path or method, a removed property, a changed type, a property that becomes required and a new required input field; an added optional field is not one. A breaking pair fails unless the next version is greater, shown on fixture pairs, and the checked-in document against the generated one. The checked-in file must equal the generated one, so a version change needs `npm run gen:api`. No git-based check of the base commit.
  - **Triage** (decision changed 2026-11-27, wi_f511452c; replaces "`prompts/triage.md` states the rule", see History): the generic triage prompt does not state the rule; triage reads it from the repository's own `AGENTS.md`, which its principles check already sends it to. `tests/api-architecture.test.ts` checks that `AGENTS.md` states the rule and the prompt does not, and the pages' imports.

- **The schedules and items routes are capabilities, and a ratchet and an architecture test hold every other /api/v1 path (decision changed 2026-11-26, phase 2 of 3 of local-task-tk_c6ba6e00-9024-4701-b9b6-24adb4fb8cdb; current; replaces "counting unregistered page paths in the same ratchet comes in a later phase, with its list file", see History).**
  - **Declared:** `src/api/capabilities/items.ts` (`items.list`, GET `/api/v1/items`) and `src/api/capabilities/schedules.ts` (`schedules.list`, `.runs`, `.suggestions` with permission `read`; `schedules.add`, `.edit`, `.pause`, `.resume`, `.run`, `.delete`, `.draft`, `.improve` with permission `owner`). Their handlers stay (`src/ui/schedules-api.ts`, `listItems` in `src/ui/api.ts`); a run imports its handler inside itself, so `scripts/gen-api.mjs` never loads one, and `answerOf` (`src/ui/api.ts`) turns a handler's result into its answer or `refuse(status, error)`. The hand-wired entries in `read-routes.ts`, `write-routes-owner.ts` and `api.ts`'s switch are gone. A schedule write's input schema types the fields `bodyOf` reads, which still checks them; a nullable leaf's refusal names null ("daily_cap_usd must be a number or null."). The item row's `tier` is an integer or null (phase 1 typed it as a string, so a list with a tier answered 500).
  - **Architecture test** (`tests/api-architecture.test.ts`): every declaration has a description, an input and an output schema, a kind (its method, GET or POST) and a permission (read or owner).
  - **Ratchet** (owner answer 4): the same test scans `src/ui/*.ts` and `web/src/api/routes.ts` for /api/v1 paths. A path a capability declares (or the feature map's) is registered; every other one, hand-written route or page path, must be on the test's `UNREGISTERED` list, held in the test file (no list file). Its ceiling is today's count less the paths moved out; the test fails on an unlisted path or a list past the ceiling. A path that moves into the registry leaves the list, and the ceiling falls with it.
  - **Command table** (`tests/command-table-registry.test.ts`): every entry has a capability (`schedule <verb>` is `schedules.<verb>`) or is on its exceptions list, which names only entries with no capability.

- **Each capability is declared once, and its route, OpenAPI document, typed client and feature map come from that declaration (new decision, 2026-11-26, phase 1 of 3 of local-task-tk_c6ba6e00-9024-4701-b9b6-24adb4fb8cdb; current).** Before, every dashboard route had its own hand-written handler, wired by hand in `src/ui/read-routes.ts` and `src/ui/write-routes.ts`, and the page's routes and client were kept by hand in `web/src/api.ts` and `web/src/api/`. The schedules and items routes moved in phase 2, their page calls in phase 3; every other route stays as it was.
  - **Declaration** (`src/api/registry.ts` `declare`): an id (`<area>.<name>`), its area, a description, a permission (`read` or `owner`), a method (`GET` or `POST`), a path under `/api/v1/` (outside the feature map's), an input and an output schema, and its run. A run returns its answer or `refuse(status, error)`. The permission is declared only in this phase: the existing guards are the only ones enforced.
  - **Schemas** (`src/api/schema.ts`, owner answer 1): an in-repo helper, no schema library and no new dependency. `string`, `integer`, `number`, `boolean`, `oneOf`, `array`, `object`, `nullable`, `optional` and `jsonObject`; each gives the input check, the output render, the JSON Schema and the TypeScript type. An object refuses an undeclared input field and leaves an undeclared output field out. A nested object may be typed only as a JSON object (owner answer 3): the items output schema (`src/api/schemas/items.ts`) types the answer's and each row's top-level fields and every nested object as a JSON object.
  - **Finding the declarations** (owner answer 2): a checked-in index, `src/api/index.ts`, imports every declaration file in `src/api/capabilities/`. `tests/api-registry.test.ts` fails while a file is not imported or an import has no file.
  - **Routes.** One `READ_ROUTES` entry, after the others and before `api.ts`'s paths, answers the feature map and every GET capability (input from the query parameters); one `WRITE_ROUTES` entry, last, answers every POST capability (input from the JSON body) behind the same guards as every write route, in the table's order: Origin, Content-Type, CSRF token (the pauses token: the owner's writes), body size, then the capability. `POST_ONLY` names the registry's routes. A bad input is a 400 before the run; an answer that does not match its output schema is a 500. Every string a capability answers, nested JSON objects and a refusal's text too, goes through the `Withholder`; a `oneOf` word, the code's own, does not.
  - **Feature map** (`src/api/feature-map.ts`): `GET /api/v1/feature-map/areas` (each area with its capability ids), `/api/v1/feature-map/capabilities` (id, area, description, permission, method, path) and `/api/v1/feature-map/capabilities/<id>` (one, with its input and output JSON Schemas; 404 for an unknown id). Its text is the declarations', so it needs no Withholder.
  - **Generated files.** `npm run gen:api` (`scripts/gen-api.mjs`, Node's type stripping, no build) writes `docs/api/openapi.json` (OpenAPI 3.1) and `web/src/api/generated.ts` (per capability its input and output types and one call through `web/src/api/client.ts`). `tests/api-openapi.test.ts` and `tests/api-registry.test.ts` fail while either differs from what the declarations generate, so a schema changed without regenerating fails; the generated client is typechecked by `npm run typecheck` and, for the fixture, in the test.
  - **Headless first** (`AGENTS.md`): stated in the phase 3 decision above.
