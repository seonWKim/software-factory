# 8. Enterprise: interfaces, environments, auth and audit

- **One owner, many workers (new decision, 2026-11-11, owner decision; current).** The decision that changed: **the factory serves one person, its owner**, instead of being built for both a solo developer and an enterprise team of many people. The owner may run many workers (processes, replicas, machines) on one store; identity comes from the environment (git `user.email`, then the OS user, then `anonymous`). Solo and many workers follow the same rule: one owner either way.
  - **Goes:** every mechanism whose only reason is another person: roles, grants, local users, per-person permissions, linked accounts for several people, shared budgets between people, a team store. Removed by #576 phase 3 (wi_3bb50eea9fda47638735d4b569f55b1e): the shared team store ([factory-store.md](../plugins/factory-store.md)) and its test database ([test-database.md](../plugins/test-database.md)). Removed by #669 (phase B of #575, 2026-11-13), after #668 made one owner check decide every command: the auth plugins `github`, `local` and `none` and the whole GrantSource interface with its `github-permission` and `static` grants; the owner check is the only AuthProvider ([auth-provider.md](../plugins/auth-provider.md)). Removed by #577 (phase 2 of #568, 2026-11-13): the roles and local users, `factory users`, `factory setup --me` and the Users API; the store keeps one owner row ([08-permissions.md](08-permissions.md)).
  - **Stays:** every mechanism whose reason is another process: claims, leases, fencing, conditional updates in the store, idempotent handlers, bus partitions.
  - **Kept as they are:** the guards G1 to G6 (`docs/architecture.md` §5); the run passport (agents' tool calls are checked against the run's item, branch and tools, [08-permissions.md](08-permissions.md)); the owner's merge for changes to the factory's own gates, prompts, permissions or tools, whatever the tier; per-project settings that may only tighten a gate ([08-settings.md](08-settings.md)); and the GitHub App and token credentials (`GITHUB_APP_ID` or `GITHUB_TOKEN`, held only by tools).
- Every infra layer is an interface with local + cloud backends: store, **sandbox**, secrets, shared storage, search, **auth**, **LLM provider** (`LLMProvider`; first impl: Anthropic, transports: Claude Code CLI on subscription locally → API / company ML gateway; other vendors or self-hosted later) and **agent runner** (`AgentRunner`; first impl: `claude -p`). Local first.
- Environments labeled by humans: test → DB data may reach the model; prod → blocked at the model interface.
- Tools/MCP (decision changed 2026-11-11, issue #588; current): the owner adds them with `factory pack add <path>`. Each descriptor passes the egress, credential-leak and tool-poisoning scans or is refused naming the rule; a passing one is stored as `pending` with only its credential's name, never its value, and nothing starts it. Approval, grants and rules scoped to the tool are later phases ([11-packs.md](11-packs.md)).
- AuthN/Z behind the `AuthProvider` interface (`resolve`, `authorize`), called by intake, tool wrappers and the human gate. Its one implementation is the owner check ([08-permissions.md](08-permissions.md)): the store's owner may act, anyone else may only file work. Agents act under run passports, narrowed to the run's item, branch and tools.
- Audit: IDs, never display names, on every record: the requester, the agent role, the approver; every owner-check and passport decision is one `authz_audit` row.
- GitHub identity: one bot identity per agent role (triage / implementer / reviewer); requester ID in the PR; approver from the PR review.
- Auth best practices applied: deny by default; least privilege; agents cannot edit who they act as; delegated tokens (run passports) short-lived and scoped; a logged break-glass path for incidents.
