# 9. Status page: dashboard evals page

- **A skill's evals page shows Trend, Grid and Compare, read only (new decision, 2026-11-23, local-task-tk_3c92ecdb phase 1; current).** The decision: **a page at `/app/evals/<skill>`, where `<skill>` is the suite's `skill_ref`, URL-encoded, that shows how the skill did run by run.** The page is reached by its URL only: it is not in the sidebar, and no other page links to it yet (phase 2). `evalsRoute` (`web/src/pages.ts`) parses the path and `App.tsx` renders `EvalsPage` (`web/src/views/evals.tsx`) as it does the transcript; the sidebar marks no page as current. The reads are the existing `GET /api/v1/evals/<skill>/runs`, `/grid` and `/compare?a=&b=` ([06-measurement.md](06-measurement.md)), typed in `web/src/api/evals.ts`, polled every 30 seconds (compare is read only while both runs are picked). Nothing is written and no control starts a run: **there is no Run now**; the CLI's `factory eval run` stays a dashboard gap, filed as a follow-up issue.
  - **Layout.** One `PageHeader` (the skill's name, its folder name from the `skill_ref`: `skills/review-plan/SKILL.md` shows "review-plan"; width `wide`), then three `Card`s in one flex column with `gap-6`, in this order: Trend, Grid, Compare. Loading shows `Loading`, a failed read `ErrorNote` with a fixed sentence (its default text would carry the skill's URL), no runs `EmptyState` ("No runs yet").
  - **Trend.** "Pass rate over time": the new `Chart` (`web/src/components/ui/chart.tsx`, [design-system/components.md](../../design-system/components.md) "Chart") with one bar per run, oldest first, height the pass rate over 1. A run with no pass rate is skipped. Every bar is also a sentence ("Nov 20, 12:00: 90%").
  - **Grid.** "Latest run per version and model class": a `DataTable`, one row per skill version, one column per model class (cheap, standard, strong, then others by name). A cell is the newest run of that pair: a `Badge` with its pass rate (tone from its status, `succeeded` or `failed`) and its date. A pair with no run shows the text "no run". A skill version is a hash, so it is named by age: the first version the skill had is "Version 1", the next "Version 2"; a run with no recorded version is "Version not recorded".
  - **Compare.** "Compare two runs": two `Select`s (First run, Second run) and one `DataTable` with the run date, model class and pass rate of both, then the gap (second minus first, in points), the noise band and whether the gap is within noise (Yes or No). Without two pass rates the table says "Not enough replays to say". The pickers list the runs that have a pass rate, as "date, model class, pass rate"; the run ID is only the option's value. It starts on the two newest runs with a pass rate, the older as First run. With fewer than two such runs the card says so and shows no picker.
  - **Plain words.** The page shows the skill's name, run dates, model classes and pass rates. No run, suite or skill ID, hash or snake_case name appears in its text; its text is in `web/src/i18n/en/evals.ts`.
