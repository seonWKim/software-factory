# 9. Status page: dashboard Routines page

- **The row menu has Pause or Resume, and the detail card has next run and suggestions (decision added 2026-11-24, local-task-tk_956892cd phase 3, phase 4 of 4; current; replaces the menu list "Run now, Edit, Delete", the detail card list and the paused Notice text, see [history/09-dashboard-routines.md](history/09-dashboard-routines.md)).** The "⋯" menu reads Run now, Edit, Pause or Resume (whichever applies; `routines.pause` or `routines.resume`), Delete; Pause posts `/api/v1/routines/pause` and Resume `/api/v1/routines/resume` through the page's one write, as the Switch does. The detail Card lists Next run (the table's wording, one helper `nextRun` for both), Last run, then the instruction, page, time zone and the two caps, and under them a read-only `DataTable` of the routine's suggestions (`GET /api/v1/routines/suggestions?routine=<id>`, the id through `encodeURIComponent`, read by `useRoutineSuggestions` in `web/src/api/routines.ts`; its key starts with the routines path, so a write rereads it). It shows each suggestion's text and state and no ID; with none it shows "No suggestions yet.". Accept, dismiss and snooze are not built. A paused routine's `Notice` (tone warn, role alert) reads "This routine is paused, so no run is due. Choose Resume to run it again." All labels are in `en/routines.ts`.
- **Repeats in plain words, the selected row marked as DataTable's current row, and a Dialog whose buttons stay in view (decision added 2026-11-24, owner UI review of the Routines page; current; replaces the Routine column's ghost `Button`, the raw Repeats words and "below `sm` the Dialog scrolls", see [history/09-dashboard-routines.md](history/09-dashboard-routines.md)).** **Repeats** reads in plain words (`repeatsText` in `routines/labels.ts`, every word a key of `en/routines.ts`): an interval in the largest unit that divides it evenly ("Every 4 hours" for 240, "Every 2 days" for 2880, "Every 90 minutes", "Every hour"), a weekly cadence with its day names in week order joined with "and" and the time after "at" ("Weekly on Mon and Fri at 09:00", "Weekly on Mon, Wed and Fri at 18:30"), a daily one "Every day at 09:00"; a cron rule, or a spec the words cannot read, shows as written ("Cron 0 9 * * 1"). The cell is plain text. **Selecting a routine** uses `DataTable`'s `select` (design-system/components.md "DataTable"): the name is a plain text button (`font-medium`, underlined on hover, `aria-pressed`, 28 px tall and pulled up 4 px) whose text sits on the line of the other cells, and the selected row is `current` (`aria-current="true"`, `surface-2` fill and a 2 px `nav-active` bar at its start, like the current sidebar link); the row keeps its height. The name column takes the room Repeats and Next run leave (both stay on one line) and is cut with an ellipsis; the detail Card has it whole. **New routine and Edit** use the shared Dialog, whose body scrolls between the title and the footer, so Cancel and Add routine stay in view at 390 px (design 09-dashboard-components).
- **A row's menu has Run now first (decision added 2026-11-24, local-task-tk_956892cd phase 3 of 3; superseded in part by the Pause or Resume decision at the top; replaces the "Not built here" mention of Run now, see [history/09-dashboard-routines.md](history/09-dashboard-routines.md)).** The "⋯" menu reads Run now, Edit, Delete. Run now (`routines.run`, action `routine run`) posts `POST /api/v1/routines/run` with the row's id through the page's one write, so the list is reread after it and a refusal shows in the same `Notice` (tone bad) above the table. It is off while the routine is paused or is an On merge routine (`schedule` null), as the server refuses both, and while the session token is unread, as the Schedules page's Run now is off while paused. No change to the layout, the Detail card or the Dialogs.
- **The Routines page lists routines with a Switch and a row menu, shows the selected one in a detail card, and creates, edits or deletes one in a Dialog (decision added 2026-11-24, local-task-tk_956892cd phase 3, phase 1 of 2; current; replaces none).** `web/src/views/routines.tsx` (the Dialogs in `web/src/views/routines/form.tsx`, the catalog keys of each word in `routines/labels.ts`), route `/app/routines`, `PAGES` entry `routines` (icon Repeat, group `system`, after Health), text in `web/src/i18n/en/routines.ts` and `page.routines` in `en/shell.ts`. The page calls the routes of [08-routines.md](08-routines.md) through `web/src/api/routines.ts`; it changes no route and no core function.
  - **Layout (the owner's sketch A: a table with a detail card).** `PageHeader` (title Routines, a one-line description) with one primary action, New routine. Under it two Cards, siblings after the header spaced by the Card's own top margin as on Health and Settings (a flex gap on top of it doubled the space, fixed 2026-11-24): the routines, and the selected routine's detail. With no routine there is only the first Card, with the table's empty state; the detail Card is not drawn. The design-system "Stays fixed" list is kept; no raw ID or user ID is shown (a new routine's ID is made from its name by `newScheduleId`, never shown).
  - **Routines Card.** A `DataTable` (`GET /api/v1/routines`, polled, oldest first) with the columns Routine (selects the row, see the Repeats decision above), Repeats (plain words, see that decision; "On merge" for the trigger form), Next run (never empty: "Paused" for a paused routine, "After the next merge" for a running trigger routine, since below `sm` each row is a card that shows the label anyway), On and a "⋯" `OverflowMenu` (Run now, Edit, Pause or Resume, Delete). **On** is a `Switch`, on while the routine is not paused; it posts `/pause` or `/resume`. A refusal of any write (the core's reason, the owner check) shows in one `Notice` (tone bad) above the table; controls send nothing while the session token is unread or a write is in flight.
  - **Detail Card.** Titled with the selected routine's name, else "Routine" with "Select a routine to see its details." It lists next run, last run, the instruction, page, time zone and the two caps, then the read-only suggestions list. A paused routine shows a `Notice` (tone warn) above them.
  - **New routine and Edit.** One `Dialog` (`RoutineDialog`): Name, Instruction, Page URL, Repeats (interval, daily, weekly, cron, or On merge), When (the cadence's spec; hidden for On merge), Time zone, Run cap USD and Daily cap USD (blank is none). From `sm` up, Repeats and When share a row, and so do the two caps, so the form fits a 1280x800 window with its buttons in view; below `sm` each field has its own row and the Dialog's body scrolls under its fixed footer. New posts `/add` with every field; Edit posts `/edit` with only the changed fields (a changed Repeats or When sends `schedule` and `trigger` together, the unused one null) and closes with no request when nothing changed. A refusal stays in the Dialog with its reason.
  - **Delete.** A confirmation `Dialog` (danger) naming the routine; `/delete` posts only on its confirm.
  - **Not built here.** Accept, dismiss and snooze of a suggestion; Run now for trigger routines.
