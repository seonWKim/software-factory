- **The Routines page lists routines with a Switch and a row menu, shows the selected one in a detail card, and creates, edits or deletes one in a Dialog (decision added 2026-11-24, local-task-tk_956892cd phase 3, phase 1 of 2; current; replaces none).** `web/src/views/routines.tsx` (the Dialogs in `web/src/views/routines/form.tsx`, the catalog keys of each word in `routines/labels.ts`), route `/app/routines`, `PAGES` entry `routines` (icon Repeat, group `system`, after Health), text in `web/src/i18n/en/routines.ts` and `page.routines` in `en/shell.ts`. The page calls the routes of [08-routines.md](08-routines.md) through `web/src/api/routines.ts`; it changes no route and no core function.
  - **Layout (the owner's sketch A: a table with a detail card).** `PageHeader` (title Routines, a one-line description) with one primary action, New routine. Under it two Cards, siblings after the header spaced by the Card's own top margin as on Health and Settings (a flex gap on top of it doubled the space, fixed 2026-11-24): the routines, and the selected routine's detail. With no routine there is only the first Card, with the table's empty state; the detail Card is not drawn. The design-system "Stays fixed" list is kept; no raw ID or user ID is shown (a new routine's ID is made from its name by `newScheduleId`, never shown).
  - **Routines Card.** A `DataTable` (`GET /api/v1/routines`, polled, oldest first) with the columns Routine (a ghost `Button` that selects the row), Repeats ("Every day at 09:00", or "On merge" for the trigger form), Next run (never empty: "Paused" for a paused routine, "After the next merge" for a running trigger routine, since below `sm` each row is a card that shows the label anyway), On and a "⋯" `OverflowMenu` (Edit, Delete). **On** is a `Switch`, on while the routine is not paused; it posts `/pause` or `/resume`. A refusal of any write (the core's reason, the owner check) shows in one `Notice` (tone bad) above the table; controls send nothing while the session token is unread or a write is in flight.
  - **Detail Card.** Titled with the selected routine's name, else "Routine" with "Select a routine to see its details." It lists the instruction, page, time zone, last run and the two caps. A paused routine shows a `Notice` (tone warn) above them.
  - **New routine and Edit.** One `Dialog` (`RoutineDialog`): Name, Instruction, Page URL, Repeats (interval, daily, weekly, cron, or On merge), When (the cadence's spec; hidden for On merge), Time zone, Run cap USD and Daily cap USD (blank is none). From `sm` up, Repeats and When share a row, and so do the two caps, so the form fits a 1280x800 window with its buttons in view; below `sm` each field has its own row and the Dialog scrolls. New posts `/add` with every field; Edit posts `/edit` with only the changed fields (a changed Repeats or When sends `schedule` and `trigger` together, the unused one null) and closes with no request when nothing changed. A refusal stays in the Dialog with its reason.
  - **Delete.** A confirmation `Dialog` (danger) naming the routine; `/delete` posts only on its confirm.
