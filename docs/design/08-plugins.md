# 8. Enterprise: plugins, GitHub login, secret names, keep awake

- **Plugins (D6, decided 2026-11-01):** every implementation of an infra interface is a named plugin, selected by name in `factory.config.json` and built only through the registry in `src/plugins.ts`; `build()`, setup/doctor and the G6 canary all resolve through it. Unknown names fail at startup. The guards (`SecretStore`, `EgressScanner`, `ToolBroker`; architecture §5) can be switched to another plugin but never disabled: config that selects none fails at startup. No external plugin loading. This changes how D3's store choice and the `auth` key are described: `store.type` and `auth` are now the plugin names for `FactoryStore` and `AuthProvider` (same keys, same values); the other interfaces are under `plugins`. Catalogue: `docs/plugins.md`.
  - **Discovered registry.** Each plugin is now a `*.plugin.ts` descriptor beside its implementation, built with `definePlugin` (`src/plugin-api.ts`, kept out of `src/plugins.ts` so descriptors do not import the module that is importing them). At startup the loader in `src/plugins.ts` finds every `*.plugin.js` under the built `impl/` (`*.plugin.ts` in the source tree, never `*.d.ts`), sorts by path, imports and registers each; `REGISTRY` is filled by top-level await. Defaults and declared secrets moved into the descriptors. Startup fails on an unknown kind, a duplicate name within a kind, a non-guard `plugins` kind without exactly one default per platform, or a guard kind with no plugin; errors name the files. `src/plugins.ts` names no plugin; only a new interface edits it. Discovery is in-repo only (no npm packages, no hot-loading). `npm run build` empties `dist/` first so a deleted descriptor cannot stay registered.
- **GitHub login is a plugin.** `GitHubCredentials` (`plugins.github_auth`) supplies the token to the shared REST client and the broker's push, the only two callers. `token` keeps the personal token; `app` signs a JWT with the GitHub App's key (`github-app.pem` next to the secret file, `GITHUB_APP_ID` in it) and uses an installation token limited to the one repository, cached until 5 minutes before expiry. The checked-in config selects `app`. `doctor` checks an App's permissions from the mint response, since GitHub's repo `permissions` field does not describe installation tokens. `factory issue` (create / comment / title / sub-issue, each egress-scanned) lets the owner's terminal post as the bot too; closing and merging stay human.

- **Declared secret names.** Secret names are declared by plugins, not a closed union. `SecretName` is a branded string built only by `secretName()` (upper-case letters, digits, `_`, starting with a letter). Each plugin's descriptor (`*.plugin.ts`, since the discovered registry above) lists the names it reads with a one-line purpose; the secret set is the union for the selected plugins, and the `env-file` store loads, returns and scans only that set. Plain settings in the same file (`MYSQL_HOST`) and undeclared keys stay out of `get` and out of the G5 scan set. A declared secret missing from the file does not fail startup; `doctor` reports it and `setup` asks for it. Guards G1–G6 are unchanged. Catalogue: `docs/plugins.md`.
- **Keep awake (decided 2026-11-01):** a new `KeepAwake` interface (`hold` / `release`, plugin kind `awake`, config key `plugins.awake`, not a guard). The worker holds it only while a claimed run executes, never while idle. Plugins: `caffeinate` (macOS, `caffeinate -i -s -w <pid>`) and `none`. **The default depends on the platform:** `caffeinate` on `darwin`, `none` everywhere else, so the checked-in config leaves `awake` out. Selecting `caffeinate` on a host without the executable fails at startup. A failed hold only logs a warning; the job still runs. Lid close still sleeps a Mac; the host-sleep lease rules (§5) cover that case. Catalogue: `docs/plugins.md`.

## History

- **Discovered registry** (D6 changed 2026-11-01). Before: `src/plugins.ts` imported every implementation and listed every plugin name, and `tests/plugins.test.ts` repeated the list with a fixed count, so every plugin PR conflicted on the same lines.
- **GitHub login is a plugin** (new decision, 2026-11-01). Before: every GitHub call read `GITHUB_TOKEN` directly, so everything the factory wrote showed the owner as author.
- **Declared secret names** (decision changed 2026-11-01). Before: `SecretName` was a closed union in the guarded `SecretStore` interface, repeated as a fixed list in the `env-file` plugin, so a new secret meant editing guarded code.
