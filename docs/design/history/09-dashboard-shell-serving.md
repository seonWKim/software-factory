## History

- **The classic page's removal, in full** (moved here 2026-11-20 from the app-only decision in 09-dashboard-shell.md, for the topic size cap; not a changed decision). `src/ui/pages.ts` and `src/ui/merge-digest.ts` are deleted. `src/ui/html.ts` is only the error page shell (404 and the other HTML errors outside `/api/v1` and `/app`): the status, one message and a home link to `/app/`, one inline style allowed by hash, and no script (the 5 s refresh script and the "updated N s ago" bar are gone). Outside `/app` the CSP is `default-src 'none'; style-src '<hash>'; form-action 'none'; base-uri 'none'; frame-ancestors 'none'`, so no script runs. `src/ui/health.ts` keeps `HealthMonitor.report` and `syncChecks`; `src/ui/github-budget.ts` keeps `readGitHubBudget`, which the overview reads. The tests that rendered the classic page check the same behaviour through the JSON API.

- **Where the responsive check runs** (moved here 2026-11-19 from the responsive check decision in 09-dashboard-shell.md, for the topic size cap; not a changed decision). CI runs it as the `responsive` job of `.github/workflows/test.yml` on every PR and push to main (the workflow has no path filters; a change outside `web/` can change what the API returns); it is not in `repo.check_commands`, since the factory's sandbox has no browser; set as `repo.ui_check` it runs in the merge queue's merge-check run on the merged commit of a change touching `web/` or `src/ui/`, and a failure keeps the base where it was (04-pre-push-gates.md, 2026-11-12); `.claude/agents/ui-reviewer.md` runs it first.

- **The responsive check's full rule list** (moved here 2026-11-19 from the responsive check decision in 09-dashboard-shell.md, for the topic size cap; not a changed decision). It fails on (`scripts/responsive/rules.mjs`): the page scrolling sideways; a visible element or its own text ending past the right edge outside a sideways scroll container; text breaking inside a word in a box narrower than 12ch; a fixed or sticky element covering more than 40% of the viewport height; an open dialog, popover, menu, listbox or tooltip past the viewport; content taller than the viewport with vertical overflow hidden on html or body; and (decision changed 2026-11-12, see History) any console message of level error, error-level log entry (a CSP violation), failed request or 4xx/5xx response the page records since its load or the previous size (`scripts/responsive/console.mjs`, fed by `cdp.mjs`, which enables the Log domain; a request cancelled by the next navigation does not count, warnings do not count, and a 4xx a page's seeded state expects is listed in `EXPECTED_HTTP_ERRORS` with a one-line reason instead of loosening the rule).

- **The responsive check's launch retry and first run** (moved here 2026-11-19 from the responsive check decision in 09-dashboard-shell.md, for the topic size cap; not a changed decision). A launch that does not open its DevTools port within 30s on CI, 15s locally, is killed and retried with a fresh profile up to twice, and the final error gives Chrome's exit status and the last 20 lines of its stderr. The first run fixed: card cells keep no `whitespace-nowrap` (a worker id ran off a 390px card), the item title and system actions break long words, the claim pause time wraps, object values in Settings keep a 10ch value column, and the Runs table's kind column keeps a minimum width.

- **A server-rendered page beside the app at `/classic` and `/items/<id>`** (until 2026-11-16, the app-only decision at the top). Before: `/classic` served the server-rendered status page (`src/ui/pages.ts`: the factory banner, open alarms, GitHub API, Running now, Queue, Paused, the filter form, the ranked items, Health with Run now, the improve report, Totals, Merges and Cost) and `/items/<id>` its item page; an inline script, allowed by hash, refreshed them every 5 s under an "updated N s ago" bar, the Run now script added its own hash to the CSP, and the error pages shared that shell with a home link to `/classic`.

- **Server revision = folder git HEAD** (decision changed 2026-11-13). Before: `server_rev` was `git rev-parse HEAD` of the UI server's code root, so after a docs-only update moved the checkout without a build it differed from the page's built-in revision and the "Dashboard out of date" banner showed with advice that could not clear it.

- **The responsive check ignored the console** (decision changed 2026-11-12). Before: `check:responsive` looked only at layout; `cdp.mjs` did not enable the Log domain or record console output, so the two console errors per page from the refused favicon (app CSP `default-src 'none'; script-src 'self'; style-src 'self'; connect-src 'self'; form-action 'self'; base-uri 'none'; frame-ancestors 'none'`) never failed it.

- **No automated responsive check** (decision changed 2026-11-10). Before: only the ui-reviewer agent looked at other widths, by hand, at 1280px and 390px wide, and no check ran on a PR, so changes made without a browser (background agents, the factory's own PRs) could break a narrow or short window unnoticed.

- **No improve run from the dashboard** (decision changed 2026-11-10, issue #508). Before: the dashboard had five write routes and no way to start an improve run; the Health panel was read-only and every classic page allowed exactly one script by hash.

- **Revisions, system actions and the tab title** (decision changed 2026-11-07, issue #311). Before: the overview returned only the supervisor's revision (`factory.rev`), the web build had no revision built in, so a tab or a page server on old code was not shown; `needs_you` counted only human-blocked and deadlocked items; the tab title had no count.

- **Where `/` goes** (changed 2026-11-07). Before: `/` served the server-rendered page and the app was only at `/app/`, with placeholder pages.

- **The dashboard is read-only** (decision changed 2026-11-07, issue #236). Before: the JSON API answered only `GET`/`HEAD` ("Read-only JSON API"), and the Settings page was read-only, pointing at `factory settings`. Now `POST /api/v1/settings` is the one write route and the Settings page edits and resets settable keys.

- **PR link in the API** (decision changed 2026-11-07, issue #240). Before: `pr_url` was built from the stored project key (`github:host:id`), giving a malformed host; now it is built from the stored label, as the classic page already did.

- **Serving `/app/`** (moved here 2026-11-20 from the dashboard app decision in 09-dashboard-shell.md, for the topic size cap; not a changed decision).
files from `web/dist`; any other path gets `index.html` (client routing), except a missing file under `assets/`, which is a 404. A path that decodes to `.`/`..`, a slash, a backslash or a NUL, a dotfile, or a file whose real path is outside `web/dist` is a 404. No built app: 503 "run npm run build", and `/` keeps working. Its own CSP: `default-src 'none'; script-src 'self'; style-src 'self'; img-src 'self'; connect-src 'self'; form-action 'self'; base-uri 'none'; frame-ancestors 'none'` (`img-src 'self'` since 2026-11-12, for the favicon, see `09-brand-and-tokens.md`; no `unsafe-inline`, no hash; so no inline `style=` attributes in the app either). Same Host and method guards (errors as text). The app's fetches go only to `/api/v1/*`; it polls every 3 s while the document is visible, and its light/dark choice stays in the browser.
