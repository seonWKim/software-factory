## History

- **Stall clock ignored background tasks; a stalled run's tail went unscanned** (decision changed 2026-11-20, "Stalled runs": background tasks and the kept tail). Before: only an open tool call or a gate Stop check stopped the clock, so a check started with `run_in_background` (its tool call returns at once) left the model waiting idle with the clock running; all nine resolve stalls of 2026-11-19/20 (16:12, 16:39 ×2, 18:51, 19:39, 20:10, 22:35, 23:14, 23:23 UTC) named `stall_ms` and killed a running `Run full test suite` task. The stalled outcome's `output_tail` was scanned only as part of the whole outcome, so a flagged tail turned the run into `egress_blocked`. Also dropped from the paragraph: a test suite longer than `stall_ms` used to end every finished implement run as `stalled` before the Stop-check hold (2026-11-09).
- **Every stall paused every claim** (decision changed 2026-11-20, "A stall pauses every claim only when no running run got model output within `stall_ms`"). Before: the worker set the global `model_stall` claim pause for every `agent_stalled` run, before it stored the outcome, whatever the other running runs were doing; the store had only `updated_at`, which the heartbeat rewrites, so nothing told one silent run from a silent model. On 2026-11-19 (16:12 and 16:39 UTC) a resolve run's stall paused every claim for about 10 minutes each time while other runs were printing output.
- **Gate Stop-check time counted against the run timeout** (decision changed 2026-11-20, "Gate Stop-check time does not count against the run timeout"). Before: the claude-code runner gave the whole `claude` process one `timeout_ms`, Stop checks included, so a finished run whose Stop check ran long was recorded as `agent_timed_out`.
- **Background and rollout notes moved here** (2026-11-20, to keep the topic file under its size cap with the stall decision of that day; the decisions themselves are unchanged). "A failed run's outcome always lands": An implement run's `spec_conflict` at the revision limit moves the item RUNNING → READY (`max_revisions`); the WorkItem state table had no such edge, so the transition was refused, the run stayed unacknowledged, was re-applied and refused on every tick, and the item sat RUNNING with nothing queued (`/retry` found no failed run). "A base merge conflict keeps its commits on the wip branch": Before, a `merge_conflict` at sync before push kept nothing, so the automatic retry built the whole change again: 10 such runs in 48 hours took 346 minutes and $21.9 (35 minutes each on average), where a resolve run takes about 14. "An invalid implement answer gets one repair turn": Why: a run that had finished its change was thrown away for a badly shaped final answer (23 such failures since 2026-11-07, two of them after about 11 minutes of finished work). "Stalled runs", who probes: its old model_stall-only form, `takeStallProbe`, was removed 2026-11-08 (below). "Stalled runs", Stop check (2026-11-09): the agent prints nothing while its Stop hook runs the check commands, and a test suite longer than `stall_ms` used to end every finished implement run as `stalled`, pausing all claims each time. Any live controller probes so that a drained child no longer leaves the pause unprobed. "Once the probe answers": a stall pattern after a host sleep holds nothing since no fix item is filed for it to release its items. "A stall pauses every claim only when…" (2026-11-20): rollout: stop old workers first. "wip branch and resume": the wip branch lives on the forge, not a local ref, since the retry can run on another host.
- **Rollout notes moved here to keep the topic file under its size cap** (2026-11-20). Stopped runs keep their work (2026-11-07): stop every old worker first; an old worker reads a `continue` wip ref as a push retry and would push the half-done branch with no agent run. A base merge conflict keeps its commits (2026-11-18): stop every old worker before the new code runs, since an old worker reads a resumed run with a conflict as a plain failure.
- **Takeover-cancelled runs counted as attempts** (decision changed 2026-11-19, "A run cancelled by an accepted interactive takeover is no attempt"). Before: `Sessions.start()` cancelled the queued implement and update runs in its own transition (reason `interactive_takeover`) before `startSession` checked for an open session, a running implement-type run or an overlap, so a refused start (another item's running run overlapping the allowed_paths) still cancelled them; the cancelled runs had no outcome and counted toward `max_attempts`. Three items went to the `max_attempts` hold this way on 2026-11-19 (wi_90dc9814, wi_bdd36b09, wi_ca3ff607) and were left as they were.
- **Rollout notes of the 2026-11-02 retry changes** (moved here 2026-11-19 to keep the topic file under its size cap; the rollouts are done). Rollout: an old worker ignores `not_before` and the pause, so stop every worker before the first new controller starts, then migrate and start the new code everywhere. **Rollout of the 2026-11-02 changes (preflight, forge-auth pause, wip resume, no automatic retry of the four codes):** stop every old worker first, then start the new code everywhere. An old worker ignores the `forge_auth` pause row (it would claim implement and update runs during a pause) and ignores a retry's `wip` input (it would run the agent again). No migration is needed.
- **Invalid implement answers failed at once** (decision changed 2026-11-18, "An invalid implement answer gets one repair turn"). Before: an implement answer that did not match the output schema failed the run with `invalid_output` at once, and its commits went with the run folder, so the retry started the work again from the base.
- **A resumed run's base merge conflict** (decision changed 2026-11-18, "A base merge conflict keeps its commits on the wip branch"). Before: on a resumed run a base merge conflict failed with `merge_conflict` at once, with no agent step; and a `merge_conflict` kept no commits on a wip branch, so its retry ran the implement agent again from the base.
- **Every held stall pattern had a fix item** (decision changed 2026-11-15, the host sleep exception in "Once the probe answers, a stall pattern holds only its items"). Before: every known stall pattern of two or more runs held its items, and the doc said a held item always has a pattern the improver files a fix for; a stall pattern caused by a host sleep, which now files no fix, would have held its items forever.
- **Failed run outcomes** (new decision, 2026-11-11). Before: a failed run's decision the WorkItem state table refused was dropped with a warning and retried on every tick, and nothing found an item left RUNNING with no run to move it.
- **`model_stall` scope** (decision changed 2026-11-10, issue #504). Before: a passing probe only ended the pause, so an item whose runs stalled again on every retry paused all claims each time (on 2026-11-09, one pattern held every item for about four hours).
- **`auth_pause_ms` is read from the config file** (gap closed 2026-11-09, RFC 0010 item 8). Before: `src/compose.ts` did not pass `auth_pause_ms` to the core config, so the forge-auth and preflight-access pauses always lasted `retry_max_ms` whatever the file said. Now: it is validated with the other retry keys and carried into the core config.
- **A push or PR that fails is outbound's retry** (decision changed 2026-11-09, RFC 0015 M7). Before: the broker's `github.push_branch` and `github.open_pr` ran in the run, so a push or PR failing on the network, a rate limit or refused credentials failed the run (`network_unavailable` requeued it, `github_rate_limited` and `forge_auth` set a claim pause and kept the commits on a wip branch).
- **`takeStallProbe` removed** (2026-11-08). Before: `FactoryStore.takeStallProbe(due, next)` stayed as a deprecated wrapper of `claimProbe("model_stall", due, next)` that no source file called. Now: its two store contract tests call `claimProbe("model_stall", …)` and the method is gone from `FactoryStore` and the SQL store.
- **Stall probe ownership and the next probe time** (decision changed 2026-11-07). Before: each tick every controller that read a due `model_stall` pause called the model, so several replicas made one call each for the same due time; an answer wrote `model_answered` = now through `pauseClaims`, and `endClaimPause("model_stall")` wrote it at the probe time even when that was still ahead, so a stall before it started no pause; and the health line showed only the start time (`since <time>`), not the next probe.
- **Stopped runs keep their work** (decision changed 2026-11-07). Replaces the part of **wip branch and resume** that kept commits only when the push or PR failed (and of the 2026-11-07 `diff_too_large` decision that only that stop kept them): a run that ended `rate_limited`, `agent_stalled` or `agent_timed_out` lost its run folder and agent sessions, so its retry started from the base; a killed run recorded zero tokens; and the fallback chain fell over on a stall with zero output tokens even after edits.
- **`diff_too_large` keeps its commits on a wip branch** (decision changed 2026-11-07, issue #217). Before: a `diff_too_large` run pushed nothing, so its commits went with the run folder when the run ended; the wip branch was kept only when the push or PR failed, or the checks failed.
- **Which failures pause and which block** (decision changed 2026-11-07, issue #216). Before: a push_access or pr_api check that failed other than with a 401/403 was a plain `preflight_failed` task failure, so one revoked permission cost every queued item its `max_attempts` with no alert; and an infra failure such as `git_failed` that repeated with the same code and detail within seconds was retried up to `max_restart`.
- **Missing toolchain and failure comments** (2026-11-07, issue #229). Before: a run folder without its tools failed as `checks_failed`, ran a fix step that could not help and spent an attempt; failure comments pasted the raw output tail with colour codes.
- **Agent asks a human; same failure twice** (2026-11-07, issue #167). Before: an agent that could not go on had to fail, and identical task failures used every attempt up to `max_attempts`.
- **Restarts** (decision changed 2026-11-01). Before: any failed run set `blocked_on: human` / `run_failed:<kind>:<code>` at once and waited for `/retry`, and the reaper requeued an expired lease with no wait.
- **No automatic retry for deterministic implement failures** (decision changed 2026-11-02, issue #135). Before: only `diff_too_large` blocked at once, and `no_commits`, `scope_violation` and `egress_blocked` were retried up to `max_attempts`, each retry a full agent run that failed the same way.
- **Implement preflight** (new decision, 2026-11-02, issue #135). Before: the agent ran first and a missing push permission showed only at the push, after a full agent run, repeated on every retry.
- **Forge-auth pause** (new decision, 2026-11-02, issue #135). Before: a 401/403 on the push was a plain `push_failed`, on `open_pr` an uncaught `exception`, and both were retried with a full agent run while every other implement run hit the same wall.
- **wip branch and resume** (new decision, 2026-11-02, issue #135). Before: the run folder was destroyed after every run, so the commits of a finished agent step were lost when the push or PR failed, and the retry ran the agent again.
- **Implement preflight, `permissions.push`** (decision changed 2026-11-02). Before: `push: false` failed the check, and a GitHub App installation token reports `push: false` even with contents: write, so every implement run failed the preflight while pushes worked.
- **The alarm step also sets `model_stall`** (decision changed 2026-11-07, design 05-alarms). Before: only a stalled run set the pause.
- **Stalled runs** (new decision, 2026-11-03, issue #176). Before: a CLI that waited without printing held the worker for the whole `run_timeout_ms`, was recorded as `agent_timed_out` (infra, counted toward `max_restart`), and its retry blocked the worker again (2026-11-02: every run from about 15:00 to 23:20 ended this way).
- **Stall rule: only model output restarts the clock** (decision changed 2026-11-07, issue #215). Before: every stdout chunk, system events included, restarted the `stall_ms` clock, and there was no first-output limit, so a run whose model never answered while the CLI printed API retries ended only at `run_timeout_ms` (runs with zero tokens took about 50 minutes each).
- **Abandoned attempts** (new decision, 2026-11-07, issue #210). Before: the reaper logged only `lease expired` with the run id, so a cut-off attempt had a start (`run start`) and no end.
