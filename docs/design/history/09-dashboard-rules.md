## History

- **The 2026-11-13 "Promote of a class encodes the rule" decision as it read in full** (shortened 2026-11-22 to keep the topic file under its size cap; no decision changed). Before: **Promote of a class encodes the rule (decision changed 2026-11-13; current; replaces "promote sends --rule only", see History).** The decision that changed: **Promote of a class on the Rules page does the whole promotion the owner did by hand**, and the factory now writes one file under the agents home. `POST /api/v1/rules/verdict` takes `{ id, verdict, reason, text?, default?, exception? }`: on promote of a class `text` (the wording), `default` and `exception` are required, 1 to 2000 characters each; on anything else they are refused (400), as is any other field. The `agents-home` plugin (docs/plugins/tacit-ledger.md) then checks that `<home>/private/tacit/rules.md` exists and its resolved path (symlinks followed) lies inside the resolved home, that it has no `## <C-id>` heading yet and has the `## 다른 곳에 인코딩된 규칙` heading, and that `bin/sync-agents` is executable, and reads the draft with `evolve show <C-id>` (the owner's sample form: `### C-xxx <title>`, `- 인시던트: …`, `- 초안: 기본값: … / 예외: …`, `- 범위: …`); a failed check or a missing part answers 409 with nothing written and no verdict. Then it writes one block immediately before that heading, followed by a blank line: `## <C-id> <wording>`, `- 기본값: <default>`, `- 예외 (이럴 땐 override): <exception>`, `- 근거: 인시던트 <T-ids joined by ", "> / 판정일 <today, YYYY-MM-DD>`, `- 범위: <the draft's scope>` (each value on one line). Then `tacit verdict <C-id> promote --reason <reason> --rule <wording> --encoded-to private/tacit/rules.md`; if it fails the file is put back byte for byte and the answer is 502 "The ledger refused the verdict: <CLI error>". Then `<home>/bin/sync-agents`; if it fails the block stays (the verdict is recorded) and the answer is 502 "The verdict was recorded, but sync-agents failed: <error>". Reject and Hold, and every proposal verdict, are unchanged and write nothing. **Read:** each entry of `GET /api/v1/rules` adds `judged` (the decision of a `type: "verdict"` line in `<home>/private/tacit/ledger.jsonl` for its ID whose `ts` is newer than `<home>/private/tacit/rule-candidates.md`'s modification time, else null; no view file: none judged), `draft` (`default`, `exception`, `incidents`, `scope` from `evolve show`, for a class not judged) and `draft_error` (why that read failed). **Page:** a judged entry shows "Judged: <decision>" and no verdict buttons until the view is rebuilt (the daily brief at 08:30); a class with a draft error shows it and its Promote is disabled. Promote's dialog of a class holds Rule wording (prefilled with the title), Default and Exception (prefilled from the draft), all editable and required, then the reason; its labels are keys in `web/src/i18n/en.ts`. **Why:** the owner's ledger refuses a promote without `--encoded-to` ("promote requires --rule and --encoded-to"), so every Promote failed and the owner wrote the block, recorded the verdict and ran sync-agents by hand; and an entry judged today was offered again until the next rebuild. Not built: locking the file against the owner's own edits made at the same time, undoing a verdict or sync-agents after they succeed, and reading `AGENTS_PRIVATE`.
