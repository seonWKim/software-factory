Each row of `/api/v1/items` and the `item` of `/api/v1/items/:id` have `merge_check`: `null` for an item that is not ready to merge, else `{ state, conflicts, head_sha, base_sha, checked_at }`. `state` is `mergeable` or `conflicts` from the item's stored result, or `checking` while it has none or while the result is for an older head than the item's recorded `last_head_sha`. `conflicts` are the conflicting file names, each through the `Withholder`. The routes read `listMergeChecks` and `getMergeCheck`, both store reads; the API still never writes and never runs git. **App:** a ready-to-merge row shows `Mergeable`, `Conflicts: N files` (the names on hover) or `Checking…` next to its state; the item page has a Merge check section with the conflicting files, the base sha it was checked against and when. The Merge button reads the item API's `merge` instead, which is disabled while a factory PR has conflicts or is being checked (issue #451 removed `mergeBlocked` from `web/src/api.ts`).
