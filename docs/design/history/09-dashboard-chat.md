- **The chat was a side panel opened by a Chat button in the top bar** (decision added 2026-11-26, local-task-tk_eea9af6d phase 2 of 2; replaced 2026-11-27, owner design feedback "Chat should be extracted as a menu + it should resemble chat GPT UI", the Chat page decision in 09-dashboard-chat.md). Before: **The dashboard has a chat side panel, opened by a Chat button in the top bar, and the Runners tab has a Chat Card (decision added 2026-11-26, local-task-tk_eea9af6d phase 2 of 2; current; replaces none).** Phase 1 declared `chat.send`, `chat.transcript` and `chat.turns` on the API registry ([04-chat-agent.md](04-chat-agent.md), [09-api-registry.md](09-api-registry.md)); this phase is their dashboard. Both parts call the generated typed client (`web/src/api/generated.ts`: `chatSend`, `chatTurns`, `chatTranscript`, `itemsList`) and nothing else: no hand-written `fetch`, no new route (`tests/ui-chat-panel.test.tsx` reads the source for both). The panel only answers: it creates no item and runs no command. Code: `web/src/views/chat-panel.tsx`, texts in `web/src/i18n/en/chat.ts` (key prefix `chat.`).
- **Layout of the side panel** (replaced 2026-11-27, same change). Before: **Layout (owner answer 1, the default accepted).** `ChatPanel` is an `aside` beside the page in the app's flex row, not a modal: the current page stays visible and keeps its place behind it (below `lg` it floats over the page's right edge). Inside, a `PageHeader` (title Chat, a close icon Button), then one `Card` (the page's Card) holding the conversation (`Clamp` paragraphs), a `Textarea` and the primary `Button` Send (⌘/Ctrl+Enter sends too). The Chat button is a ghost icon Button before Refresh's More menu ([09-dashboard-shell.md](09-dashboard-shell.md)); it toggles the panel (`aria-pressed`). The panel stays mounted while closed, so closing it keeps the conversation and its session.
- **Each message carried the open page** (replaced 2026-11-27, same change: the Chat page is the open page, so only an item is named). Before: **Each message carries the open page and item (owner answer 1 of the spec: "What is this?" is about the open item).** `chat.send` takes only `text` and `session_id`, so the panel puts one context line before the message: "Open page: Work." and, on an item page, "Open item: “<title>”, state <state label>, stage <stage>." The title, state and stage are the item's row in the stored items list (`itemsList`, read once per 10 s at send), so the turn can answer "What is this?" about the open item and about nothing else of it. A shown transcript takes the line off again. The model is the Ask model; with none set (`chat.send` answers 503) the panel says chat is off and where to add a model.

A code block (a diff) has no shared component in `design-system/components.md`; until one is added it is a `Card` holding `<pre>` text in `font-mono text-xs`. A table is a `Card` holding a `DataTable`. No Markdown component and no new component is used.
