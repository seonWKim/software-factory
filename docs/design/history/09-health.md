# 09-health

- **Health's header linked the Activity page** (2026-11-26 until 2026-11-27, the Activity tab decision at the top). Before: `HealthPage`'s `PageHeader` had an Activity link to `/app/activity`, a separate page, and every actor other than Schedules linked back to Health from its About card.
- **Health had no link to Activity** (until 2026-11-26, the Activity link decision at the top). Before: the Activity page had no route and Health linked nothing to it.
- **Nine Health tabs** (until 2026-11-24, the four tabs decision at the top). Before: the tabs were Checks, Spend, Failures, Runners, Host sleeps, Merged without review (`?tab=checks|spend|failures|runners|sleeps|merges`), then, shown only with data, Claim pauses, Efficiency, Improve and GitHub budget; each tab drew only its own Card, and the Checks, Host sleeps and Merged without review labels always carried a count ("Checks (22)", "Host sleeps (5)").
- **A host sleep row listed its runs and the keep-awake hint inline** (until 2026-11-24, the compact host sleep row decision at the top). Before: a row read "Computer slept N min at <time>; N workers paused" with its relative time, then, when it held runs, "Runs it held:" with each run's raw work item ID linked and its status, the keep-awake hint under that list, and a Details disclosure with the row's stored entries under every row; `sleepRows` was in `src/ui/api.ts` and the entry had no `work_item_title`.
- **The model credential and sandbox checks showed raw text** (until 2026-11-23, the plain words for credential and sandbox decision at the top). Before: only the status-label checks folded into one row; the credential row read "model credential missing: one of CLAUDE_CODE_OAUTH_TOKEN, ANTHROPIC_API_KEY (run: npm run setup)" with no button, and the three sandbox lines were three warn rows repeating "sandbox reads|writes|network: not OS-enforced, so auto mode is refused (<why>)", the install command and docs URL included.
- **Spend and Failures below every tab; Runners a page of its own** (until 2026-11-22, the tabs decision at the top). Before: the tabs were Checks, Claim pauses (while held), Host sleeps, Merged without review, Efficiency, Improve and GitHub budget, and every tab drew the Spend and Failures Cards below it (`#spend`, `#failures`, which `/app/spend` and `/app/failures` led to), the Failures window switch always in the toolbar; the worker processes and Running now were the hidden Runners page at `/app/runners`.
- **Host sleep rows showed no runs** (until 2026-11-20, the host sleep runs decision at the top). Before: a row said "Computer slept N min at <time>; N workers paused" and nothing about the runs it held; the API entry was `{ worker_id, woke_at, gap_ms, run_id }`, with no work item or run status, and no hint about keep-awake.
- **Health showed the checks' raw text** (until 2026-11-20, the plain words decision at the top). Before: the Checks card said its count three times (tab "Checks (27)", the count beside the title, "27 ok" on the fold) under a "Checked 42s ago" line; the report's `msg` was doctor's line, so Health showed "GitHub: 2566/5000 left, resets 12:50, synced by replica …", "secret file at <path> is private (mode 600)", the config file's path and nine `status label "sf: …" exists` rows; host sleeps grouped by exact `woke_at` ("host slept N min", "<date> UTC", "workers 0–4"), so one sleep a few ms apart filled several rows; the budget tab said "812 of 5000 calls left until <ISO time>.", "This factory counted N calls in this window." and "Its share: 5000 calls (1)."; the waiting banner showed the stored reason with its ISO time; Spend's note was "The agent CLI's own cost per run, by UTC day of finish; not checked against the bill. A week starts on Monday."; the Failures title was "Failed runs by error code".
- **The first Health read waited, and a timer ran while the page was in use** (until 2026-11-23, wi_926cad13, the stored-report decision at the top). Before: the first read after `startUi` waited for the first run, and while started a run happened every 60 s if either route was read in the last 10 minutes (`Activity`, `IDLE_MS`, `start()`/`stop()`), and once when the first read after an idle spell woke both snapshots.
- **Health's tabs were Sections; Claim pauses a bare list** (until 2026-11-19, the Cards decision at the top). Before: each tab was a `Section` with no surface, and the Claim pauses tab showed its list with no heading.
- **Health checks ran inside the request** (until 2026-11-19, the background snapshot decision at the top). Before: when the last run started 60 s ago or more, a `GET /api/health` or `/api/v1/health` ran the checks (GitHub calls included) and waited for them, so a read took about 4.5 s; a throwing check replaced the last report with one FAIL row. That behaviour remains for a monitor that is not started.
- **A Health section on the server-rendered page** (until 2026-11-16, the API-only decision at the top). Before: `/` (later `/classic`) showed the checks as a Health section with a refresh link (`?health=refresh`, still at most one run a minute) and, for a user who may approve, the Run now button; `HealthMonitor.section` built it, and page loads counted toward the 60 s limit beside the API.

## History

- **Health page on one page** (decision changed 2026-11-15). Before: Checks, Claim pauses, Host sleeps and Merged without review were stacked on one page; the sleep list had one row per worker entry (so one sleep hitting five workers filled five rows); Merged by used `PersonName`, "you" behind a disclosure with the user ID and a Copy button.
- **Current text names SQLite only** (decision changed 2026-11-11, issue #567). Before: the first decision was titled "No MySQL check"; the Host sleeps paragraph named a MySQL database without step 0028; the first decision said "had a MySQL check"; the schema probe said MySQL treated a missing `schema_migrations` as version 0 and that the MySQL check was gone.
- **MySQL check** (decision changed 2026-11-11, issue #590). Before: with a MySQL store, doctor read `schemaVersion()` and printed "MySQL <user>@<host>:<port>/<db> reachable, schema up to date" (or behind: FAIL with `npm run migrate`; unreachable: FAIL with the connection fix from `storeErrorCheck`).
- **App token expiry** (decision changed 2026-11-08, issue #434). Before: an App token's expiry came from its mint response and went through the same day thresholds, so the hour-long expiry failed on every App factory and told the owner to run the rotate command.

- **Thresholds** (decision changed 2026-11-07, issue #311). Before: the token check warned only above 30 days (rounded to the nearest day), so a token expiring in 2 days showed ok; a schema behind the code was a warn, "schema at version X of Y (the factory migrates it when it starts)".
- **Claim pauses on the Health page** (new decision, 2026-11-07, issue #291). Before: the Health page showed only the checks, so a timed pause (`rate_limit`, `forge_auth`, `preflight_access`) was not visible and could not be ended from the app.
- **Read-only schema probe** (decision changed, 2026-11-01). Before: doctor's MySQL check ran `store.migrate()`, so doctor, and `setup` through it, created or upgraded the schema.
- **Runs tab sections** (decision changed 2026-11-28). Before: the Runs tab held Runners, Failures and Host sleeps, and the run timeline and dependency graph were a separate Workers page. Now they are Runs tab sections after Runners.
