## History

- 2026-11-07: the first version kept the actor, transcript and token fields inside the run's `input` JSON with no schema step, and put this decision in the `docs/design.md` index. Replaced by the run columns above (the work item's migration criterion) and this topic file.
- **MySQL text removed from the current decisions** (decision changed 2026-11-11, issue #567). Before: the schema bullet read "migration 18 (SQLite) adds the run columns ...; MySQL: step `migrations/mysql/0018-run-session.sql`, the same three columns."
- **A queued implement or update run is taken over on start** (decision changed 2026-11-19). Before: `factory session start` refused, with nothing changed, on an item with a queued or running implement or update run. Now a queued one is cancelled and the interactive task starts; a running one still refuses.
- **A start over another item's running run can wait** (decision changed 2026-11-21). Before: nothing waited: `session start` over another item's running run on shared files was refused, and the owner ran it again; meanwhile triage could claim the NEW item and write its own spec, so the next `--spec` start was refused ("--spec applies only to a NEW item"). Now `--spec <file> --wait` reserves the NEW item and starts when its files are free.
- **A start acts as the CLI identity** (decision changed 2026-11-21). Before: `session start` looked the person up on GitHub (`GET /users/<login>`, the login `--as` or else `repo.owner`) on every start, and a failed call refused it with "no GitHub account". Now no `--as` uses the CLI identity with no network call, and `--as` needs the GitHub source.
- **A session and the work beside it use the workers' coordination cost** (decision changed 2026-11-21, wi_a1d21531). Before: `startSession` refused, and a claim skipped an implement-type run, whenever the item's `allowed_paths` shared any path with another item's open session or running implement-type run (`pathsOverlap`), whatever the path's weight, so shared design files and the i18n barrel serialised sessions that workers would have run side by side.
- **A session keeps the machine awake; `session_lost` names the last heartbeat** (decision changed 2026-11-21). Before: `factory session start` held no keep-awake (only the worker did), and the reaper's `session_lost` detail was the bare "the session's lease expired", with no time of the last heartbeat.
