## History

- **Nothing read `permission_mode`** (decision changed 2026-11-27, phase 2 of 3 of local-task-tk_cad55672: the permission gate reads it). Before, the phase 1 bullet read "adds a setting and two columns, nothing reads them yet" and "Phases 2 and 3 add the gate that reads them; this phase changes no behaviour": agent writes (the coordinator's merge, a chat tool call) had no gate, and the command table had no `reversible` flag.
- **`AuditedAuthProvider` removed** (decision changed 2026-11-16, phase 2 of local-task-tk_481fa28b). The decision that changed: the Audit bullet of "Roles, local users and their tables are removed". Before, it read "`AuditedAuthProvider` no longer records (it would audit twice) and only delegates; it is deprecated: compose.ts still builds it, and the next change to compose.ts builds `OwnerAuth` directly and deletes it", and the No command passport bullet added "`AuditedAuthProvider` has no passport branch". compose.ts wrapped `new OwnerAuth(store)` in it at two places.
- **`Principal.attributes` removed** (decision changed 2026-11-16, phase 2 of local-task-tk_481fa28b). Before: `Principal` had `attributes: Readonly<Record<string, string>>` ("from the identity provider; agents cannot edit these"); every caller set it to `{}` and nothing read it.
- **Every owner-check decision was audited** (until 2026-11-16, design 08-retention). Before: `OwnerAuth` wrote one `authz_audit` row for every decision, also each allowed check a dashboard page made on load (5,588 approve_spec rows on 2026-11-15 alone), and no row was ever deleted.
- **Current text names SQLite only** (decision changed 2026-11-11, issue #567). Before: the Migration paragraph said "No MySQL step", the Secrets step said MYSQL_PASSWORD was never asked, the guided flow asked for the store (`sqlite` | `mysql`), skipped the MySQL root password and took `--rotate-mysql`, and factory users and links named the MySQL step `migrations/mysql/0014-identity-links.sql`.
- **Roles, local users and their tables are removed** (decision changed 2026-11-13, issue #577). Before: the owner was the `owner` row of `identity_local_users`, beside rows for other local users with other roles that allowed nothing more; `factory users list|add|remove`, `factory setup --me`, the Users API (`/api/v1/users`) and the `/app/users` redirect managed or showed them; `identity_local_user_changes` audited each change; `AuditedAuthProvider` wrote the decision's `authz_audit` row, so the CLI's `localAuth`, `factory session` and the Slack taps were not audited; commands could carry an edge passport field.
- **Local user changes are audited, and the dashboard manages them** (decision 2026-11-08, issue #445; replaced 2026-11-13 by #577). Every add, role change and removal of a local user wrote one `identity_local_user_changes` row in the same transaction, from `factory users add|remove` and the Users page (`POST /api/v1/users`).
- **The auth plugins and the grants are deleted** (decision changed 2026-11-13, issue #669). Before: phase A left the `github`, `local` and `none` auth plugins, the grant interface and its `github-permission` and `static` grants in the tree, unselected; `selectPlugins` took a fixed auth name nothing built; the Slack taps built the `local` auth plugin by name; Identity asked a list of role sources (`ServiceGrant`, `OwnerGrant`) for roles, with denies.
- **One owner check decides every command** (decision changed 2026-11-13, issue #668). Before: an auth plugin chosen by the command's origin decided each command (`auth` for GitHub comments, `local_auth` for the CLI and the dashboard, `slack_auth` for Slack threads, default the local one), with roles from GitHub write access (`github-permission`), static grants (`permissions.static`) and the store's local users; CLI rows, dashboard requests and relayed comment and Slack commands carried an edge passport that Identity checked first; approve_tool had its own owner-action path inside the legacy check; refusals read "needs write permission" or "`<user>` has no role that allows it".
- **Chat accounts act as their linked factory user, with its stored role** (decision 2026-11-09, issue #498; replaced 2026-11-13 by the owner check). A Slack account was judged by the local auth plugin: its link gave the factory user, and that user's stored role (plus `static` grants) decided, with the CLI's refusal text.
- **Local commands are authorized locally, on any item** (decision 2026-11-08, issue #318; replaced 2026-11-13 by the owner check). Local commands (CLI, dashboard) on any item were judged by the auth plugin for origin `local`; `auth` was a string or `{ "github_issue", "local", "slack_thread" }`; the `local` plugin read roles from the store's local users plus non-remote grants.
- **`approve_tool`** (new decision, 2026-11-11, issue #589). Before: the actions were `submit_work`, `approve_spec`, `approve_merge`, `record_verdict` and `use_tool`; nothing could approve a pack tool.

- **One owner** (decision changed 2026-11-11, owner decision). Before, "Two setups, one rule": solo had zero setup and you were the owner on your first command; a team on a shared store had the first person as the owner, who granted roles to others, and linking a local identity to a GitHub account would merge one person's identities for audit.
- **Chat accounts act as their linked factory user, with its stored role** (decision changed 2026-11-09, issue #498). Before: Slack accounts were judged by the forge's auth plugin (with `auth: github`, through `github-permission` or `static` grants on the linked user), while the CLI's users and roles lived in the store, so one person could hold two different rights.

- **Local user changes are audited** (decision changed 2026-11-08, issue #445). Before: `factory users` (owner only) was the only way to change local roles, and a removal deleted the `local_users` row with no record of the change, who made it or the old role.
- **Setup steps share one frame and can resume** (decision changed 2026-11-10, issue #501). Before: some steps asked with a default and others only printed; the model credential and the GitHub token had steps of their own, the other secrets a later one; a declined config diff left GitHub selected, so GITHUB_APP_ID was still asked; the mode was asked before the database and set later in "You and the mode"; nothing recorded finished steps, so an interrupted run started at step 1; and the ANTHROPIC_API_KEY check read `ok  ANTHROPIC_API_KEY is not set in this shell (good: …)`, like an error.
- **Guided setup and display names** (decision changed 2026-11-08). Before: `factory setup` needed a terminal and asked only for secrets (store and plugins were edited by hand in factory.config.json, the mode only through `factory mode`), and no display name was stored anywhere: git `user.name` was not used at all.
- **Passports in the running factory** (decision changed 2026-11-09, M9 follow-up). Before: the auth plugins decided every command and `AuditedAuthProvider` recorded it under passport `none`; auto mode's approvals and merges were checked by nothing.
- **Passports in the running factory** (decision changed 2026-11-08, RFC 0015 M9 wiring). Before: the passport service existed but nothing used it: the ToolBroker checked only the lease, command rows had no passport, nothing was audited to `authz_audit`, and the UI showed user ids only.
- **Passports** (new decision 2026-11-08, RFC 0015 M9). Before: a command's user id went straight to `authorize`, with no signed token, no narrowing for runs, no revocation and no audit of decisions.
- **Local commands are authorized locally, on any item** (decision changed 2026-11-08). Before: local commands were authorized locally but accepted for local items only; on a GitHub item the CLI refused and only a GitHub comment, judged by the GitHub auth plugin, could act.
- **Local commands are authorized locally** (new decision, 2026-11-07, issue #318). Before: one `auth` plugin authorized every origin, so with `auth: github` a CLI command resolved only through a link that no command created, and local items stuck at spec approval while GitHub was the only judge.
- **Permissions in the factory** (decision changed 2026-11-01, issue #107). Before: permissions were GitHub write access only, checked inside the `github` AuthProvider, so a Slack user had no way in and one person's GitHub and Slack accounts were two strangers.
- **Raised size limits** (decision changed 2026-11-01, issue #107). The checked-in limits went from 1500 and 40 to 3000 and 60. The human set them from the size of that change (estimated 1,500 to 2,500 lines in 30 to 45 files).
- **Raised again** (decision changed 2026-11-02). Before: 3000 and 60.
- **Command passport expiry** (decision changed 2026-11-09, review of RFC 0015 M9). Before: a command's passport was checked for expiry when the controller handled the command, so a command that waited over an hour in its stream was refused as `expired`.
- **Edge passports for Slack commands** (decision changed 2026-11-09, issue #479). Before: only command rows got an edge passport; a Slack command the listener stored as a stream record was relayed with none, so the auth plugin alone decided it and the audit row said `none`.
- **Ending a run passport** (decision changed 2026-11-09, worker review finding 5). Before: `end(run)` dropped the run's passport whoever had minted it, so a slot that lost the run in the same process dropped the passport of the claim that took it over, and that claim's broker calls failed `passport_missing`.
