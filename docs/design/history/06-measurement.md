## History

- **Suites and cases from the CLI** (decision changed 2026-11-23, local-task-tk_a5eb7be8-4fe7-4e9a-992e-1d620810bf73 phase 1). Before: the skill-evals decision said "Out of scope: creating suites or cases"; the store had create calls only, and no command or store method updated or deleted a suite or a case.
- **Per-merge evaluation** (decision changed 2026-11-11, issue #512). Before: the store kept merges (`merge_sha`), revert and fix-forward rows, verdicts and token cost apart, and nothing combined them into one result per merge. Stats over the revert and fix-forward rows were "not built yet".
- **Autonomy** (new decision, 2026-11-11, issue #522). Before: the stored push, merge and revert verdicts were only counted together as `implicit`, so neither `factory stats` nor the Data page could say how many merged items needed a person's push.
- **Implicit verdicts in the numbers** (decision changed 2026-11-08, issue #316). Before: stats counted explicit `/verdict` verdicts only, and nothing else wrote one.

- **Eval on change** (decision changed 2026-11-18, issue #493). Before: "**Results** go to `<state_dir>/golden/results/<timestamp>.json`, not the store … Not yet: comparing two agents automatically, repeated runs per case, shadow mode, a `checks/` folder per case." No change was evaluated against golden cases: a change to a prompt, skill or setting reached agents with no eval, nothing read a `uses` list or a `golden` config block, and no per-entity fingerprint or verdict was stored. Every replay was a review replay, and the implement role had no golden case (the rule-of-two ratchet listed it as short with triage and resolve).
- **Golden sets per role** (decision changed 2026-11-18, issue #492). Before: "**Golden set for the reviewer.**" Cases lived in one shared folder, `golden/cases/<pr>/` (`diff.patch`, `spec.md`, `case.json`), in the repo. `factory golden add <pr> [--expect should_flag|should_pass] [--force]` wrote there. `factory golden run --agent reviewer` (only `reviewer` was accepted) replayed every case with the worker's review system prompt and printed `catch_rate` and `false_alarm_rate` only, with no pass rate, tokens or time. "**Cases belong to a role** (2026-11-08, RFC 0015 M10): `case.json` may name its run role (`role`); a case without one is a `review` case." The minimum check counted that shared folder for every role, and `golden/` was in the prompts category of the gate list.
- **Golden compare** (new decision, 2026-11-08, issue #338). Before: `golden run` printed one prompt's rates and compared nothing, so a prompt change had no before/after number.

- **Run attempts** (new decision, 2026-11-07, issue #207). Before: one `worker_runs` row per run held only the latest claim: every claim overwrote `started_at`, a resumed paused run reused it, and an earlier claim's end, tokens and error had no record of their own.
- **`factory stats`** (new decision, 2026-11-01). Before: the feedback rate above had no read path, and `factory status` lists only the 50 newest items.
- **Golden set for the reviewer** (decision changed 2026-11-01: measurement now has a golden-set step). Before: "golden PRs" above was a plan with no cases, no runner and no numbers.
- **Revert and fix-forward tracking** (new decision, 2026-11-01). Replaces "revert rate (webhook)".
- **MySQL text removed from the current decisions** (decision changed 2026-11-11, issue #567). Before: the merge evaluations table was "SQLite migration 42, MySQL step `0043-merge-evaluations.sql`", and the run attempts backfill was "SQLite migration 20 (applied on open) and MySQL step `migrations/mysql/0020-run-attempts.sql` (`npm run migrate`; `CREATE TABLE IF NOT EXISTS` and `INSERT IGNORE`, so a rerun adds nothing)".
- **Merge record read to merge** (decision changed 2026-11-22, wi_f9e6887d). Before: the per-merge evaluation was "Read-only for every dial: no weight, gate or auto-merge rule reads it", and the per-tier rule said "nothing reads the rule to merge"; phase 2 of the drop-back was not built.

- **Run attempts, backfill and rollout** (moved out of the current decision, 2026-11-23, to keep the topic file under its size cap; decision unchanged). **Backfill:** SQLite migration 20 (applied on open) gives every run with attempt ≥ 1 one record numbered by its `attempt`, from the run row: status (a queued run with attempt ≥ 1 is `paused` when `paused_at` is set, else `lease_expired`), `started_at`, `finished_at` (else `paused_at`, else `updated_at`; null while running), the lease owner as worker id (null once the lease was cleared), error code, failure class and tokens as above. Queued runs with attempt 0 and manual runs get none. **Rollout:** stop old workers before the new code starts: a claim by old code writes no record.
- **Golden results report pass^k, rationale** (moved out of the current decision, 2026-11-23; decision unchanged). `pass_rate` averages, so a case that passes 2 of 3 replays adds 0.67 and hides that the agent is right on the same input only two times in three (Sierra's τ-bench: pass^k counts a task only when all k runs succeed).
- **Golden results report pass^k, follow-ups** (moved out of the current decision, 2026-11-23; decision unchanged). **Follow-ups, not built:** `golden.require_stable` (a change that turns a stable-passing case into an unstable one is a regression) is a separate issue; raising a tier's auto-merge should read `pass_k`, not `pass_rate`, once enough replays exist. Cost: k replays cost k times the tokens, so keep `replays` at 1 for the per-change gate if cost matters.
- **Run attempts, example** (moved out of the current decision, 2026-11-23; decision unchanged). A step that failed twice and then succeeded shows three runs with one attempt each.
