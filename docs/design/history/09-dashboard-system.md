## History

- **`setup_missing` had no plain copy** (decision changed 2026-11-22, wi_a4543d54, the setup_missing decision at the top of 09-dashboard-system.md). Before: RFC 0024 WP1 (wi_ce1668d5) added the code but no `failure.setup_missing.*` entries, and its commit e855393d removed the server description while the web catalog file was in review; a group showed the raw code as its title and "This error code has no plain description yet.", and no test checked the entry.
- **The Improve tab titled groups by error code and printed date-times** (decision changed 2026-11-22, the Improve tab decision at the top of 09-dashboard-system.md). Before: a group's title came from a `rules.code.*` table keyed by error code ("Other failure" for an unknown one); the header read "Window {start} to {end}, reported {created}. N groups (M runs), K single-run patterns." in local date-time; filing and draft notes showed raw text such as "skipped (issue_cap)"; the button read "Run now" with the hint "queues an improve run of the last 24 hours"; the read sent filing and draft notes as one string and no hotspot flag.
- **The improve report sat on the Rules page** (decision changed 2026-11-21, the Improve tab decision at the top of 09-dashboard-system.md). Before: it was the last card of the Rules page (above the ledger-off EmptyState when the ledger was off), each failure group titled by its error code in monospace with its detail, draft and filing always shown.
- **Failures and pauses printed stored names; times had four shapes** (decision changed 2026-11-19, the plain words decision at the top of 09-dashboard-system.md). Before: a failure group printed its error code under the title, a pause its name before its label, a check its raw status, and times read "12s", "4m ago", "in 4m" and "(as of 4m ago)".
- **Failures, Spend and Data drew their own block headings** (until 2026-11-19, the Cards decision at the top). Before: Failures and Spend were a `<section>` with a raw `text-base` h2 over `Section`s with no surface; Data's table was a `<section>` with a monospace h2 beside its range, filter and paging; Work's blocks were `Section`s and its empty match an `Empty` line.
- **Table docs described every `legacy_` copy** (decision changed 2026-11-15, the legacy contract in 10-event-driven). Before: State's table docs gave each `legacy_` copy a line, `HIDDEN_COLUMNS` listed the legacy copies of the token and hash columns, and the Ask model saw every table.
- **The Queue page and the item-based Queued filter** (decision changed 2026-11-14). Before: System → Queue (`/app/queue`, `QueuePage`, `page.queue`) listed the queued runs in claim order with when each may start; Work's "N queued" counted the same runs, but its button and the Queued filter button set `state=queued`, which filtered items (the 2026-11-13 "one queued count" decision), so the count and the list could differ.
- **Ask's hidden-column reads on a Node without an authorizer** (decision changed 2026-11-14). Before: on Node before 24.10 the child ran a query with no hidden-column lock of its own, relying on the name check and the `[hidden]` result mapping, so a hidden column read under another name (a renamed CTE column) returned its value. Now such a query is refused by the child's plan check.
- **Data page without table info or questions** (decision changed 2026-11-14). Before: the Data page listed every table by name with its row count and columns only, nothing said what a table held or which component owned it, and free-form SQL was out of scope, so a question about the data needed a hand-written query.
- **Autonomy on the Data page** (new decision, 2026-11-11, issue #522). Before: the Data page showed only the raw tables, and no route returned Autonomy.
- **Work items tree** (decision changed 2026-11-08, issue #295). Before: the Work items page was one flat table of `/api/v1/items` rows (item, state, why, since, issue, PR) with no parent, phase, worker, queue position or claim decision on a row, filtered by the server's `state` and `q`. It stays as the List toggle.
- **`/api/v1/workers`** (field added 2026-11-07, issue #209). Before: it returned only `workers`, the lease owners of running runs, so an idle process did not appear and no slot count was shown.
- **Store reads behind the API** (changed 2026-11-07, issue #239). Before: the API had only curated views, and tables such as `controller_claim_decisions`, `controller_file_conflicts` and `worker_run_attempts` had no view at all; the store had no generic table read.
- **Unreviewed merges in the app** (new decision 2026-11-07, issue #268). Before: the controller recorded an `controller_unreviewed_merges` row and a log line, and only tests read the rows; the app had no route or view for them. Replaces "showing unreviewed merges" under "Not built" in `05-sources.md`.
- **Workers, Failures and the effective worker count** (decision changed 2026-11-07, issue #312). Before: the Workers page listed lease owners and "Running now" and ignored `processes`, so draining processes and idle slots were invisible; the factory banner showed the status file's `workers` (the file value, which could disagree with an override or the `max_workers` cap); the Floor's failed count was plain text, and no route grouped failed runs by error code.
- **Work summary line, raw-code Failures headings, Import tooltip** (decision changed 2026-11-16, the Failures and Work decision at the top). Before: the Work summary line "N running · N queued · N held · N needs you · rate limit: …" (each count a button that set the state filter), the Failures group heading as the raw error code with the server's English `description`, and the Import button's tooltip naming the CLI command.
