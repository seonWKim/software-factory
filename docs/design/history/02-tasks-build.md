## History

- **`task create` takes only `--title`, `--body-file` and `--project`** (until 2026-11-20, the `--depends-on` decision at the top). A local item that had to wait for another one needed a `Depends on: wi_…` line typed into its body file; nothing in `task create --help` named that line, and triage's spec replaced the body it was in.
- **A plain task carries only its title** (until 2026-11-19, wi_6fee2cb6; replaced by the description decision at the top). `controller_tasks` had no body column, so Build this and `factory task build` made a work item whose problem was the title alone; `task create --project` sent its `--body-file` body only to the new item, never to the stored task, and `buildTask` took the body as an argument.
- **Every close of a work item completes its linked tasks** (2026-11-18 to 2026-11-19, local-task-tk_a81c3768; replaced by the completed close decision at the top). The store's close transition called `completeLinkedTasks` on the first move of an item to `CLOSED` whatever its close reason, so `/reject`, a budget-checkpoint reject, a source close as not planned and a PR closed unmerged marked the linked task done too. `GET /api/v1/tasks` gave `close_reason` only on done tasks, and the row showed it (`rejected`, `not planned`, `closed`) only beside the done time.
- **Only a merge completes the linked task** (until 2026-11-18, the every close decision above, itself replaced 2026-11-19; it changed the merge close of the 2026-11-12 date views decision). `closeLinkedTasks` was called by each merge path after its close (the local merge, the Merge button's PR merge, a PR merged on the forge), in its own transaction. `/reject`, a budget-checkpoint reject, a source close and a PR closed unmerged closed the item and left its task open, and the Tasks page showed no close reason on a done task.
- **Upcoming started tomorrow, and no view showed events** (until 2026-11-12, the calendar views decision in design 02-tasks-page). Upcoming listed tasks due in the 7 days after today, so today's tasks were only in Today; the calendar component synced events that no view read.
- **No views, no link to an item, no merge close** (until 2026-11-12, issue #607). The #606 decision said: "Reminders, due-date alerts, dashboard and status page views, and linking a task to a repository, an item or a pull request are not part of this decision." A task could only be listed by `task list`, never sent to intake, and stayed open when the change made for it merged.
