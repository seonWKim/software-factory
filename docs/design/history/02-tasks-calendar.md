## History

- **The dashboard's add and edit forms were not part of the local events decision** (until 2026-11-25, the dashboard add, edit and delete line above, phase 2 of local-task-tk_dc8c579a). The Calendar page only read events: the three local event routes had no caller in the dashboard.
- **Creating, editing or deleting events is not part of this decision** (until 2026-11-24, the owner's own events decision above, wi_c03c5983). The calendar component decision of 2026-11-12 left out creating, editing and deleting events: the factory held only copies of its configured sources' events, so an event the owner wanted to add had no store and no route, and the calendar read showed nothing with no calendar connected.
- **A sync replaces all of the source's events, and a day is synced only inside the last scheduled sync's window** (until 2026-11-22, the replace rule decision above, wi_76e42fbc). Each scheduled sync deleted every stored event of the source before writing its answer for one day back to 30 days ahead, so nothing outside that window was kept, and days outside it showed as not synced with no way to sync them from the page or the CLI.
- **The reminder is a desktop notice only, sent up to a day late** (until 2026-11-13, the reminder channels decision above; owner answer 3 of #598). The `task-reminders` unit wrote no outbox intent, so a reminder never reached Slack or another `notify_channels` adapter, and `REMINDER_LOOKBACK_MS` was one day.
- **A task has a due date and an optional `HH:MM` time, no duration, no timeline and no reminder** (until 2026-11-13, the schedule a task decision above). Quick add read only `HH:MM`, nothing stored how long a task takes, the Tasks page had no hour-by-hour view, and no reminder fired at a task's time.
- **A calendar read had no time limit** (until 2026-11-12, the Google call timeout decision above). A Google that accepted the connection and never answered held the controller's tick until the process restarted.
