## History

- **Every verdict was a new row, and Slack results had no verdict buttons** (decision changed 2026-11-12, one-tap verdicts). Before: a verdict on a result was a typed `/verdict`, a 👍 (or 👎 then `/verdict changes`), or the dashboard's Accept, Changes and Reject; a stored comment ID was always a duplicate, so a person could not change a verdict on the same message.
- **A pushback stayed in the factory's store** (decision changed 2026-11-11, issue #570). Before: `/revise` and `/reject` were applied in the commands unit and a `/verdict` stored in the verdicts unit, and neither called anything outside the store, so a pushback left no trace the owner's ledger could read.
- **Reactions were ignored** (decision changed 2026-11-11, issue #524). Before: the GitHub source added 👀 but never read reactions, and the Slack app had no `reactions:read` scope or `reaction_added` event, so a 👍 or 👎 on a factory message recorded nothing; only a typed `/verdict`, `factory verdict` and the app's verdict request did.
- **No verdict in Needs you** (decision changed 2026-11-11, issue #513). Before: a Needs-you row offered only commands that change state, so a waiting item offered no verdict there; a verdict was sent from the item page.
- **A verdict needs a PR on every surface but the controller** (decision changed 2026-11-11, issue #523). Before: the controller recorded a verdict on a local item with no PR, but `applies()` required a PR, so the item API, `/help`, the footers and the SET_UP.md table did not offer `/verdict` there; `factory verdict` was an unknown command; the item page had only the note box; and the closed-item refusal text lived only in the verdict unit.
- **Implicit verdicts and the lenient `/verdict`** (decision changed 2026-11-08, issue #316). Before: only `/verdict` wrote verdicts; `/verdict accept` alone and `/verdict yes` were refused (a severity was required for every kind), so every owner `/verdict` on record was refused; merges, pushes and reverts wrote no verdict; a `/verdict` on a merged item was refused as closed.
- **Verdict command** (new decision, 2026-11-01). Before: the gate commands were only `/approve`, `/reject` and `/retry`, read only on the issue, and human feedback on a PR was free-form text.
- **MySQL text removed from the current decisions** (decision changed 2026-11-11, issue #567). Before: the proposals table was "SQLite migration 43, MySQL step `0044-command-proposals.sql`, since 0043 is merge-evaluations"; the verdict columns came from "SQLite migration 39, MySQL step 0039" and the implicit-verdict paragraph ended "Enterprise: the GitHub forge, implicit verdicts from its PR events, on the shared store with both migrations applied"; the command inbox copied pending requests with "SQLite migration 29 (MySQL step `0029-thread-outbox.sql`)"; migration 6 was "(SQLite and MySQL)"; and the app request handling was "migration 23 on SQLite, step `0023-app-command-handling.sql` on MySQL".
