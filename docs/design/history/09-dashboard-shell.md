## History

- **App shell, step 2 (issue #160; 2026-11-07)** (moved here 2026-11-19 from the dashboard app and read API decision in 09-dashboard-shell.md, for the topic size cap; not a changed decision). `web/` holds the app: `web/vite.config.ts` (base `/app/`, no module-preload polyfill, nothing inlined), `web/tsconfig.json` (DOM and JSX; `npm run typecheck` runs it after the server's), one root `package.json` and `node_modules`. The shell: a sidebar (Floor, Work items, Workers, Queue, Health, Settings; every page but the shell is a placeholder naming the step that brings it), and a top bar (its current contents are the top bar decision at the top). TanStack Query polls every 3 s and not in a hidden tab; nothing animates under `prefers-reduced-motion`. shadcn's Button is a plain file (`web/src/components/ui/button.tsx`) without class-variance-authority. Web tests are `tests/*.test.tsx` with `@vitest-environment jsdom` in the file, so every other test keeps the node environment. Decision changed: none; this builds the recorded stack.
- **The app is the default, steps 3–5 (2026-11-07)** (moved here 2026-11-19 from the same decision, for the topic size cap; not a changed decision). `/` answers 302 to `/app/`; the server-rendered page that answered there is removed (see the top). Pages: **Floor** (the supervisor banner, then Needs you (ready to merge, needs approval, needs a human, stuck), Running now, the first 10 queued runs, then the last-24-h numbers), **Work items** (the API's ranked list with the state filter and search; an item page under `/app/items/<id>` with its facts, runs with their errors and the timeline), **Workers** (lease owners with runs, and the running runs), **Queue** (every queued run in claim order, with when it may start), **Health** (the doctor checks, failing first; read every 30 s, not 3 s) and **Settings** (see below). `/api/v1/overview` now also returns `factory`, the supervisor status the banner shows (absent without a status function, null when stopped). Client routing is `history.pushState` under `/app/` (`web/src/nav.tsx`), no router dependency. The item page also has the item's command buttons (below, issue #228).
- **The responsive check's launch retry and first run** (moved here 2026-11-19 from the responsive check decision in 09-dashboard-shell.md, for the topic size cap; not a changed decision). A launch that does not open its DevTools port within 30s on CI, 15s locally, is killed and retried with a fresh profile up to twice, and the final error gives Chrome's exit status and the last 20 lines of its stderr. The first run fixed: card cells keep no `whitespace-nowrap` (a worker id ran off a 390px card), the item title and system actions break long words, the claim pause time wraps, object values in Settings keep a 10ch value column, and the Runs table's kind column keeps a minimum width.

- **System group always open** (decision changed 2026-11-13). Before: System was a collapsed `details` with a wrench icon and a chevron, open only when clicked or while one of its pages showed.

- **Revisions, system actions and the tab title** (decision changed 2026-11-07, issue #311). Before: the overview returned only the supervisor's revision (`factory.rev`), the web build had no revision built in, so a tab or a page server on old code was not shown; `needs_you` counted only human-blocked and deadlocked items; the tab title had no count.

- **Where `/` goes** (changed 2026-11-07). Before: `/` served the server-rendered page and the app was only at `/app/`, with placeholder pages.

Before: the JSON API answered only `GET`/`HEAD` ("Read-only JSON API"), and the Settings page was read-only, pointing at `factory settings`.
