## History

- **The transcript page never polled; a live view was out of scope** (decision changed 2026-11-20, the live transcript decision at the top of 09-dashboard-item.md). Before: the worker stored an agent step's transcript only when the step returned, so a running run had no stored part; the transcript API answered 404 for it and the page kept its loading state; Current run linked a transcript only when one was stored; the transcript page never polled ("a stored transcript does not change"), and "Run transcripts in the app" (2026-11-07) listed a live view and what the worker stores as out of scope.
- **The timeline and the Runs table printed stored names** (decision changed 2026-11-19, the plain labels decision at the top of 09-dashboard-item.md). Before: a timeline row listed `field: from → to` with the stored field name, its reason as stored, the Runs table the stored status ("succeeded") and error code, and the page's times as "4m ago" built per call site.
- **The item page used Sections** (until 2026-11-19, the Cards decision at the top). Before: Thread, Phases, Merge check, Runs, Timeline and Steps were `Section`s with no surface, the state was a `StatusBadge` and run statuses square `Badge`s.
- **The decide box sat after the title, the thread listed every entry, and a terminal line followed the buttons** (decision changed 2026-11-19, the decision-first item page at the top). Before: the page showed the title, the "What you need to decide" box (or the why sentence), the facts, the IDs, the thread with every entry listed (older long factory messages folded to one line, the newest, the newest factory message, every `spec` and `coordination-hold` and the anchored one open), the phases, the merge check, the runs and the timeline, with no current-run section; under the box's buttons, "From a terminal: `factory <command> <short number>`" with a Copy button, and each button titled with its `/command` usage.
- **The item page showed no queued feedback** (decision changed 2026-11-15, `/revise` while implementing). Before: `/revise` was refused while implementing, so there was no queued feedback to list; the refusal showed only under "Last refused command".
- **A stale token's 403 was shown until a reload; a Factory work row's error sat in its actions** (until 2026-11-15, the stale-token retry decision at the top). Before: `postJson` sent the token the caller held and returned the 403 "Missing or stale x-csrf-token; reload the page." as the write's error, with no code in the body, so after every UI restart each write failed until the owner reloaded; `NeedActions` drew that error inside the Factory work row's actions, and the title (`flex-1`, basis 0) shrank to "Tas…" while the Merge button covered the "Ready to merge" badge.
- **The item page's decide box and readable names** (decision changed 2026-11-12). Before: the item page showed the breadcrumb's source link (a local item's `local:` address), a Stage fact with the raw stage, the why sentence, the facts, then In short and a Commands section with lowercase buttons of equal weight and a severity dropdown named only for screen readers; tables, the timeline, host sleeps and "Acting as" showed raw item IDs, `github:<number>` actors and `host:pid:slot` worker IDs.
- **Thread readability** (decision changed 2026-11-09). Before: the markdown renderer showed `<details>` as text, all sections looked alike, and a thread entry's header was a line of grey text above a full-width body.
- **Item page, phases and narrow screens** (decision changed 2026-11-07, issue #313). Before: the item API had no `spec_comment_url`, `parent_id`, `phase` or `phases`; the timeline printed each change as `field: <from JSON> → <to JSON>`, so a spec showed escaped newlines and arrays; the Runs table showed only the kind ("the item page's Runs table shows kind, attempt, status, error, worker, started, took, tokens and an Open link when a transcript is stored, scrolling inside its own box"); every table kept its full width in a scroll box on a phone; the sidebar links below `sm` had no title; the Closed facet read 0 because closed items were loaded only when a filter asked for them; and Settings showed `_ms` keys as plain milliseconds.
- **Why an item waits** (decision changed 2026-11-07, issue #310). Before: the level returned `queued` before it checked dependency blockers, so an item waiting on another item's merge showed Queued; a deadlock claim decision was not in Needs you or `needs_you`; the Queue's Starts column read only the run's `not_before`, so a coordination hold showed "now"; and the item page showed the raw `blocked_on: blocked_reason`, cut off, with `#N` not linked.
- **Run attempts in the item API** (decision changed 2026-11-07, issue #207). Replaces: "`/api/v1/items/:id` (facts, timeline, runs)" with one row per run and no record of its earlier claims, and "no store method, interface, migration or schema changed" (the item route now also reads `listRunAttempts`).
- **Item list and item fields** (field added 2026-11-07, issue #248). Before: no merge readiness in the API; a ready-to-merge row showed only "Ready to merge".
- **Run transcripts in the app** (new decision 2026-11-07, issue #303). Replaces: the UI had no storage dependency and only read the store; the worker stored transcripts that nothing read back, the item page had no worker column or transcript link, and the Data page listed shared-storage transcripts as out of scope.
- **Item tables: plugins, issue and PR links** (decision changed 2026-11-08, phase 4 of the change-fields split). Before: `main.ts` passed `UiDeps.prUrl(label, n)` and the UI built `https://<label>/pull/<n>` from the stored project label; items, the item page and unreviewed merges returned `pr_number` and `pr_url` (an unreviewed merge's `pr_url` only when `plugins.prs` was `"github"`); the overview returned `plugins: { issues, prs }`, and the app showed the PR column and tree PR chip only when `prs` was `"github"`.
- **A deadlock claim needs a person** (decision changed 2026-11-11). Before: an item whose current run's latest claim decision was a deadlock ranked `needs_human` (badge `deadlock`) before its running state was checked, was listed as a `claim_deadlock` system action, and was counted twice in `needs_you` on the Floor. Now the run goes on, the item ranks `running`, and no system action exists for it.
- **A CI wait and the gap after a run ranked stuck** (decision changed 2026-11-12). Before: `blocked_on: ci` and an item between one run finishing and the next being queued ranked `stuck` on the list and in alerts.
- **Thread oldest first, owner commands not shown** (decision changed 2026-11-13). Before: the Thread listed the item's thread entries and verdicts oldest first, each with its full markdown body; the owner's `/approve` note, `/revise` and other commands, stored in `inbound_commands`, never appeared, and a non-factory entry had no role.
