# 09-status-page

## History

- **The model credential row hid its only action in a "⋯" menu and gave no reason** (until 2026-11-27, issue #874; the decision of wi_508d0226, 2026-11-22). Before: the `model_credential` Needs-you row showed only "Add a model credential"; its "⋯" (More commands) menu held one item, Add model credential, which opened the dialog.
- **A verdict from Needs you, moved out of the topic file to keep it under its size cap** (2026-11-22, no decision changed). Kept as it was: **A verdict from Needs you (decision changed 2026-11-11, issue #513; replaces "a Needs-you row offers only the commands that change the item's state, so a waiting item has no verdict there").** A Needs-you row in the app lists `verdict` in its ⋯ menu, after its state-changing commands, wherever it applies (an open item with a PR, or any local item); it opens a dialog with a one-line field, no inline form; sending it stores the same app request as the item page's note box. Details in [09-dashboard-app.md](09-dashboard-app.md).
- **Spend and Failures were sections below every Health tab; Runners a hidden page** (until 2026-11-22, the tabs decision of 09-health.md). Before: `/app/spend` and `/app/failures` led to `/app/health#spend` and `#failures`, and Runners kept its own route `/app/runners`.
- **The overview `needs_you` counted every waiting item at once** (until 2026-11-22, the rank reason and held asks decision at the top). Before: `needsYouCount` was an exact store count of every open item blocked on a person or the budget plus `system_actions.length`, whatever the time; ask rows carried a level and badges but no rank reason or held flag; merged-without-review rows carried no checks or review link (`change_url` null) and no verdict.
- **Each page mapped states itself; failed, held and finished items had no state of their own** (until 2026-11-22, the state table decision at the top of 09-status-page.md). Before: `src/ui/priority.ts` held nine levels and `LEVEL_LABELS`; the web copied the labels (`LEVEL_LABELS` in `web/src/lib/format.ts`, `FILTER_LABELS` on Work), the tones (`LEVEL_TONE` in `badge.tsx`), the Rules (`STATE_LEVEL`), Tasks (`STATE_OF`: "Spec waiting", "Triage queued") and run (`RUN_STATUS_KEYS`) words, and the Needs-you levels (`NEEDS_YOU_LEVELS`). A failed run's block was Needs you, a coordination hold Blocked by another task, every closed item Closed. `needsYouCount` counted every open item blocked on a person or the budget (`WAITING_ON`), triage asks and failed runs too. List rows sent no `state_label`.
- **Three levels for what waits** (decision of 2026-11-12, replaced 2026-11-22 by the state table decision at the top of 09-status-page.md). Before: **Three levels for what waits: Needs you, Needs triage, Blocked by another task (decision changed 2026-11-12; replaces the one "Needs a human" level and "Waiting on another issue").** The list's levels are now: ready to merge, needs approval, Needs you (`needs_you`), Needs triage (`needs_triage`), stuck, running, queued, Blocked by another task (`blocked_by_task`), closed. `levelOf` (`src/ui/priority.ts`) reads two more inputs that `src/ui/list.ts` fills: `held` (the item's queued run has an unapproved `held` claim decision, a coordination hold) and `asked_by` (the kind of the run behind an `agent_needs_human` block, `blockingRunKind`). **Blocked by another task:** a coordination hold, a deadlock claim, a dependency hold (`blocked_on: dependency`, also while its run is queued) and a phase or upstream hold. The badge names the item it waits on: `waits on #N` (a coordination or deadlock holder's number from its `holder_ref`, a dependency's or phase's number), else fixed words. Held work no longer looks like work that needs a decision. **Needs triage:** an item whose latest agent ask came from a triage run. The row shows the agent's question and an Answer link to the ask comment. Triage cannot ask yet (its output has no `needs_human`, a follow-up), so this level stays empty until then. **Needs you:** every other person's or budget block: merge pending and spec approval keep their own levels inside the Needs-you group; failed run, max loops, merge conflict, budget, Rule of Two, dependency closed, implement/review/resolve asks and unknown reasons are `needs_you`. A row never shows an empty reason or "no reason": a null block reason reads the item's state and next step (decision above); an agent's ask reads its question. **Counts and filters.** The `needs` filter ("Needs you": server `src/ui/filters.ts` `NEEDS_YOU`, the web app's `NEEDS_YOU_LEVELS`) is the Needs-you group plus Needs triage, never Blocked by another task. The `needs_you` level is no filter option of its own (`state=needs_you` is a 400): it would share the group's label, and the group shows it. The overview `needs_you` counts items blocked on a person or the budget plus system actions; a deadlock claim is in Blocked by another task, is no system action and is not counted (its run goes on). The old ids `needs_human` and `waiting_on_issue` are gone: a request with one gets 400. **Colours** reuse the existing tones: Needs you red, Needs triage amber, Blocked by another task neutral zinc (web).
- **The model credential row named a command** (decision of 2026-11-21, replaced 2026-11-22 by the Add model credential dialog decision at the top of 09-status-page.md). Before: the row read "Add a model credential: run `npm run setup`" with `npm run setup` as its command, and the dashboard had no way to save the credential, so the owner had to open a terminal.

- **Refresh and CSP.** (until 2026-11-16, the app-shows-the-status decision at the top) Before: No meta refresh. One constant inline script fetches the same URL every 5 s while the tab is visible (`visibilitychange` stops and restarts it), parses it with `DOMParser`, and replaces only the `<main>` sections whose HTML changed, restoring scroll, open `<details>`, form values, focus and selection; rows whose `data-sig` (version, level, run status) changed get an opacity flash of 180 ms, none under `prefers-reduced-motion`. A manual refresh button (`aria-label`) shows only with JavaScript; `<noscript>` has a Refresh link. The CSP is now `default-src 'none'; script-src '<sha256 of the script>'; style-src '<sha256 of the style>'; connect-src 'self'; form-action 'self'; base-uri 'none'; frame-ancestors 'none'`. Both hashes are computed from the constants in `src/ui/html.ts`; there is no `style=` attribute and nothing loads from another origin. Styling: colour, spacing and radius tokens on `:root` with a dark theme via `prefers-color-scheme`, tabular numbers, titles cut with an ellipsis (full text in `title`), tables in their own horizontal scroll box so the page fits 375 px.
- **Section order and waiting items (decision changed 2026-11-07).** (until 2026-11-16, the app-shows-the-status decision at the top) Before: `/` puts what the operator acts on first and background last: the factory banner, Running now, Queue, Paused, the filters and the ranked work-item list, Health, then Totals, Merges and Cost (Merges since 2026-11-11). An item blocked on `upstream` or `dependency` ranks as waiting on another issue, never as stuck. A held split phase (`phase_hold`) shows `waits on #N`, the phase before it; a split parent (`phases_open`) shows `waits on N issues`, its open phases (`#N` when only one is open). - **Merges digest (new decision, 2026-11-11, issue #512).** (until 2026-11-16, the app-shows-the-status decision at the top) Before: The classic page `/` shows a "Merges (last 7 days)" section between Totals and Cost. No sync plugin is read, so the section renders the same with none configured or during an outage. **Empty state:** with no evaluation in the window it says "No merge in the last 7 days" and that merges from before evaluations were stored are not counted. **Free text:** the only free text is the item title, which goes through the Withholder. A title with a finding is replaced whole by `[withheld: <rule>]`. The digest is not posted to GitHub, Slack or Jira. The dashboard app does not render it yet.
