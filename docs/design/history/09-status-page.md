# 09-status-page

- **Seven functions each derived an item's state** (until 2026-11-16, the one-phase decision at the top). Before: `statusOf`, `commandPhase`, `awaitingMerge`, the API's `readyToMerge` (a copy of `awaitingMerge`), `levelOf`, the web's `detailLevel` and `noticeKind` each read stage, blocked_on, blocked_reason and close_reason with their own checks.
- **`max_revisions` by surface** (until 2026-11-16). Before: the status label said needs human, the level Needs you, the item page Needs approval, the notice kind other.
- **merge_pending and spec_pending at any stage** (until 2026-11-16). Before: `levelOf`, `detailLevel` and `noticeKind` read the reason without the stage.
- **Work counted running items by level** (until 2026-11-16). Before: the Work summary's "N running" counted listed items whose level was running, Activity counted running runs, so they could differ ("0 running" and "3 running").
- **Open items and All by different rules** (until 2026-11-16). Before: Activity's Open items summed the stage counts, Work's All counted the listed rows (at most 200, closed ones included in the read), so they could differ ("Open items 15" and "All 11").
- **The why sentence in English on the server** (until 2026-11-16). Before: `src/ui/why.ts` and `src/ui/need.ts` wrote the reason in English ("Too many review loops…", "review found bugs too many times"), the API sent it as `why.text`, and a held item read "Held behind <holder ref>", a raw local id for a local holder.
- **Alarms as one line, the count with alarms once, linked items left out** (decision changed 2026-11-16, the Needs-you rows decision at the top). Before: the Needs you section listed only work items, without those shown on an open task's row, from the web's level list (stuck items included); under it `FloorNotes` showed each non-alarm system action as a red line with its command and every open alarm together as one line "Open alarms: N." linking to Failures; `needs_you` counted the items blocked on a person or the budget plus the system actions with all alarms once (`oneLine`). One alarm and one merge item gave a badge of 2 and a section count of 1.
- **Deadlock wording** (decision changed 2026-11-15; the Floor notes decision above). Before: Tasks showed one line "Started past a deadlock: N. Their runs go on; a person checks the overlap." with a link to Work items, the item's why sentence read "Started past a deadlock with #N: a person checks the overlap", and the row badge read `deadlock with #N`. Now: no line on Tasks, the plain-words sentence naming the other item by title, and the badge `waits on #N`.
- **Current text names SQLite only** (decision changed 2026-11-11, issue #567). Before: the new nullable columns (migration 3) and the comment links (migration 8) were each marked "SQLite and MySQL".
- **One Needs-you list first on the Floor** (decision changed 2026-11-12). Before: the Floor showed the claim pauses and every system action (each open alarm as its own red row with its detail and where to look) above the Needs-you table, so at 1024×700 the table was cut off; `needs_you` counted each alarm; a person's block with no stored reason read "waiting for a person" in the row and "Waiting for a person" in the why sentence; status was a square badge.
- **Levels for what waits** (decision changed 2026-11-12). Before: one "Needs a human" level (`needs_human`) held every `blocked_on: human` item, every budget block and every deadlock claim; coordination holds were "Queued" and dependency holds "Waiting on another issue" (`waiting_on_issue`); the overview's `needs_you` counted only human blocks, and a null reason read "no reason".
- **A verdict from Needs you** (decision changed 2026-11-11, issue #513). Before: Needs you offered only commands that change the item's state; a verdict was sent from the item page's note box only.
- **Merges digest** (new decision, 2026-11-11, issue #512). Before: the page had no digest of what the loop merged or what happened after each merge. **Section order** changed with it: Totals and Cost became Totals, Merges and Cost.
- **Alarms in Needs you and the why-it-waits sentence** (new decision, 2026-11-08). Before: alerts were stored and readable through `listAlerts`, but no view showed them: Needs you, the why-it-waits sentence, the item list and the item page said nothing of an open alarm.
- **GitHub budget** (new decision, 2026-11-07, issue #340). Before: the page showed no GitHub rate limit, so a factory at 0 calls looked idle or failing.
- **System actions in Needs you** (new decision, 2026-11-07, issue #311). Before: Needs you counted only items blocked on a person (and, since issue #310, deadlocked items), so a pending migration, an expiring token, a claim pause and a stale UI were not listed, and the tab title had no count.
- **Claim pauses on the Floor page** (new decision, 2026-11-07, issue #291). Before: the Floor page showed no claim pause, so the operator saw runs not starting with no reason and no way to end the pause but a database edit.
- **"Last 24 h" tokens** (decision changed 2026-11-02, issue #136). Before: succeeded runs only, input + output.
- **Refresh and CSP** (decision changed 2026-11-01). Before: meta refresh every 5 s and no JavaScript; the CSP had `style-src 'unsafe-inline'`, `form-action 'none'`, no script.
- **Read-only status page** (first decided 2026-11-01): meta refresh every 5 s, no JavaScript, no front-end dependency. Replaced by Refresh and CSP, and by the dashboard app ([09-dashboard-app.md](09-dashboard-app.md)).
- **Dashboard UX** (decision changed 2026-11-01, issue #64). Supersedes "no JavaScript, meta refresh" and the fixed Needs you / All work items sections.
- **Needs you** (2026-11-01). It replaces the "Waiting for you" list.
- **Section order and waiting items** (decision changed 2026-11-07). Before: Totals and Cost came first, Running now and Queue came after the list and Health, and a split phase or parent waiting on other phases showed as "stuck N min".
- **A deadlock listed as a system action** (decision changed 2026-11-11). Before: each item whose current run's latest claim decision was a deadlock was a `claim_deadlock` system action (`factory status <id>`, `work_item_id` set), counted once in the Floor when its row was also shown. Now it is not listed.
- **A CI wait and the gap after a run ranked stuck** (decision changed 2026-11-12). Before: `blocked_on: ci` and an item with no run in the seconds between one run finishing and the next being queued fell through to `stuck`.
