  - **Run transcripts in the app (new decision, 2026-11-07, issue #303; current).** A run's stored transcript opens from the item page. **Lookup:** by the worker's storage key, `transcripts/<item>/<run>.json`, never `runs.transcript_url`, which holds the external link a person gives for an interactive session (those stay out of scope). The run must belong to the item (`listRuns(item)`); no store method, schema or migration changed. **Storage:** `SharedStorage` gains `getRange(key, start, end)` → `{ bytes, size }` (only that range is read), implemented by `fs`. `UiDeps.storage` (optional; the ui command, `src/cli/handlers/ui/`, passes the configured storage plugin) is the UI's only storage dependency. **API** (`src/ui/transcript.ts`, routed from `src/ui/api.ts`): `GET`/`HEAD /api/v1/items/<id>/runs/<run>/transcript?offset=&filter=&tail=&part=`. One request reads at most 64 KiB (`PAGE_BYTES`) and returns at most 64 KiB: a forward page leaves a line cut by the range for the next page (`next`) and skips a single line over 64 KiB with a marker; `tail=1` reads only the file's final 64 KiB and returns its last 20 steps (`earlier` says more exist). Each stream-json line (Claude Code's or the OpenAI-compatible runner's events) gives its steps (`text`, `tool_use`, `tool_result`, `result`, `system`, `error`); a line that is not a JSON event is a `plain` step, so a non-stream-json transcript shows as plain lines. `filter=edits|commands|reads` keeps only tool calls of that kind and is applied on the server, page by page. **Egress:** every step and every other text of the response (outcome code, detail, summary, worker id) passes the `EgressScanner` on the new channel `ui` before it leaves; a finding withholds the whole step (`[withheld: <rule>]`, its tool name dropped), never a cut-off part, and Errors are fixed texts (404 unknown run or part, another item's run, no transcript; 400 bad `offset` or `filter`; 500 without the storage message). `/api/v1/items/:id` adds `transcripts`, run id → its stored parts (only runs with a transcript; from one `list` of the item's prefix); the run rows keep their fields, and the app's worker column is the last attempt's `worker_id`. **App:** the Runs table (columns: the timeline decision at the top) has an Open link when a transcript is stored; the view `/app/items/<id>/runs/<run>` (`web/src/views/transcript.tsx`, routed in `App.tsx`) shows the outcome first, then the steps: assistant text collapses past five lines, tool results start collapsed, errors are highlighted, a failed run offers "Jump to the last 20 steps", the step-type filter holds across "Load more" pages, and text wraps so a 375 px screen does not scroll sideways. A queued or running run's page is live (the live transcript decision at the top).
