## History

- **`/classic` kept its improve section and Run now beside the Rules page** (until 2026-11-16, the Rules-page-only decision at the top). Before: `/classic` still answered 200 with the improve report (`improveSection`) and the Health panel's Run now button (its own script, allowed by hash), so the draft and filing lines were built in both `src/ui/health.ts` and `src/ui/rules-api.ts`.
- **The improve report and Run now only on the classic status page** (decision changed 2026-11-16, the Rules page decision at the top). Before: the latest report and the Run now button were rendered only by `/classic` (`improveSection` and the Health panel's Run now in `src/ui/health.ts`); the dashboard app showed neither.
- **Every recurring group was filed or sent to a person** (decision changed 2026-11-15, the host sleep decision at the top). Before: a group of two or more failed runs was filed as a fix item in the project's repo (or, when its draft needed a person, alerted as `needs_person`), with no check of whether the cause was in that repo, so an `agent_stalled` group caused by the host sleeping got a fix item whose spec guessed its paths and waited at the spec gate.
- **Promoted rules only grew** (decision changed 2026-11-14, the retire decision at the top). Before: nothing scored the promoted rules, and retiring one took `tacit verdict <C-id> retire` in a terminal plus a hand edit of the rules file; the Rules page sent promote, reject and hold only.
- **Learned rules and verdicts through the real CLIs** (decision changed 2026-11-12). Before: `LearnedRules` read `TacitLedger.list("promoted")` (`tacit list --agent software-factory --state promoted --json`), a rule's text was the owner's wording stored with its promote verdict, else the entry's `rule_draft`, and a rule whose `scope` tags did not include `software` (`RUN_DOMAIN`) was left out; a verdict sent `{ id, verdict, reason, by, text? }` as JSON on stdin to `evolve verdict --agent software-factory`, and the ledger kept its draft beside the owner's wording. The real CLIs have neither form, so no rule was read and every verdict failed.
- **Learned rules and pushback signals** (decision changed 2026-11-12, issue #571). Before: a rule promoted with the terminal `/evolve` was written only to the owner's own agent instruction files, so no run's prompt saw it, and promoting rules from the factory was "still later"; the improve run grouped failed runs only, so the owner's pushbacks carried no weight in a report.
- **Scorer grades and the 24-hour failure count** (decision changed 2026-11-11, issue #514). Before: no run was graded, so the factory had no quality signal on its own output; the trigger counted unreviewed failures per run kind, with no 24-hour window. Before #508 the improve run started only on its daily schedule (and by `factory improve`), so a burst of failures waited up to a day for a report.
- **Per-project improve reports and the learner** (decision changed 2026-11-11, issue #497). Before: an improve run's report grouped the failed runs of every project in its window, and no step acted on a group, so a project that kept failing with `diff_too_large` kept the same `max_diff_lines`.
- **Hold for a person and fix outcome** (decision changed 2026-11-11, issue #511). Before: the items of a filed pattern were held only by the alarm step's re-raise, after `alarm_repeat_count` new failures, as `blocked_on: upstream`; no outcome was recorded, and `controller_filed_patterns` had no outcome columns.
- **Rules, learnings and skills in every prompt** (decision changed 2026-11-11, issue #490). Before (2026-11-07): "Additive learnings: planned to be automatic, **not built yet**: no code or doc writes learnings today." No rules or learnings reached a prompt; the doc index indexed every markdown file under `docs/` and `skills/` (a `learnings.md` included) and named a skill by its first `#` heading.
- **A fix spec runs without a person** (decision changed 2026-11-10, issue #504). Before (2026-11-09): every group was filed and triaged, and its spec waited at the spec gate like any item's (`/approve`, or auto mode below tier 4 with no gate path); a draft had no `needs_person`, and a draft that touched the gate list was filed too, with a note that it needs a human merge.
- **An improve run when failures pile up, and Run now** (new decision, 2026-11-10, issue #508). Before: the improve run was queued only once a day by the controller (keyed by UTC day) and by `factory improve`; nothing counted failures, so a burst waited up to a day for a report, and the Health panel had no way to start a run.
- **Filed items are triaged by the factory** (decision changed 2026-11-09). Before (2026-11-08, #308): a person started them. Filed items carried no intake label and got no triage run, so filing the factory's own fixes never went ahead without a human; the body said "Filed for a person to start".
- **File each recurring failure pattern** (new decision, 2026-11-08, issue #308). Before (phases 1 and 2): nothing was filed or posted; `controller_filed_patterns` stayed empty, filing and posting to a source were listed under Not yet, and the status page did not show the report.
- **Draft cause and fix per failure group** (new decision, 2026-11-07, issue #307). Before (phase 1, #306): the improve run called no model; its report grouped failed runs but named no cause or fix, and "reading or summarising failures with a model" was listed under Not yet.
- **Daily improve run** (new decision, 2026-11-07, issue #306). Before: no run looked back at failed runs; they could be read by time window (the status page), but nothing grouped them or stored a report.
- **Doc index in the prompt** (new decision, 2026-11-01). Before this, no agent received any capability list (`list-all` existed but nothing built it).
- **Checked-in `CapabilitySearch` default** (changed 2026-11-07). Before: the default stayed `list-all`, which finds nothing, so no prompt got a doc index. Now: `bm25`.
- **Additive learnings** (corrected 2026-11-07). Before: "additive learnings: automatic", though nothing wrote them. Now: marked planned, not built yet.
- **MySQL text removed from the current decisions** (decision changed 2026-11-11, issue #567). Before: the outcome migration was "(SQLite and MySQL; no numbered step: the numbered list is frozen)"; the record needed no schema step "as it is, in SQLite and MySQL"; and the tables were "SQLite migration 31, MySQL step 0031".
