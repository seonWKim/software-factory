## History

- **The implementer runs the type check and its related tests** (decision changed 2026-11-18). Before: `prompts/implement.md` read "Run the project's checks before finishing, in this order: {{check_commands}}.", so the implementer ran the full check list and the worker ran it again before every push.

- **Sync before push, both steps failing** (decision changed 2026-11-18). Before: both conflict steps failing always failed the run with `merge_conflict`, failing checks included, and the resolve-step retry's prompt named only the first step's failure in one sentence.
- **Test database** (decision changed 2026-11-13, issue #579). Before, the bullet read: "**Test database (new interface `TestDatabase`, docs/plugins.md).** `none` is the only plugin: it sets nothing, so the MySQL tests skip themselves and the PR body says so." The worker made one lease per run, put its env in each check command's environment, redacted its values from check output and added its skip line to the PR body.
- **UI check at merge, not in the sandbox** (decision changed 2026-11-12). Before: the UI check (`npm run check:responsive` on this repo) ran only in the PR CI `responsive` job and by hand; the merge-check run ran the install command and the checks only, and an implementer that could not start Chrome in the sandbox reported the check as missing, which marked the item incomplete and stalled it in auto mode.
- **Test database: `mysql-local` removed** (decision changed 2026-11-12, issue #599, PR #655). Before, the "Test database" bullet read: "**Test database (new interface `TestDatabase`, docs/plugins.md).** One database per run, made the first time a check runs and dropped in a `finally` at the end of the run, also when a check failed. `mysql-local` creates `sf_test_<run id>` on a local test-only MySQL server (admin URL `TEST_MYSQL_URL` in the secret file, SET_UP.md) and sets `SF_TEST_MYSQL_URL` in each check command's environment; it refuses any name not starting with `sf_test_`. `none` (the default) sets nothing, so the MySQL tests skip themselves and the PR body says so. The URL is in no agent run's environment, prompt, outcome, comment or log: check output is redacted (the URL and its password) before it is kept. Security: a check runs code the agent wrote with the URL in its environment, so that code can read the test user's password during the checks; the test user may only create, use and drop `sf_test_*` databases on a server with no factory data. That is why this change is tier 4." And the "Not in this decision" bullet read: "**Not in this decision:** the post-PR CI gate (§5) and `.github/workflows/test.yml` are unchanged; the update run still runs no install; no hosted MySQL; `sf_test_*` databases a crashed run leaves behind are not swept (needs a decision). The checked-in config selects `test_database: none` until `TEST_MYSQL_URL` is added to `.env.example` (outside this change's allowed paths) and the local test user exists; then it switches to `mysql-local`."
- **Pack checks in the implement run** (decision changed 2026-11-11, issue #494). Before: the engine ran checks only at `before_run` and `before_merge`, both for the owner's `*.hook.ts`; the gate hooks' PreToolUse and Stop enforced only the worker's own rules (allowed_paths, commits, size, the check list), and no check from a pack ran during an implement run.
- **Gate hooks during the agent step** (decision changed 2026-11-07, issue #302). Before: every implement gate ran only after the agent had stopped. The worker failed a run with `no_commits`, `scope_violation` or `diff_too_large` in its final steps, and those go to a human rather than a retry; the mid-run diff check, which stops the agent over budget, was the only check during the run, so the agent was never told of a gate failure while it could still fix it.
- **Base rerun** (decision changed 2026-11-07). Before: every second failure of a pre-push check was `checks_failed`, a task failure, with no look at whether the failing tests also fail on the base branch, so a test that times out under load cost the item attempts and an owner `/retry`.
- **Diff budget during the agent step** (decision changed 2026-11-07, issue #217). Before: "Nothing is pushed and no handoff is written" for every `diff_too_large`; the size gate ran only in the pre-push step, after the whole agent step, the base merge and the checks, so an over-budget run spent its full agent run first, and the implementer was never told its limits. Its commits went with the run folder.

- **Sync before push** (decision changed 2026-11-01). Before: an implement run pushed its branch as it was built on the base resolved when the run started, so a base that moved during the run could open a PR that already conflicted, as #66 and #70 did; and the scope gate's `<base-sha>` was resolved before the implementer started.
- **A failed conflict step is retried once as a resolve step** (decision changed 2026-11-02). Before: the agent got one try, and a miss failed the run, whose retry rebuilt the implementation from scratch. The issue asked for the retry "as a resolve on the pushed work"; at that point nothing is pushed and a failed run pushes nothing, so the retry stays inside the run rather than pushing unmerged work first.
- **Scope gate and conflicting files** (decision changed 2026-11-02). Before: a conflicting file outside `allowed_paths` failed with `scope_violation` like any other, so a base change to a shared file stopped the run although that side of the conflict was not the item's doing.
- **Gate commands and the resolve run's gates** (new decision, 2026-11-01). Before: the only command gate was `repo.test_command` in the update run, and no gate ran the repo's install.
- **Pre-push gates** (decision changed 2026-11-01): the pre-push step now holds three checks, not only the scope gate, and the floor check now also looks at the files a branch really changes, not only at the `allowed_paths` triage listed.
- **Resolve run scope gate** (decision changed 2026-11-01 after review): the gate now measures the tree that is pushed. Before: two working-tree snapshots, with the agent's own commit pushed after them.
- **Pre-push checks** (decision changed 2026-11-03, issue #158). Before: the implement run pushed and opened its PR right after the pre-push gates, with no check command at all; `repo.test_command` ran only in the merge-conflict step and the update run, neither had a MySQL server, and the typecheck ran in no factory step, so CI found failures only after the PR existed and each cost a new implement loop or a manual fix, as #145, #151 and #154 did.
- **MySQL text removed from the current decisions** (decision changed 2026-11-11, issue #567). Before: the enterprise bullet read "Enterprise (shared store, mysql)"; the Stop hook ran checks "without the test database, so MySQL runs only in the worker's gate"; the no-database decision said "`<state_dir>/test-mysql.url` stays in `deny_paths`, because the file can still hold a MySQL login on the owner's machine. Why: the MySQL store is being removed (#567), so no check needs a MySQL database."; and "Not in this decision" ended "no hosted MySQL".
- **Merge check reruns failing test files once** (decision changed 2026-11-17). Before: the merge check ran the check list once; one flaky failure was a red result, so the merge queue removed the entry and counted a loop, sending a fine change back to an implement run (or blocking it at `max_loops`).
