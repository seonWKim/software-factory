## History

- **Pack loaders' shared-store option removed** (decision changed 2026-11-16, phase 2 of local-task-tk_481fa28b). The decision that changed: the shared-store pause above. Before, it read "the pack loaders get `sharedStore: false` until phase 2 of #659 removes that option": `packPluginFiles`, `packChecks`, `loadPackTools` and `withPackTools` took a `sharedStore` flag, every call site passed `false`, and on `true` a project pack's plugin, tool or check failed startup with a message naming a shared store (mysql).
- **Migration renumbering removed** (decision changed 2026-11-13, #659 phase 2). The decision that changed: Migration renumbering, in code. Before, this sentence stood:
  - > **Migration renumbering, in code.** Until #576 phase 3 removed `migrations/mysql/`, after a base merge is committed (implement sync, update run), when a MySQL step file the branch adds (`migrations/mysql/NNNN-<name>.sql|ts`) had a number the base already had, every step the branch added moved, in number order, to the next numbers after the base's highest (`git mv`), literal references to the old name (`0025-name`) in the files the branch changed followed, and the worker committed that, before the scope gate and the checks. With the folder removed, no branch adds such a step, so this renumbering moves nothing. A SQLite schema collision was and is a real conflict: SQLite numbers its migrations in `schema.ts`, and the gates report it.
- **MySQL store refused by its own check, MySQL dialect kept** (decision changed 2026-11-13, issue #663). Before: a config with `store.type` `"mysql"` failed at startup in `checkConfigKeys` with one problem line that named `"store": { "type": "sqlite" }`; the SQL dialect type still allowed `"mysql"` and the snapshot, bus DDL, migration runner, table copy, retention, outbound intents and store catalog branched on it; `src/compose.ts` kept a MySQL `StoreConfig` variant, a reviewed-keys merge for an external config on a MySQL store, and a shared-store flag set from `store.type === "mysql"`.
- **Coordination thresholds and weights are settable live** (decision changed 2026-11-12). Before: `max_coordination_cost`, `hotspot_weight` and `mechanical_weight` were read only from `factory.config.json` at startup, so a change needed a PR and a restart; only `hold_policy` was settable.
- **Store backend D3** (decision changed 2026-11-11, issue #590). Before: **MySQL** by default (D3 changed 2026-10-31), because several workers and machines were planned; SQLite stayed for tests and single-machine use, and `store.type` picked one. Setup created the MySQL database and user with a generated `MYSQL_PASSWORD`, `MYSQL_*` settings in the secret file overrode the store block, `npm run migrate` ran the MySQL schema steps, and CI ran a `test-mysql` job. MySQL claimed runs in READ COMMITTED transactions, every claim first locking the `worker_claim_locks` row.
- **Migration lock per database** (decision changed 2026-11-10). Before: `npm run migrate` took one server-wide `GET_LOCK('software_factory_migrate')`, so migrations of unrelated databases on one MySQL server waited for each other; CI's MySQL tests, which migrate a fresh database per test, queued on it and timed out at 20 s once the RFC 0015 timestamped migrations doubled each migration's time. A migrate from before the change and one after it no longer exclude each other on the same database; run one version's migrate at a time while upgrading.
- **Default hotspots** (decision changed 2026-11-09). Before: `DEFAULT_HOTSPOTS` named `src/core/controller.ts` and `src/core/worker.ts`; after RFC 0015 M5 and M6 removed both files, neither matched any path, so changes to the controller units or the worker were never weighed as hotspots.
- **One GitHub sync per project** (decision changed 2026-11-08). Before: every replica polled GitHub, budget per process: the controller ran the GitHub inbox poll and outbox delivery on every replica each time the poll interval was due, only the stream listener took a store lease (`inbound_listener_leases`, keyed by source type only), and the rate-limit budget lived in each GitHub client's memory, so its guard protected one process only.
- **Hold policy** (decision changed 2026-11-07, issue #314). Before: a run held by coordination cost stayed queued until a human posted `/approve` or the holder merged, with no setting to let it run after a wait or at once; the stored decision had no start time (its `at` moved whenever the holder changed); and the coordination settings could be set only in `factory.config.json`, none of them at runtime.
- **A held run names the holder that decides** (decision changed 2026-11-07). Before: holds were sorted by cost alone (running and PR holders first only at equal cost), so a run held by an open PR and also sharing more files with a queued run was stored as `held` by the queued run, which read as a deadlock the deadlock rule failed to break; and a decision naming an item that had since merged or closed stayed until the next claim reached that run, so a poll right after a merge could still post or show "waiting for #N to merge".
- **Split parents count as merged; `/retry` re-checks a closed dependency** (decision changed 2026-11-07, issue #246). Before: a factory item counted as merged only when closed `completed` with a merge sha, so a split parent closed as completed after all its phases merged (#213) blocked its dependents with `dependency_closed`, and no command applied to that block, so the item stayed stuck until edited by hand.
- **Dependency edges re-read only when the issue changed** (decision changed 2026-11-07, issue #254). Before: the read times were in the controller's memory (`EDGES_REFRESH_MS`, `DEPENDENCY_STATE_REFRESH_MS`): links were re-read on every delivery of an open item without a PR, and again by the coordination step once this process's last read was 30 minutes old, so a restart or another replica read every item's links again after 30 minutes; the 30-minute refresh and the outside-state reads ran under `lowBudget()` too.
- **Dependency reads only when the source changed** (decision changed 2026-11-07, issue #254). Before: edges re-read from the forge on every poll: each poll, for each item with a queued implement run or a dependency hold (up to 50 each), the controller read the issue body, its `sub_issues` and its `blocked_by` (three GETs), plus one GET per dependency outside the factory, so about 40 calls a poll with ten such items; on 2026-11-07 this used up the GitHub App's hourly limit, which also kept `/approve` and `/retry` comments from being read. A failed read failed the whole item's coordination pass, so stored edges did not apply during an outage.
- **Mechanical paths** (decision changed 2026-11-07, issue #297). Before: every shared path weighed at least 1.0, and `docs/design.md` was a hotspot at 3.0, so two items that each added an index line and a migration step reached the 2.5 threshold and ran one after the other; every base-merge conflict went to an agent step or a resolve run, even when both sides only added lines, and was recorded as a learned weight; a MySQL step number both branches took was left for the tests to fail on.
- **Parallel workers: CPU share for tests** (decision changed 2026-11-07). Before: no test-worker limit reached a run, so each run's `npm test` (agent or check list) started a vitest pool sized to every CPU; with `workers: 10` on a 10-CPU Mac about ten pools of about ten workers ran at once (load average 38 / 71 over 15 minutes, measured 2026-11-07), MySQL tests hit the 20 s timeout (18 of 19 failures in one full run, gone when rerun serially) and runs failed `agent_stalled`. The resolve run's gate commands also did not get `SF_WORKER_INDEX`.
- **Worker slots reported per process** (decision changed 2026-11-07, issue #209). Before: the pool re-read `workers` each tick and logged "worker slot stopping: workers lowered" once per slot that stopped, never the count itself; the only count in the logs was the supervisor's `child started` line (`workers: <block size>`, the config, not the live value); the store kept no per-process record, so an idle process appeared nowhere and no host could see another host's slots.
- **Parallel workers** (new decision, 2026-11-01). Before: one worker loop per process, so approved items were built one at a time.
- **One branch writer per item** (decision changed 2026-11-01). Before: the overlap rule skipped an implement-type run while any item with overlapping `allowed_paths` had one running, later with shared docs exempted; nearly every spec lists a whole folder, so one implement run ran at a time whatever `workers` said.
- **Claim order** (decision changed 2026-11-01). Before: FIFO, the oldest queued run first whatever its kind, so a short triage or review run that a person waits on could sit behind older implement runs for about 45 minutes while every worker was busy.
- **MySQL schema steps** (decision changed 2026-11-01, issue #97). Before: the MySQL schema was a positional array of statement groups in `src/impl/store/mysql/schema.ts`, applied silently by `store.migrate()` on every store open, so nobody could see or check pending changes, a data change could not run on its own, and parallel PRs collided on the same array position.
- **Host sleep record** (decision changed 2026-11-07, issue #218). Before: a worker noticed a late wake only inside a run's heartbeat and only logged it (gap over 2 × `heartbeat_ms`); the idle wait and the pause watch were not checked and nothing reached the store, so an outage that was really a laptop sleep looked the same as a long run.
- **Host sleep** (fencing rule changed 2026-11-01). Before, `lease_expires_at` was also a hard deadline for every write.
