## History

- **Thread readability, moved out of the topic file to keep it under its size cap** (2026-11-23, no decision changed). Kept as it was:
  - **Thread readability (decision changed 2026-11-09; current).** The decision that changed: the markdown renderer folds `<details>` and styles the spec's key sections; design only, no API change. **Markdown:** a small built-in renderer (`web/src/components/ui/markdown.tsx`, no dependency): headings, paragraphs, bullet and numbered lists, fenced code, inline code, bold, `[text](url)` links, and a `<details><summary>…</summary>` … `</details>` fold when each tag sits on a line of its own (the spec comment's form). It builds React elements, never HTML strings, so any other raw HTML shows as text; a link is drawn only for an http(s) URL, any other (`javascript:`, `data:`, relative) shows its text, plain. A section headed "In short" is a tinted summary block and one headed "Decisions for you" an amber attention block, each from its heading to the next heading of its level or higher. A paragraph "AS-IS: … TO-BE: …" shows as two lines with bold labels. **Thread:** each entry has a header bar (author, channel, kind as a badge, time on the right) apart from its body; the body is at most 75ch wide with relaxed line height.
- **Item thread on the item page, moved out of the topic file to keep it under its size cap** (2026-11-22, no decision changed). Kept as it was:
  - **Item thread on the item page (new decision, 2026-11-08, issue #286; current).** **Item API:** `/api/v1/items/:id` adds `thread`, the item's thread entries read with the store's existing `listItemMessages` (`src/ui/thread.ts`), oldest first, each `{ seq, at, kind, author, channel, anchor, body }`: `body` through the Withholder; `kind` from the marker (the word after `<!-- factory:` for the factory's own entries, `comment` for a GitHub comment `github:<id>`, else `message`); `author` is `factory` for an entry whose marker starts with `<!-- factory:` and `unknown` for every other, because a thread entry stores no author; `channel` is the item's source type; `anchor` is `msg-<seq>`. The marker itself is never returned. No store method, schema or migration changed: storing an author or channel per entry was weighed and left out (the owner's choice, option A), so existing entries need no backfill. **Item page:** a Thread section (`web/src/views/thread.tsx`) under the command buttons lists every entry sorted by time (seq breaks a tie), each with its author, `on <channel>`, kind and age, the body as markdown, and the anchor as the element's id; opening the page with that hash scrolls to it. A command sent from the command box re-reads the item after its 202, so the controller's reply shows in the thread once it is written (and with the 3 s poll); no live update beyond that. **Routing:** a hash on an `/app/` path (`#msg-3`) does not change the page. **Merge:** a local item merges with `factory merge` or the item page's Merge button (above, issue #438).
