## History

- **The Calendar read's `calendar` list was the sync rows** (until 2026-11-19, the Calendar read decision at the top). Before: `GET /api/v1/calendar/events` answered `calendar` from every `calendar_sync_state` row and placed every stored event, whatever the live `calendar` setting said; the page showed "No calendar is connected." whenever that list was empty. A connected source had no row until its first sync, and a disconnected one kept its rows and events.
- **Tasks used Sections and Calendar a bare heading** (until 2026-11-19, the Cards decision at the top). Before: Needs you and the open tasks were `Section`s with no surface, row states were `StatusBadge`, and the calendar's period was an h2 in the controls column above an unframed week or month.
- **Quick add on a project tab sent no project** (decision changed 2026-11-18, the quick-add decision at the top). Before: the page posted `{ id, words }` whatever the tab, so the task was stored with no project unless the words had `+slug`, and the tab's list did not show it.
- **The "+" was a bordered button beside the project tabs** (decision changed 2026-11-15, the Project tabs line above). Before: `Button` (secondary, `size-8`) in a flex row next to `Tabs`, outside the tab row's box. The dialog, the create API and the `project` parameter did not change.
- **The Tasks page had a view control, Today, Upcoming and All** (until 2026-11-15, the one list decision at the top). A `SegmentedControl` (`tasks.viewLabel`) picked one of three views, Today on load; each view had its own empty state (`tasks.emptyToday`, `tasks.emptyUpcoming`, `tasks.emptyAll`) and the timeline showed on Today only. The three views are one list now.
- **The Calendar page had Day and Upcoming** (until 2026-11-15, the Calendar page decision under the Tasks page decision at the top; decision changed: "a Day / Upcoming control over today through 7 days ahead from `GET /api/v1/tasks`"). Before: a `SegmentedControl` Day / Upcoming, then the events of today (Day) or of each of today through 7 days ahead (Upcoming) from `GET /api/v1/tasks` with no project filter, with no new route; with a calendar and no events the empty state said "No events today." or "No events from today through the next 7 days." with no link. No other period could be shown, because that read places only today and the next 7 days.
- **All ended with a Show done switch** (until 2026-11-15, the Tasks page view control decision at the top; design 02-tasks, the done tasks stay decision). Before: All's groups were followed by a `label` holding the shared `Switch` and Show done (`tasks.showDone`), off on load; on, the done list (Show older, Reopen, `tasks.emptyDone`) showed under it with an unfiltered read.
- **The project switcher was a select beside the view tabs** (decision changed 2026-11-14, the Tasks page decision at the top). Before: a native `Select` labelled Project (`ProjectSwitcher`, `w-48`) sat after the Task view control on one wrapping row; it opened the browser's menu, which matches nothing in the design system. The filter, the `project` parameter and the unfiltered Done read did not change. The view control stays a `SegmentedControl`.
- **The Task view control had five options and the timeline was on Inbox too** (until 2026-11-14, the three views decision at the top). Before: Inbox, Today, Upcoming, List and Done; the switcher filtered Inbox, Today, Upcoming and List; Inbox and Today ended with the collapsed timeline; Inbox and List had their own empty states (`tasks.emptyInbox`, `tasks.emptyList`).
- **The List tab** (until 2026-11-14, the three views decision at the top). The fourth tab, List (`tasks.list`, formerly Project), grouped every open task by `#list`; All does that now, with undated tasks included as before.
- **The Tasks page stacked Factory work, Quick add, then the tabs; events in Today and Upcoming** (decision changed 2026-11-14, the Tasks page decision at the top). Before: Factory work (one table per group, each repeating Item, State, Why, Since, Actions, the state shown up to three times), Quick add, then the view tabs and Project switcher, with no spacing between them; calendar events and the stale-sync notice were rows in Today and Upcoming; Today's timeline always showed 00:00 to 23:00 with event blocks; an empty tab had an "Add one above (press q)" button and a bare count.
- **Factory work lists every project's items** (decision changed 2026-11-14, the Factory work decision at the top). Before: "Tasks have no project field and show in every project scope; the Factory work section is to follow the project scope of the project switcher once it merges (it is not in the repository yet, so the section lists every project's items for now)." The section read `GET /api/v1/items` with no filter whatever the switcher showed.
- **The Tasks page's Project tab, and no task projects on the dashboard** (decision changed 2026-11-14, the switcher and List tab decision above). Before: the fourth tab of the Task view control was named Project (`tasks.project`) and grouped the open tasks by `#list`; the dashboard had no route or control to create a task project, set a task's projects or filter by one (only `factory project …`, `+slug` in quick add and edit, and chat).
- **Repeated tab heading, always-shown Build line, two cells under a card's title, raw hold_policy JSON** (decision changed 2026-11-13). Before: the Tasks section's heading repeated the selected tab's name, the view switcher had its own bottom margin (a 48 px gap), empty tabs were a plain box with no next step, the Build line showed with no Build button, the quick-add placeholder was "Add a task, e.g. pay rent friday p1 #home" and the overdue and event labels were Badge; a Table card put its first two cells under the title (the second unlabelled) and listed the rest from the fourth column; Settings' models grid was `grid-cols-[auto_7rem]`, File value showed raw milliseconds, defaults were written "not set (default 3)" and "not set; default:", hold_policy was a free JSON box, the message_style example showed twice, the per-project line read "for <project>: the global value" and the Commands paragraph explained acting as another user.
- **The Tasks page lists only plain tasks** (replaced 2026-11-13 by Factory work on the Tasks page, "One view for tasks and factory work"). Before: a built task's row showed only its work item ID as a link, and the work that needs the owner appeared only on Needs you.
- **Tasks entries marked "coming"** (2026-11-11, replaced 2026-11-12 by the Tasks page, issue #607). Before: the sidebar's Tasks group held Inbox, Today, Upcoming and Projects as disabled entries marked "coming", never links.

- **The Needs you section left out linked items and showed alarms below it** (decision changed 2026-11-16, design 09-status-page). Before: an item shown on an open task's row was not a section row, stuck items were, and the system actions and the "Open alarms: N." line were `FloorNotes` lines after the section, outside its count.

- **The Needs you page** (replaced 2026-11-15 by the Tasks page and landing decision at the top; decision of 2026-11-13, wi_fc2c). Before: Needs you (`/app/`, key `needs`, Factory group) was a page of its own with a `PageHeader` and count, a factory indicator (a dot and one word, the revision in a Tooltip), a `Notice` when the factory was paused, stopped or failing, and one `Table` per group (Merge, Approve, Answer or fix) with the columns Item, State, Why (`WhyText`), Since, Issue (when a row had one) and Actions, then the system-action lines and the claim pauses. Its sidebar entry was the only one in the Factory group. Now: the compact list of the Needs you section on Tasks, no factory indicator, no Why links or Since column.

- **The Needs you page layout** (decision changed 2026-11-13, wi_fc2c). Before: Needs you was one section titled "Needs you" (repeating the page title) under the full-width factory banner, with one table whose Why cell carried the reason as accent-coloured text, the row's command buttons (lowercase `approve` and `retry`, a "⋯" menu) and the Merge button after it, so the buttons moved with the text length; the State cell had a "Checking…" line while the merge check ran, Issue and PR were always columns, and the Why text showed item IDs and slash commands raw. `FactoryBanner` stays on the Runners page; `ItemsTable` serves Work items only; `NeedCommands` and its menu are replaced by `NeedActions`.

- **Needs-you Why column** (decision changed 2026-11-07). Before: the Why column showed the item's badges, which repeated the State (for example "needs approval"), or the raw blocked reason; the reason was built only in the classic page.
- **The Tasks row ID was the only link** (decision changed 2026-11-19, the Tasks row line at the top). Before: the accent mono work item ID linked to the item and the title was plain text.
