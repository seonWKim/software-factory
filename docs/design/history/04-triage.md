## History

- **Companion entries were `{ when, also }` only** (decision changed 2026-11-22, wi_3f9ab60a). Before: an entry had exactly `when` and `also`, so a spec showed which paths a rule added but not why; every entry fired on `when` alone; the built-in table-docs rule fired only for a `.ts` file under `src/<owner>/migrations/`, not the folder; and the checked-in config had no rule for a controller table's `src/controller/table-docs.ts`, the SQL store's folder or a new run kind's `worker_kinds` files, so implement runs stopped with `agent_needs_human` for them.
- **Decision options were plain strings** (decision changed 2026-11-21, wi_80ba9d05). Before: a decision option was a plain string with no record of the paths it needs or the done-when lines it changes, the spec comment showed no option, and the triage prompt had a rule for owner answers from earlier approvals but none for an instruction in `/revise` feedback, so a revised spec could offer the opposite of that instruction as a default.
- **A stated dependency was any decision** (decision changed 2026-11-20). Before: triage turned a request's "run after wi_X merges" into a decision of its own wording, usually free text ("Start now, or wait for wi_288c? default: wait"); approving it, the default included, set no dependency hold, so the implement run started at once and stopped for a human.
- **Prompt rules** (decision changed 2026-11-07, issue #335). Before: `prompts/triage.md` named this repo's principles from AGENTS.md, the MySQL migration paths (`migrations/mysql/`, `src/impl/store/mysql/migrations.ts`) for a store schema change, the topic files `docs/design/<topic>.md` and `docs/plugins/<interface>.md`, and `src/core/` in its example; the implement and review prompts named `npm test` and the `npx` rule.
- **Triage text check** (decision changed 2026-11-08, issue #454). Before: `parseTriage` checked only that each text field was a string or a list of strings, so tool-call markup passed into the spec, and a bad value got a bare error (`decisions`, `missing text field`) that did not say what was wrong.
- **Markup refusal retry** (decision changed 2026-11-10, issue #488). Before: a triage answer refused for tool-call markup was retried like any other invalid output: the controller ran a fresh triage with the same prompt and no note of the error, and the triage prompt said nothing about tags in field values.
- **Triage decisions** (decision changed 2026-11-10, issue #526). Before: each decision was `{ text, default, owner_only }`, one line with no reason and no options; the spec comment listed them as bullets, so an answer could not name its decision.
- **MySQL text removed from the current decisions** (decision changed 2026-11-11, issue #567). Before: a missed companion was "the MySQL migration step for a schema change"; the checked-in config declared "both store schemas (`also`: `migrations/mysql/` and `src/impl/store/mysql/migrations.ts`)" and the store interface pair listed "both schema files, `tests/store-contract.test.ts`, `migrations/mysql/` and `src/impl/store/mysql/migrations.ts`"; the project-neutral prompts named no path of this repo "(the doc indexes, `src/core/`, the MySQL migration paths)", and this repo's own rules were "never `npx`, the MySQL migration paths, solo and enterprise in the desired output".
- **`.claude/` paths in a spec** (decision changed 2026-11-15). Before: triage accepted `.claude/` paths in `allowed_paths` and `files_to_change` like any safe relative path, and the implement run's write there was refused by the sandbox, so the item waited on a person.
- **Generated files, ratchet lists and asserting tests** (decision changed 2026-11-16). Before: the checked-in `path_companions` covered only the doc indexes, the store interface, the config keys and the design topic files, so a migration or setting change did not allow `schema/sqlite.sql` or `docs/settings.md`; `isCovered` covered only `allowed_paths`, so lowering a count in a ratchet list under `tests/architecture/known-violations/` needed the file in `allowed_paths`; and the triage prompt did not ask for the tests that assert changed text or behaviour.
- **Built-in companions** (decision changed 2026-11-18). Before: "Doc indexes. Built in, apart from the config: an answer naming `docs/design.md` or `docs/plugins.md` in `files_to_change` or `allowed_paths` gets `docs/design/` or `docs/plugins/` added." These were the only built-in companions; a design topic's History file, a web view's i18n area file and a source file's test came only from `path_companions` entries in the config, and none was declared, so each needed triage to name it.
- **Table-docs companion** (decision changed 2026-11-18, wi_227e8c5b). Before: "Built-in companion rules: a design topic's History file, a web view's i18n area file, a source file's test"; `applyCompanions` applied three rules, so a migration's owner table-docs file (`src/<owner>/table-docs.ts`) came only from triage naming it, and a spec that added a table without it stopped as `spec_conflict`.
- **i18n companion was the area file only** (decision changed 2026-11-18, issue #694). Before: a web view or component added only `web/src/i18n/en/<area>.ts`, so an item whose area file was new also had to hand-edit the import list and spread line of `web/src/i18n/en.ts`, a path it did not have.
- **i18n barrel with every area** (decision changed 2026-11-20). Before: a web view or component added its area file and the generated catalog barrel `web/src/i18n/en.ts`, since triage cannot tell a new area from an existing one; the triage prompt listed the design index for a new topic file but did not say to leave it out otherwise, so almost every plan claimed `docs/design.md` and `web/src/i18n/en.ts`.
