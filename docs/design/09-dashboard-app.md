# 9. Status page: dashboard app and read API

- **Dashboard app and read API (new decision, 2026-11-02, issue #124; steps 1 and 2 of the dashboard plan).** The status UI moves to a client app. **Stack:** Vite, React, TypeScript, Tailwind, shadcn/ui (components copied into `web/` as plain files, not a dependency), lucide icons and TanStack Query; the system font stack, nothing from a CDN. The app lives in `web/`, `npm run build` builds it into `web/dist/` (git-ignored) after the server (the shell, its dependencies and that build step land in the change after the API and the serving; until then `/app/` answers 503), and `isCodePath` counts `web/` as code so the updater rebuilds on a change there. Once the server-rendered pages are retired (step 6, `src/ui/html.ts` and `src/ui/pages.ts`), the app supersedes them; until step 3 it is served at `/app/` and the old pages stay at `/` and `/items/<id>` unchanged (same HTML, same CSP).
  - **Read-only JSON API** (`src/ui/api.ts`), `GET`/`HEAD` only, the same Host guard, `cache-control: no-store` and security headers as the page, errors as JSON `{ error }` (404 for an unknown path or item id, 400 for an unknown filter value): `/api/v1/overview` (items per stage, human-blocked count, running and queued run counts, runs succeeded and failed and tokens in the last 24 h: the page's numbers), `/api/v1/items` (the page's ranked list with the same filters `state`, `stage`, `tier`, `kind`, `unblocks`, `closed`, `q`, plus the facet counts; the ranking moved to `src/ui/list.ts` so the page and the API share it), `/api/v1/items/:id` (facts, timeline, runs), `/api/v1/runs` (running then queued runs: kind, item id, attempt, owner, last heartbeat, start, lease expiry; never the fencing token), `/api/v1/queue` (queued runs, oldest first), `/api/v1/workers` (each current lease owner once, by ID, with its running count; history is step 5) and `/api/v1/health` (the same `HealthMonitor.report` as `/api/health`, which keeps its response). Every free-text value (titles, blocked reasons, state-change values and reasons, actor and owner ids, run errors) passes through the `Withholder` as plain text or `[withheld: <rule>]`. The API calls only store read methods; no store method, interface, migration or schema changed. Orphaned-run rules (heartbeat older than 2 × `heartbeat_ms`, or lease expired) belong to the floor view (step 3), which applies them to the raw owner, heartbeat and lease expiry returned here.
  - **Serving `/app/`** (`src/ui/app.ts`): files from `web/dist`; any other path gets `index.html` (client routing), except a missing file under `assets/`, which is a 404. A path that decodes to `.`/`..`, a slash, a backslash or a NUL, a dotfile, or a file whose real path is outside `web/dist` is a 404. No built app: 503 "run npm run build", and `/` keeps working. Its own CSP: `default-src 'none'; script-src 'self'; style-src 'self'; connect-src 'self'; form-action 'self'; base-uri 'none'; frame-ancestors 'none'` (no `unsafe-inline`, no hash; so no inline `style=` attributes in the app either). Same Host and method guards (errors as text). The app's fetches go only to `/api/v1/*`; it polls every 3 s while the document is visible, and its light/dark choice stays in the browser.
