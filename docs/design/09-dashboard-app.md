It calls `TacitLedger.verdict` with the reason, the owner's user ID and, for promote, the edited wording (1 to 2000 characters; the ledger keeps its draft, decision 3); a reason is 1 to 1000 characters. It is the page's only write path: nothing goes to the store. Refusals: 400 for a body that is not one, 409 with no ledger, 403 for anyone but the owner, 502 when the CLI fails; each before the CLI runs. **Page:** Rules in the sidebar after Failures (`web/src/views/rules.tsx`), one card per entry at every width (kind, ID, scope, rule draft, evidence). Promote, Hold and Reject each open a dialog that asks for the reason before it sends (the confirm stays disabled while it is blank); Promote's dialog also holds the rule's wording, prefilled with the draft, sent as `text` only when changed. A viewer who is not the owner sees the cards read-only with the reason. With the plugin `none` the page shows an empty state with one action, "How to turn on the ledger", which lists the steps (set `plugins.tacit` to `agents-home`, check `bin/tacit` and `bin/evolve` in the agents home, restart). **Wiring:** `buildUiParts` builds the `plugins.tacit` plugin for the UI process; it only runs the ledger's CLIs. **Why:** the ledger's candidates were reachable only from the terminal, with no page that showed their evidence. **Solo and enterprise** behave the same: one owner judges, and the verdict carries their user ID, never a display name.

- **Run attempts in the item API** (decision changed 2026-11-07, issue #207). Replaces: "`/api/v1/items/:id` (facts, timeline, runs)" with one row per run and no record of its earlier claims, and "no store method, interface, migration or schema changed" (the item route now also reads `listRunAttempts`).
- **`/api/v1/workers`** (field added 2026-11-07, issue #209). Before: it returned only `workers`, the lease owners of running runs, so an idle process did not appear and no slot count was shown.
- **Where `/` goes** (changed 2026-11-07). Before: `/` served the server-rendered page and the app was only at `/app/`, with placeholder pages.
- **The dashboard is read-only** (decision changed 2026-11-07, issue #236). Before: the JSON API answered only `GET`/`HEAD` ("Read-only JSON API"), and the Settings page was read-only, pointing at `factory settings`. Now `POST /api/v1/settings` is the one write route and the Settings page edits and resets settable keys.
- **Store reads behind the API** (changed 2026-11-07, issue #239). Before: the API had only curated views, and tables such as `controller_claim_decisions`, `controller_file_conflicts` and `worker_run_attempts` had no view at all; the store had no generic table read.
- **PR link in the API** (decision changed 2026-11-07, issue #240). Before: `pr_url` was built from the stored project key (`github:host:id`), giving a malformed host; now it is built from the stored label, as the classic page already did.
- **Item list and item fields** (field added 2026-11-07, issue #248). Before: no merge readiness in the API; a ready-to-merge row showed only "Ready to merge".
- **Unreviewed merges in the app** (new decision 2026-11-07, issue #268). Before: the controller recorded an `controller_unreviewed_merges` row and a log line, and only tests read the rows; the app had no route or view for them. Replaces "showing unreviewed merges" under "Not built" in `05-sources.md`.
- **Run transcripts in the app** (new decision 2026-11-07, issue #303). Replaces: the UI had no storage dependency and only read the store; the worker stored transcripts that nothing read back, the item page had no worker column or transcript link, and the Data page listed shared-storage transcripts as out of scope.
- **Workers, Failures and the effective worker count** (decision changed 2026-11-07, issue #312). Before: the Workers page listed lease owners and "Running now" and ignored `processes`, so draining processes and idle slots were invisible; the factory banner showed the status file's `workers` (the file value, which could disagree with an override or the `max_workers` cap); the Floor's failed count was plain text, and no route grouped failed runs by error code.
- **Needs-you Why column** (decision changed 2026-11-08, issue #286). Before: `need` was `{ reason, command }` and the reason linked nowhere; the item page had no thread and the item API returned no thread entries.
- **Needs-you Why column** (decision changed 2026-11-07). Before: the Why column showed the item's badges, which repeated the State (for example "needs approval"), or the raw blocked reason; the reason was built only in the classic page.
- **Item tables: plugins, issue and PR links** (decision changed 2026-11-08, phase 4 of the change-fields split). Before: `main.ts` passed `UiDeps.prUrl(label, n)` and the UI built `https://<label>/pull/<n>` from the stored project label; items, the item page and unreviewed merges returned `pr_number` and `pr_url` (an unreviewed merge's `pr_url` only when `plugins.prs` was `"github"`); the overview returned `plugins: { issues, prs }`, and the app showed the PR column and tree PR chip only when `prs` was `"github"`.
- **A deadlock claim needs a person** (decision changed 2026-11-11). Before: an item whose current run's latest claim decision was a deadlock ranked `needs_human` (badge `deadlock`) before its running state was checked, was listed as a `claim_deadlock` system action, and was counted twice in `needs_you` on the Floor. Now the run goes on, the item ranks `running`, and no system action exists for it.
- **A single theme toggle** (decision changed 2026-11-12). Before: one button switched between light and dark, read the stored value or the system preference once at load and stored `light` or `dark`, so a click pinned the page and a change of the system scheme was ignored. The toggle labels were "Switch to dark theme" and "Switch to light theme".
